## 先读这个范围

用户最新补充覆盖早先“左栏也不变”的要求：**保留右侧会话检查器与三栏结构；左侧场景和中间消息用固定版公开基础组件作最小业务组合。** 不自作主张重新设计其它区域。

本轮由 Codex 按已确定设计实施。ADR-005 的小满自主功能开发不变，也不是本轮的前置依赖。ADR-006 不改双脑工作流、模型设置、权限、任务继续和 QQ 发布语义。

**非必要禁止增加自定义控件。DSH 有类似控件就复用。只有确实没有可用的类似控件，说明充分的具体理由并得到用户对替代方案的确认，才可自行设计。** 将 [DEVELOPMENT_GUIDE_APPEND.md](DEVELOPMENT_GUIDE_APPEND.md) 合并到现有开发指南；不新建运行时检查或审批系统。

## 本轮已批准的设计

- 公开 Input/Button 组合原有场景搜索和选择行为；不是把 QQ 群伪造成磁盘目录，也不是列出一堆内部任务会话。
- 公开正文、折叠、工具文本和状态组件组合 Asuna 消息；只为真实 Asuna 消息增加脑来源／阶段元信息。
- 真实 MONOLOGUE 保持可读，随着实际内容增长。provider 元数据在默认关闭的诊断详情；完整原包只留审计，不替代正文或重复思考。
- 一条实际生成只有一个稳定消息位置；生成、完成、发布确认原位更新。新片段不是新气泡。
- 不新增常驻“双脑状态卡”、消息 toast、第三块 Thinking 区、打字动画、仪表盘或并行新页面。
- 原始 reasoning 若实际返回，保留与其它正文片段的顺序，并用真实来源标签；不冒充 MONOLOGUE，不另开固定 Thinking 区。

完整行为见 [UI_SPEC.md](UI_SPEC.md)，固定版实际出口与限制见 [NATIVE_REUSE_MAP.md](NATIVE_REUSE_MAP.md)。示范代码见 [examples/README.md](examples/README.md)。示范不是新的数据存储或 UI 框架。

## 从这里实施

1. 核对本地安装版本和现有入口；本包的参考固定为 `0.1.5-rc.2 / dsh-v0.1.5-rc.2`，不是 master。保留工作树与运行任务。只读相关 UI 和导出契约，不拉整个仓库，不升级 DSH。
2. 在现有本机端口打开实际 DSH Chat 与当前 Asuna 页，留各一张开发用截图。原生控件是视觉真相；不再让图像模型或 Codex另设计一张参考图。
3. 先恢复真实 `phase.output` 正文，拆开正文与 provider 诊断。然后在现有页面嵌入原生组件／注册视图、接同一份只读显示投影。输入仍送 Asuna 的现有可信入口。
4. 用真实消息验证同一位置增长和完成结算，再处理左栏来源映射、咨询归属和断线显示。按 [IMPLEMENTATION.md](IMPLEMENTATION.md) 处理，禁止复制私有组件或伪造不存在的 `<DSHChat>` 导出。
5. 必须沿用右侧检查器的数据、筛选、选择和详情行为。为挂载移动组件允许最小机械调整，不另写一个检查器。清除本轮已经替代且无调用者的旧渲染分支；不加 `v2` 并行页面，不全库清理。
6. 按 [ACCEPTANCE.md](ACCEPTANCE.md) 在实际页面核对。达到用户可见结果就停止扩展。

“已有类似组件但数据不同”首先是绑定／投影问题，不自动允许自绘控件。固定版存在导出或必要操作缺口时，仅指出该缺口；不得偷导私有路径、修改 node_modules、克隆组件源码或换成自制 fallback。继续不依赖该缺口的部分，不把整个 agent 服务停住。

## 不得再次偏移

- 不调用模型总结日志来制造漂亮的思考过程；不让模型输出 UI schema。
- 不为 UI 合并、清空、fork 或重置两个脑的真实历史，不把真实 private scope 混进另一场景。
- 不将页面断线、渲染错误或流字段未知传播成 agent 失败。
- 不把 DSH 的“停止当前生成”按钮接到 Asuna 的“停止整个服务”端点。
- 不增加新的模型调用、重试、步数门槛、预算检查、内容评分。
- 不用“用了 DSH 颜色／按钮”宣称原生会话列表与聊天已经复用。
- 不以工具输出或正文相似度去重，不用最新选中消息猜测片段归属。
- 不做裸 DSH 模型 A/B；这里比较原生控件的视觉与交互，不比较模型答案。

交付一段短报告：实际入口、复用的原生包／slot、允许的最小 Asuna 适配、移除的旧分支、页面证据、真实剩余缺口。构建通过不等于页面通过；参考代码通过不等于本地集成已完成。
