# ADR-009：人格入住、类人认知与单一记忆真相

状态：**已实施**（P0–P7，2026-10-05 合并到 main）。之后：人物档案（dossier）已退役，对人的理解由 `understand_person` 记（ADR-025）；阶段协议（DECIDE/WRITE）由 ADR-011 的工具取代，下面写到的「提交」现在都是工具调用；QQ 平台代码移到通道包。§ 编号沿用全文的 ARCHITECTURE.md（§7.4 来自 PERSONA_CONTRACT.md，「MEMORY §5.2」来自 MEMORY.md），代码注释引用它们。

## 一句话决定

核心只提供与人格无关的类人能力原语（情感账本、文档层、记忆显著度与遗忘、节律/心跳/夜间沉淀、人格数据 API 与人格作业），所有状态以 Mongo 修订账为唯一真相，文件只承载行为；人格是可替换的插件，用这些原语自己完成入住与成长。

## owner 裁定（不得推翻）

- R-2 删除终端聊天适配器；所有交互走 Web。
- R-3/R-4 不替人格完成她自己的任务（归置表、导入器、校验器、召回题库）；核心只提供能力，架构允许她以后自己接入新数据源。
- R-5 人格是插件：核心代码、核心 prompt、核心工具、示例配置不含人格名、人格正文或人格专属参数；合成人格 `demo` 能跑通全部测试。
- R-6/R-7 不泄露 owner 个人信息；个人数据只存本地（本地配置、Mongo、私有源根），仓库只放占位符与合成夹具；`tools/check_staged_secrets.py --personal` 告警，本 ADR 文件夹必须零命中。不重写 git 历史。
- 开发期：旧数据不转换，不合新设计就删（删前导出到本机）；没有兼容代码（2026-10-04）。

## 六条原则

1. **文件存行为，Mongo 存状态。** prompt、skill、代码是文件，经 `development_publish` 发布；她学到的、感到的、记得的、答应的、决定的，都是 Mongo 中带修订链的记录。md 只作种子输入或导出。原生会话 JSONL 是执行日志，永远不是记忆权威。
2. **人格是插件。** 人格参数是人格数据（人格模型 JSON 的公开默认值 + `policy:<persona>` 的私有覆盖），生效值：政策 > 人格模型 > 核心缺省；核心缺省等于「功能关闭」或「沿用现状」。
3. **判断归角色，记账归程序。** 语义选择由角色做，数值、衰减、幂等、闸门由确定性代码做；不引入替模型打分的评分器。状态以解释过的文字到达模型，模型用类别词写回（owner 2026-10-04）。
4. **隐私分层**（§2）。
5. **个人数据留本地。**
6. **DSH 原生优先，以固定版实际存在的接口为准。** 不用 `dsh-time-context`（浏览器时区会进入群回合）。

## §2 隐私与可见性

- **2.1** 每个回合由程序算 `session_class ∈ {owner_private, public}`：owner 本机场景、规范人物是 owner 的私聊、受信的家里线路（对端、agent 线）是 `owner_private`；其余（群聊，包括 owner 在群里发言；非 owner 私聊）是 `public`。跨场景链接永远不提升会话类。内部回合（心跳、沉淀、自开发）的类由目标场景决定，目标必须是 `owner_private`。
- **2.2** 文档节带 `visibility ∈ {public, owner_private}`；记忆单元多一个 scope `owner-private:<persona>`；未声明可见性的写入一律按 `owner_private` 保存并提示（宁私勿泄）。情感事件全局（一个人格只有一颗心），但原因字段按 `source_scope` 判可读。源快照和作业报告在 `owner-private` scope，只有 operator 视图可读。
- **2.3** 可读 ⇔ 数据是 public，或会话是 `owner_private`；再叠加场景作用域。公开场景读 owner 私密场景的链接在启动时拒绝（`LINK_PRIVACY_DOWNGRADE`）。每个读路径（检索、`Store.get`、上下文各块、渲染、探针、行动脑提示、CONSULT、BlobStore、作业返回值、导出）都过这条判定，并有泄漏测试。

## §5 文档层

- 文档 `doc:<persona>:<slug>`，按节（`sid` 由标题确定性生成，之后不变）存全文，每节带可见性、注入方式（`always | on_demand | never`）与标签。复用修订账，每次修订带理由、来源、作者、幂等键。
- 操作：`seed`（只在头缺失时）、`replace_section`、`append_section`、`correction`（追加更正，原文不改）、`set_tags`、`adopt_seed`（按节合并包内新种子，双方都改过的列为冲突不覆盖）。**不提供删除**，只有 operator 的隐私擦除写墓碑。`contract` 只读。
- 谁能写：角色只在 `owner_private` 回合写自己的文档（群里只能写那个群的群笔记）；人格作业经数据 API；operator 回滚与擦除。陌生人的输入不能驱动她修改自我。
- **5.4** 种子只填缺失的头，包升级不覆盖；`character_core`/`current_self` 保持 ADR-007 的语义。

## §6 情感引擎

- `affect_events` 只追加、不可修改；变化只能用修订（`close`、`void` 必须写理由、`fix_ts`、`fix_kind`）。投影是纯函数：按人格模型的半衰期衰减，挂着（`open`）的不衰减，`void` 视为从未计入，先求和再钳。
- 对模型只用词：她读到档位、指示句、倾向与来由，记账也用类别词，由人格模型的 scale 映射为数值。心情全局共享；关于某个人的状态按人隔离。
- 只有角色能提交；`ref` 必须是本回合可引用的 id；单条不合格只拒这一条，不打断回合。**没有删除情感事件的 API**，不提供批量重置。
- 注入：`owner_private` 完整投影（含原因）；`public` 只有档位与 public 倾向，不含原因、人、事件 id 或数值；行动脑不注入。情感模块不产生任何可直接发出的句子。
- **6.7** 可选第三路由 `appraiser`：回合结束后异步提案（不阻塞），由她接受、修改或拒绝；过期明示 `expired`。未配置即关闭。

## 人格作业与数据 API（契约 §5–§7）

- 人格包只放可公开的东西：人格模型 JSON、文档种子、skills、集成、作业代码。`registerPersona` v2 校验人格模型，不合格时 Core 惰性并显示原因；没有人格时核心不冒充任何人格。
- 源根由 owner 在本地配置授权，状态 `cohabiting`（旧居还活着，按 sha256 增量、按 `origin + source_identity` 幂等；她改过的文档不被覆盖，列为冲突）或 `cutover`（不再写入）。只有 owner 能切换。
- 数据 API 只对作业开放：写入全部支持 `dry_run`，试运行由宿主强制不写；令牌绑定单一人格；每次写入都审计。探针走与真实回合相同的检索和可见性路径。
- **7.4** 作业在沙箱里跑完即退（无网络、只读挂载已发布作业与授权源根、`/out` 有上限、超时强杀）；只随 owner 开发授权的任务触发；返回给行动脑的只有状态、退出码、计数和报告 id，不含摘录。核心不自动定时运行作业。

## §8 渲染

- **8.1** 角色系统提示 = 核心中性头 + 人格文档中对本会话可读、`inject=always` 的节（public 在前，利于共享缓存）+ 口吻；去掉 harness 身份句。预算 = min(`render.budget_tokens`, 窗口 × `render.max_window_share`，缺省 0.25)：让渲染超预算变大的修改被拒（`PERSONA_RENDER_OVER_BUDGET`），已超时照常完整渲染并标红，**从不静默截断**。回合只存 `system_ref`（修订 id 与 sha），不存全文。
- **8.2** 上下文块按人格模型的 `recall_protocol.order` 排列；「我是谁、对方是谁、我现在什么心情」走确定性注入，检索只负责被话题勾起的往事。
- **8.3** 行动脑系统提示恒为 public 渲染：缺省只有带 `values` 标签的 public 节或显示名；`render.action_persona=persona` 时给出「她是谁」（按任务来源会话的类别取节，不含记忆与状态；owner 试行）。

## 记忆（MEMORY.md）

- 检索 = RRF（向量 + 词法）× 遗忘（owner 定：0.5^(距上次真实使用天数/30) × 0.5^(此后该对话消息数/1500)；只有角色轮次算使用；钉住不衰减；淡出且已被摘要覆盖的原始块退出自动召回，显式 recall 仍可读）。**不删除。**
- **MEMORY §5.2** RRF 只表示排名，不判断「够不够」：另算 `coverage`，不足时上下文明说「证据不足，只能当灵感，不能当事实说」。`invented` 条目任何注入都带「自述编写，非共同经历」标记。
- 审计对大于 16 KB 的文档只存哈希与大小，哈希链照旧可检篡改（D-4）；阶段结果和回执只存哈希与引用。
- 导出是只读派生物，目标必须在工作树外或被忽略的路径。

## §10 节律、心跳、夜间沉淀

- **10.1** 节律块由 `rhythm.timezone`（IANA；未设时明示「以 UTC 显示」，核心没有缺省时区）和 `rhythm.sleep_window` 计算。**节律是她决策的输入，不是闸门**：普通回复绝不因睡眠窗被拦。`public` 会话缺省不注入本地时刻（会暴露 owner 的时区与作息），除非 `rhythm.public_clock=true`。`rhythm.*` 是核心私有键，人格包不得给默认值。
- 心跳见 ADR-012。
- **10.3** 夜间沉淀：原生 daily 计划，每个本地日期最多一次，在 owner 私密场景里列出挂着的情感事件、待决提案和晋升候选；晋升受每日配额与来源门槛（≥2 个回合、≥2 个本地日期）约束，核心缺省不晋升。

## §11 表达

- **11.1** 一段话可按 `speak.split_marker` 切成至多 `speak.max_messages` 段，按序发布；渠道场景按字数排间隔，前段未送达后段不能被领取，前段失败后段取消；崩溃后按原键续发。
- 近期措辞提示：确定性统计自己重复的 4-gram，只提示不禁止。

## §0.3 演示环境

UI 开发与人工检查用演示 profile（只装合成人格 `demo`、测试库、无渠道）；用真实 profile、真实库或真实人格须先得 owner 同意。测试拥有的库用后删除。

## 不做的事

不做 Kazusa 式多轴评估、门控情绪公式、RAG 规划器、多 LLM 巩固链；不做数值关系分；不默认做数值睡眠恢复；不建第二个数据库、向量库或 md 同步守护进程；不让行动脑、群聊或跨场景链接接触 `owner_private` 内容；不替人格标注可见性、取参数值、写题库或导入真实数据；不默认引入独立复审 LLM。
