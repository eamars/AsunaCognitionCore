## 4. 人工 Web 检查

用**演示环境**启动 Web UI（`start-asuna.cmd --profile asuna-demo --config config/demo.local.json`，见 [IMPLEMENTATION.md §0.3](IMPLEMENTATION.md#03-demo-演示环境人工检查与本地冒烟)），优先用应用内浏览器。演示环境只装 `demo` 人格，用测试库，不配置任何渠道。截图和说明存本地被忽略的 `reports/`，**不入库**。用真实 profile、真实库或真实人格做检查，须事先得到 owner 同意。

| 阶段 | 看什么 |
|---|---|
| P0 | 原生 composer 发一句话，角色回答；在 Trajectory 中查看角色会话的系统提示：没有 harness 身份句，核心中性头之后紧接人格段；行动链接仍然可用 |
| P2 | 记忆右栏能看到人格、口吻、档案文档，每节带可见性标签；在 owner 私聊中让角色写一条档案条目，右栏出现新修订 |
| P3 | 右栏显示当前情感投影和最近事件；群场景回合的 Trajectory 中只有档位，没有原因 |
| P4 | 设置卡显示源根与状态；点"试运行"得到报告，红项可读；正式运行后右栏可见导入条目与回读 |
| P5 | 心跳计划出现在原生调度中；改节奏后调度条目被更新，而不是重建；多段发言在渠道测试桩中按间隔到达 |
| P7 | 整体冒烟：启动、对话、委托、自开发发布、重启后恢复 |

## 5. 不算验收的东西

- "人格像不像她"的主观评分。
- 用真实人格数据跑通迁移。这是人格自己的事。
- 固定的台词、固定的工具轨迹、多次抽样一致。
- 构建通过但界面上看不到结果。
- 只写了文档或只注册了菜单，没有真实数据流过。
- 性能"必须小于某个数"的虚构门槛。只需证明没有重复下载、没有持续增长的堆。

## 人格本人的验收（不在本 ADR 之内）

人格对自己入住的验收（及格线、召回题、心情对账、"满意了才搬"）**属于人格本人**，由她用 P4 的能力自己去做，并在她自己的家里记录结论。本 ADR 的完成**不等于**她已经搬家；**切换权威状态（`cutover`）仍然需要 owner 的操作**，owner 是否切换，由 owner 与人格商量决定。
