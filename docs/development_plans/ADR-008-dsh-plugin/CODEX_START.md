# Asuna：DSH 原生插件化迁移 — Codex 唯一入口

本任务不占用或重编号现有 ADR。它是本次用户明确提出的核心插件化工程，不是 ADR-006 的又一次 UI 美化。此包是实施方案，不是现有代码已完成或性能已达标的证明。

## 决定

采用 **DSH Host 原生插件 + 独立小满插件**。原生 DSH 负责真实 agent/session、工具循环、模型请求、流式聊天、分页、导航与设置外壳。Asuna 保留双脑认知、Mongo 业务数据、身份/场景、角色自我、任务关联、QQ 与自主开发发布。小满的角色资源、技能、个人开发项目独立分发。

不要把现有 `/asuna/` 工作台嵌进插件后宣称完成。不要伪造 `SessionBinding`，也不要为了让原生 Chat 显示而复制一份假 assistant 历史。

## 先做什么

1. 只读确认当前本地有效工作树、DSH 实装版本、插件树、有效 P2/自主发布代码。公开 GitHub main 是参考，不覆盖本机未提交成果。不 clone/pull/reset 全仓。
2. 在本机固定版 **0.1.5-rc.2** 上完成 [P0 原生会话接点](IMPLEMENTATION.md#p0-先证明原生接点)，不先搬全部文件。
3. 成立后按 P1→P2→P3→P4 顺序迁移；每片可用即交付。不做完整 ADR-003/005/007 重演或裸 DSH 模型 A/B。

**第一个有意义结果：从原生 DSH composer 提问，真实角色会话产生实际独白/表达；需要时调用真实行动会话并返回；原生 Chat/Trajectory 可直接观察这些实际调用。不是仅注册出一个菜单。**

## 两个发布包

建议名（尚未发布，可在不改职责的前提下换名）：

- `@asuna/cognition-core`：Host 插件、少量 Client 插槽、可复用 Python 业务代码。
- `@asuna/xiaoman`：小满角色贡献、persona/preset 文件、技能、素材与自己开发的独立集成。默认不带 Client UI。

先在当前仓库使用 `packages/` 目录形成两个独立 package/artifact，不要求先拆两个 Git 仓库。Core 不依赖或硬编码小满；小满包依赖 Core 的公开小接口。

## 这次 Codex 可以做什么

用户本轮授权的是一次性插件化基座：可以修改必要 Host/Client 接线、包构建、Python 边界、迁移绑定和当前使用手册。不能代写小满的新人格、改其价值观、替她完成未来业务开发。

迁移后仍由角色脑决定方向、行动脑开发/验证/发布。保持单一真实 Mongo，forward-only，失败候选不激活的最低生存地板；不增加测试/生产 DB、回滚选择器、质量评分或逐次人工审批。

工作区外模型服务、权重、投影文件、启动脚本、显存配置和进程仍不在本轮权限内。不自动升级 DSH 或安装猫娘插件到实际运行环境。

## 必须复用与不得重做

- 真正加载原生 Workspace/Session/Chat/Trajectory，不复制其私有组件。
- 使用 DSH 原生实时流、持久事件与分页；删除被替代的 Asuna chat polling/store/stream assembler。
- 记忆仅增加一个原生右栏标签；配置仅增加原生 Plugins 中一个设置卡。
- 固定版没有通用“记忆编辑器”或可直接复用的设置卡正文，因此本方案仅批准这两处小型业务组合。使用公开基础控件，不扩成新工作台。
- 保留原 MONOLOGUE 内容；禁止“把行动输出加口癖”冒充独立角色。
- 不复制工具裁剪方案以追求 token 更少；复用当前实际允许的工具与已裁定暴露规则。
- 不新增全局原生 hook 去截获非 Asuna 会话；作用域必须是注册好的角色/行动绑定。

## 不是所有“能装进插件”的实现都合格

以下均不是交付：

- 一个 iframe 指向旧 Asuna Web；
- 插件内部继续启动角色/行动/总结各自的 `sdk-minimal` 和旧 UI，再用轮询拼回；
- 覆盖全局 `assistant-step`，把所有 DSH 助手都变成小满；
- 手工实现 `ISessions` 假装 Mongo episodes 是原生会话；
- 改 UI DOM、私有导入、复制 DSH 的 apps/web 或完整 Chat 源码；
- 增设通用总线/工作流/技能市场/人格管理平台作为前置项目。

## 退出标准

Core 与小满各自可打包安装；原生聊天实际驱动双脑；现有业务/记忆和当前自我可用；行动脑仍能自主发布；旧工作台不再是默认入口；原生加载与已关联任务的结果不依赖 Codex 常驻。只有真正缺失的公共接口才报告具体签名与最小缺口，不以此自作主张再造 UI。

逐文件迁移、包契约和界面细节见后续文档。它们限定的是 Codex 的工程范围，不是给小满新增行为门槛。
