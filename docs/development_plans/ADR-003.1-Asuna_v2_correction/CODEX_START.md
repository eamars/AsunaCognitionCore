## 先读这一条

**双脑是为了增强独立的情感与角色能力，不是削弱工具、编码、长流程或自主排错能力的理由。Asuna 扩展 DSH，不再以自定义检查替 DSH 接管这些能力。**

**“裸 DSH 基线”是设计参照，不是运行对照任务。不要启动裸 DSH 对照实验、逐项 A/B、重复采样、成功率矩阵或轨迹比对。** 判断新增代码是否擅自缩窄原生执行语义，看实际配置、调用链、扩展点和错误传播；不需要先让模型撞上限制。正常功能验证仍然要做，但它不承担“证明所有模型行为不退化”的任务。

## 本包如何覆盖旧要求

本文件与 [执行决定](DESIGN_AND_CURRENT_FIX.md) 替代旧 `asuna_agentic_loop_correction` 包的执行入口和纠偏步骤；旧报告保留作证据，不同时执行两套指令。旧 V1/V2.2/UI 文档中冲突的限步、强制结果报告、恢复阻断、固定恢复验收包以及逐功能裸 DSH 对照解释均不再执行。非冲突的产品目标与已有授权继续有效。

不重新做 V1；保留现有模型、DSH 固定版本、Mongo、Web/CLI、技能、任务和未提交成果。Kazusa 和裸 DSH 小满只作为设计/经验参考，不移植实现。先读本文件及执行决定；示例按需要读，不要求把所有历史开发包重新灌进模型。

## 当前要做什么

**先删掉/缩小 ADR003 已明确的扩展层阻断，并修通原 NapCat 任务；不要新增一个“恢复系统”。**

1. 看原报告关联的运行版本、相关文件和未提交改动，避免把磁盘修改当成已加载。不要全库审计、清库、重置工作树或丢弃已有方案。
2. 在实际调用路径中修复 `occurred_at=None` 等已知阻塞，同时处理该输入被留在终止状态、错误未交回模型的问题。原输入和原目标保留，诊断不能再次强依赖同一个坏检索器。
3. 直接移除无依据的额外 65 步拒绝、强制 `task_status` 结束资格以及关闭原生恢复的覆盖；具体处置见执行决定。不是把阈值调大、换 ID 绕计数，也不是保留多余检查再为它加修复 agent。
4. `UNKNOWN` 只表达真正不明的操作结果，不自动屏蔽整项任务的反馈、合法核实和继续工作。校验只阻止其确实要保护的动作，不扩张成认知禁令。
5. 按改动做必要的局部代码/接线验证，然后回到原授权 NapCat 任务，让运行中的 Qwen 继续已有上下文和目录。QQ 可用才继续原定群聊、定时成长和 Bonus。不要先完成一个新的恢复验证项目。

这些是同一条修复工作的顺序提示，不是五个新平台或五组强制模型测试。已完成且未受修改影响的部分不重跑。

## 开发中不得再次误读

- Gemma 的有界流程约束她自己的角色生成阶段；不逐步审批 Qwen 的工具、重试、调试、子任务或压缩。没有新增角色内容，也不能因此暂停已授权的行动任务。
- 普通工具错误由当前 DSH/Qwen 回路继续；新增扩展层错误只补缺失的传递或续接，不代替模型制定固定修复动作。
- 没有证据说某个故障路径已触发，就写“代码分支”；一次成功不证明全部能力，一次失败不证明模型不行。不能因此开始统计试验。
- 程序需要的关联由代码填。自然语言结果不必再通过一套完成报告 schema 才能进入角色理解；未查清的结果也不能虚报完成。
- 新增限制、拦截、强制依赖或错误 handling，必须说明具体需求、原生机制为何不足、实际缩窄了什么、为什么不能删掉或放到更窄的地方。写在现有 diff/短报告即可；不建立审批平台、理由 schema、评审 agent 或每次运行前的检查表。
- 本包已明确撤销的限制可直接纠正，不反复向用户确认。全新、未获授权的能力收窄不能因“架构完整/便于审计/统一格式”自行落地；不实施该收窄，继续不依赖它的工作。
- 保留真实身份、授权范围、用户取消和不重复未知副作用的要求；“扩展而非限制”不等于给所有群友宿主权限。

## 验证和回报

用最小的已有测试或局部检查确认自己改动的确定性分支；用原来的自然语言 QQ 任务检查正式路径是否可用。没有额外的裸 DSH 进程、对照评分、同词回复、同工具序列或同执行步数要求。不为了收集错误专门制造多轮真实 QQ 发送。

回报只写：**改了什么不合理设计；相关代码现在怎样走；做了什么必要验证；原任务实际到了哪里；真实错误/缺项；唯一下一步。** 保留原始自然语言和 traceback，不用哈希和 PASS 数量替代事实。
