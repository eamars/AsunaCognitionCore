# V2 · 由 Asuna 自己开发 NapCat QQ 接入

**这是潜在的第二版真实任务，不在 V1 核心可用之前启动。** 用户通过已交付的本机聊天入口提出目标，运行中的 Gemma／Qwen 完成主要开发；Codex 不预写 NapCat 成品。

“自主”在这里指系统根据自然语言目标自行规划、调用工具、编写/修正实现并保存能力，不代表修改模型权重，也不要求零错误或完全无需提供登录授权。

## 1. 开始前只确认必要条件

本机聊天、真实工具往返、新记忆和基本恢复已可用；Qwen 可以使用通用执行工具，自己的持久技能目录可写。V1 基础成长已有有限证据。若用户主动将 QQ 选为首个技能成长实验，可以用本任务补足 C6 的工具成长证据，但必须将 V1 尚未证明部分如实列出，不能先宣称完整 V1 已通过。

Codex 已按 `CHANNEL_SEAM.md` 提供实际可调用的入站、公开出站和回执接入位置，以及 `RUNTIME_API.md`。只是写了接口说明而没有真实可用调用，不算前置完成。

用户已有 NapCat 服务由用户或现有部署负责登录。只读取指定配置，确认运行端点、传输方式、当前账号、用于测试的对方账号和凭据来源。文档没有本机地址，不得从旧日志抄旧 QQ ID、默认端口或默认 token 当新授权。

初始允许一个明确的私聊对象，群列表为空。首次真实发送需有此任务明确的测试授权。若旧小满也在同一账号回应，先用不同测试对象/新实例，或由用户明确切换对应范围，不能让两套角色重复发言，也不能擅自停掉旧系统。

缺少扫码、token 或端点时，通过本机入口一次说明缺什么；不扫描全部网络或账户配置。缺 QQ 凭据不影响已经可用的本机聊天。对外读取文档/访问获准 QQ 服务不等于使用云模型，模型调用仍全部走本地部署。

## 2. 开发者分工（此表是验收的一部分）

| 主体 | 应该做 | 不应该替代 |
|---|---|---|
| 用户 | 提出目标；指定 NapCat 和测试对象；完成登录及必要授权；实际发消息验证 | 不手动充当两个模型的消息中转 |
| Gemma | 理解为什么想在 QQ 交流；提出目标和行为约束；读结果、形成表达、吸收反馈 | 不要求她自己可靠选择全部 API 或维持网络循环 |
| 运行中的 Qwen | 读文档/环境；选择传输；写适配器、调试、试运行、保存用法；需要时改进 | 不把全部开发步骤转回 Codex，不直接代替 Gemma 回答每条 QQ |
| Codex | 修缺失的宿主 API、配置接线、启动器、正常错误回传；帮助用户拿到可运行入口 | 不提前写 NapCat adapter，不手工修它每个任务内错误后宣称 Asuna 学会了 |
| 运行时 | 授权、可靠场景映射、模型/任务调度、已决定公开内容的发送与回执 | 不替角色预先生成感受，不把“代码完成”记成“上线成功” |

第三方协议客户端/依赖可以复用，但使用范围和来源要明说。复用不等于必须从空白逐行造轮子；也不能下载一个现成完整 bot，只改名字就声称 Asuna 自主设计了适配器。Codex 若实际参与了语义实现，诚实标“共同开发”。

## 3. 将任务交给她，而不是绕过角色直接给 Qwen 编程题

通过现有本机聊天使用 `tasks/ASK_ASUNA_TO_BUILD_QQ.md` 的自然语言。Gemma 形成意图；Qwen 获取必要材料并执行。任务中的配置指向是给代码用的，不把 token 正文放进两侧上下文。

只向 Qwen提供：可读的正式文档位置、已核实的连接配置来源、允许的目录/网络、宿主 API 和真实错误。不要提供已完成的 QQ 适配器、隐藏答案、固定测试语句识别代码或一句话就回显的假聊天脚本。

执行期间用户能继续在本机与 Gemma说话、询问进展、调整范围。Qwen遇到可恢复错误自行重试/修正；缺权限、缺事实或需要改目标再回到角色。普通查库/查文件/协议调试不要求 Gemma每一步批准。

## 4. 只做一条传输路径，不实现全部 NapCat 协议

NapCat 官方配置文档区分 HTTP服务端、HTTP客户端、WebSocket服务端（正向）和 WebSocket客户端（反向）；WebUI管理端口不是 OneBot 业务端口。[N1]

由 Qwen 根据现有实例实际启用的方式选择一条。若正向 WebSocket 已可用，作为外部客户端通常适合本任务：可同连接收事件和发请求。[N1][N2] 若已部署的反向 WebSocket 或 HTTP事件推送更合适，就沿用它，说明原因；不要为了本设计重配旧服务，也不要一次做四种模式。

开发的是 Asuna 外部适配器，第一版不要求安装 NapCat 内部插件、修改 QQ 客户端或重建 NapCat。协议 JSON是适配器处理的数据，不是强制 Gemma 和 Qwen 每轮输出的聊天格式。

WebUI token、OneBot API token 和 Asuna 的适配器凭据不可混用。实际鉴权和消息格式按安装版本核对，缺信息时从合法文档/配置获取，不靠这里写死的示例值。宿主、WSL/容器的 localhost 各指所在网络环境，验证真实可达地址，不能把宿主地址假设成容器回环地址。

只做文本私聊，确认真实发言者、目标会话和自己的账号，过滤自身消息及心跳等非聊天事件。数组消息中的回复/提及语义需按真实事件保留；没实现的消息类型明确标为不支持，不假装读懂图片/语音。

## 5. 任务推进路径

### A. 搞清环境与实现位置

Qwen 读取宿主契约与 NapCat 当前文档，确认端点、账号和传输。选定自己的实现目录，写一份短用法；环境缺少什么就报告具体缺项，不启动新的架构设计项目。

### B. 做出真实收发适配器

Qwen 编写并运行代码，先确认能得到实际事件/接口返回，再接到宿主。自身代码报错原样返回 DSH，由它继续修。不要要求一次成功，不把一项任务变成“代码修复 benchmark”。

私聊输入必须进入正常角色路径，输出必须来自正常 PublishService。传输级测试发言可以在已授权对象进行，并明确标注为系统测试；这不算角色对话验收，也不纳入虚构的角色经历。

### C. 发真实消息，走一次完整认知链

由用户在允许的 QQ 私聊发送新内容。适配器把事件送进宿主队列，程序应能唤醒认知处理，不等待用户再去本机敲一句。Gemma 自然回应，发布器交给适配器发送，实际回执保存。

接着在 QQ 上提出一个真实小任务，Qwen 执行，Gemma 理解结果并回应原私聊。只有文字回显或另一套直接调用模型的机器人不算通过。

### D. 保留能力并正常运行

适配器入口、依赖、配置引用、用途和启动方法保存在自己的持久能力目录。宿主启动一次并管理生命周期；不是 Qwen每条消息手动挂一个等待脚本。

用户按已说明方式重启服务后，适配器能被发现并启动；不需要重做开发、重新输入“你会用QQ”、手工 index 或重挂门铃。正常 QQ 收发、心跳和重连应由代码完成，静默时不消耗循环 LLM 调用。

V2 本机聊天客户端和后台宿主分开生命周期；关闭客户端不自动关掉已明确启动的 QQ 服务。停止整个服务的命令也要真实交付，不能承诺关闭后它仍会工作。

### E. 获得反馈并继续成长

通过真实私聊询问体验或接收自然反馈。Gemma 决定是否改变表达、处理方式或关系理解；Qwen仅在需要技术改进时参与。一次反馈不必改人设，也不能把赞美机械转换成总好感加分。

文字私聊可靠之后，可由用户选择授权一个测试群；再之后可以发展图片／表情包作为另一个真实成长任务。它们不是本轮文本接通的前置，也不能通过“暂缓”把通用媒体表达永远排除。

## 6. 验收：五件实际看得见的事

### Q1 · 用户从 QQ 发起，她真的被唤醒

准备：指定测试对象、有效配置、无旧bot重复回应。用户发：“小满，我从 QQ 来找你了。”再连续自由追问两轮。

通过：真实 QQ 内容进入当前场景，Gemma 的公开回复实际出现在同一私聊。无需本机额外按回车唤醒，无Qwen直答。保留输入、真实回复与必要平台回执；握手成功本身不算通过。

### Q2 · QQ 聊天中能做事，再回到聊天

输入：“帮我看看笔记里备用线放哪儿。原笔记别改。”接着聊一句无关的话，最后回到之前话题。

通过：Qwen 实际取数，角色得到真实结果并回复原私聊；期间消息不丢、不被误判为取消；工具结果不变成另一个通用助手的回复。

### Q3 · 身份与记忆连续，但不是默认混库

在 QQ 留下一条新的普通偏好，继续交流并在恢复后问起。若用户明确授权本机私聊与该QQ私聊共享记忆，再在本机问同一细节。

通过：实际检索到新聊天，人物/场景正确。尚未配置跨私聊共享时不要求读取本机私密经历；禁止把不共享误判为记忆损坏，也禁止靠昵称自动合并。

### Q4 · 正常重启和一次真实故障后仍能使用

按文档停止/重启宿主，重新从 QQ 发消息。再用一次实际发生或受控的一次短断连检查可见错误与恢复，不做多维故障矩阵。

通过：技能无需重写即可继续；没有重复自言自语/回复回环；错误出现在本机 trace。若平台不能提供离线补史，明确说明不保证那段消息已追回，不假称“没丢”。发送回执不明时不盲目重复副作用。

### Q5 · 证明是谁开发、用户能怎样继续使用

查看 Qwen 运行中的文件创建/修改、命令与错误恢复记录，以及最终短用法。用户读到 Gemma 对这次能力和反馈的真实理解。

通过：主要实现由运行中的 Asuna/Qwen 完成；重启后可复用；用户拿到实际启动、停止与查看错误的办法。普通 diff 与原始记录足够，不要求哈希证书。若 Codex代写关键实现，必须如实标注，不能通过此项“独立成长”。

可先报告“私聊可用、记忆未验证”等部分结果，但不得合并成“QQ接入完整通过”。这五项只覆盖有限真实路径，不证明所有网络、群聊或平台版本都可靠。

## 7. 收尾报告只需一页

实际采用的 NapCat 版本/传输方式（非密钥）、代码目录和依赖、可执行启动/停止方法、一段真实QQ对话、一段任务往返、重启结果、一个真实错误及恢复、她保留下来的能力/理解、仍不支持什么。

不要把 report.json 的字段数量当完成度。若账号/网络阻塞未解决，交付真实阻塞和已完成代码，保持本机入口可用，不让 Codex悄悄代写全部适配器来获得成功结论。
