# 提议：她决定不说话时，那一轮怎么显示

| 项 | 内容 |
|---|---|
| 状态 | 提议，等 owner 决定；未实施 |
| 日期 | 2026-10-05 |
| 关系 | 与 ADR-010 相关（都是「按 DSH 原生方式做」），但可以单独决定、单独实施 |

## 现象

在「小满 · 本地私聊」里，她决定委托而且不先说话（`next=delegate`、`speak_before_action=false`）或决定沉默（`next=silent`）时，角色脑那一轮的最后一步就是 DECIDE。DSH 把一轮最后一步的正文当作这一轮的回答（`ui-chat/src/client/conversation-nodes/turn-process.ts` 的 `latestAnswer`），于是页面上「角色脑」标签下面是一整段原始 JSON：

```text
角色脑
{"next":"delegate","goal":"只读查询……","constraints":[…],"recall_query":"","speak_before_action":false}
```

她说话的轮次（`next=speak`，或委托前先说）不受影响：SPEAK 是最后一步，DECIDE 留在「Completed in …」折叠里。

按签收标准（「看不懂就删」），这一段读者看不懂。但它是模型的真实输出，不能伪造或删掉，只能换一种原生的表达方式。

## 选项

### A（推荐）：DECIDE 改成一次工具调用
在 DECIDE 这一步给角色脑一个 `decide` 工具，参数就是现在的决策 schema。她调用这个工具，而不是在正文里写 JSON。
- **渲染**：DSH 把工具调用画成折叠里的一行，最后一步带工具调用就不算回答（`latestAnswer` 在有 tool-call 时返回 null）。不说话的那一轮只剩「Completed in …」折叠，后面接行动脑的原生记录。角色脑和行动脑的关系就是 DSH 原生的父 agent 调子 agent，两边渲染自然一致。
- **校验**：参数先由 DSH 按工具 schema 校验，失败作为工具错误交还给她（`tools/post-execute` 的 feedback）。这就是 answers.py 现在用「程序检查」文字去做的事，换成了 DSH 自己的通道。answers.py 里 DECIDE 的 JSON 检查可以删掉。
- **代价**：
  - 阶段协议要改：`stage_decide.md`、协调器从工具调用取决策、原生通道让这一步可以调用 `decide` 且只能调用它、`answers.py` 里 DECIDE 改为「必须有这次工具调用」。
  - DSH 的循环在工具调用后会继续下一步，需要让 `decide` 结束这一步，而不是再问一次模型。具体做法要先在 rc.2 里核实：用 hook 停住循环，或者把这次工具结果当作这一阶段的结果交回去。
  - 角色路由的模型要支持工具调用（当前模型支持）。
- **风险**：中等。改的是每一轮都会走的路径，需要合成 profile 上的完整回归和真实页面走查。

### B：让 DECIDE 的 JSON 写在 ```json 代码块里
只改 `stage_decide.md`，解析时去掉代码块。页面上这一段会显示成代码块，比一行原始 JSON 好读一点，但仍然占着「她的回答」的位置，读者还是会以为她回了一段代码。代价最小，问题只解决了一半。

### C：在页面上把 DECIDE 回答藏起来
需要自定义渲染，违反「不做自定义组件、两个脑共用同一套渲染」的要求。**不采用。**

## 建议

做 **A**。顺序：
1. 在 rc.2 里核实怎样让一次工具调用结束这一步（只读调查）。
2. 在合成 profile（`demo`）上实现，并加回归用例：不说话的一轮没有回答气泡，委托在折叠里显示为一次工具调用，参数错误时作为工具错误回到她那里。
3. owner 在真实页面走查后再切换。

B 可以作为 A 落地前的临时措施，但我不建议做：它会改变她的输出格式，A 落地时还要再改一次。
