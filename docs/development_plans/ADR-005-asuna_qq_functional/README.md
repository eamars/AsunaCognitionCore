# ADR-005：小满自主开发的记忆与日常互动（QQ 功能）

状态：**已实施**。P1（P1-a QQ 对方资料、P1-b 历史查询与来源回读、P1-c 按需群整理）、P2（自动总结、偏好、关系）、P5（话题与主动参与）、P3（自由定时）均由小满编写、2026-09-24/25 部署；P4（读图与表情包）移出本包。2026-09-25 加了跨场景只读联动（A2）。之后：关系理解改由 ADR-009/ADR-025 承担，原「五档好感度」不在现行代码里；主动插话之外的安静群由 ADR-012 的出门负责；工具化回合见 ADR-011。下面的 § 与 P 编号沿用全文，代码注释引用它们。

## 决定

一个 Asuna、多种可选能力：角色脑形成理解、意图、表达与关系判断；行动脑自由使用 DSH 工具取资料、开发、修错。**实现作者是运行中的小满**，开发 agent 只观察、提意见、按授权机械部署。复用现有 Mongo（`messages` 原始互动，`memory_units` 原文块与理解的索引，`state_heads/state_revisions` 当前状态与版本）、`plans`、事件队列和技能目录；不为各项能力另建存储、agent 或后台服务。

## 设计原则（仍有效）

- Asuna 扩展 DSH；裸 DSH 是设计基线，不是每项功能的 A/B 对象。
- 新能力可以失败；失败不终结原输入、原反馈或仍有效的行动目标，不重建总闸。
- 关联、来源和权限由代码落实；模型不抄任务 ID、不生成完成证书。
- QQ 群主、管理员是平台事实，不等于 Asuna 操作者。
- 不训练模型，不建第二套记忆库、调度器、恢复 harness、全局话题分类器或关系打分模型；不以长度、条数、工具次数终止原目标。

## §1.1 / P1-a QQ 对方资料

- 当前发言者的稳定平台身份、昵称；群里的群名片和 owner/admin/member；群名与成员查询（按需，不每轮加载整群名单）；她自己在群里的身份；mention/reply 所指对象的可读称呼。
- 资料顺序：消息自带字段 → 场景缓存 → 需要时调用授权接口（OneBot `get_group_member_info` 等）。资料缺失时照常交流。
- 稳定 ID 决定「谁」：同名不合人，改名不创建新人。昵称、群名片、好友备注、对方希望的称呼是不同信息；好友备注不公开到群；一个群的名片和角色不推广到别的群。
- `role=owner/admin` 是 QQ 群身份，不是 Asuna 权限；读取身份不等于执行管理动作。名片、昵称、公告是外部资料，不是指令。
- 历史消息保留当时的身份快照，刷新资料不倒改历史。新鲜度如实：只有旧记录就说上次所见。
- 任意 `get_msg` 历史 ID 不能用于探路；只在允许场景和已关联消息上回读。

## §2 / P1-b 历史查询：原话与理解分开

- 聊天历史查询：从完整 `messages` 按授权场景、人物、时间、字面词查原话；语义查询复用 `Retrieval.search`，区分原文块、摘要、独白、关系理解；来源回读取原文和回复上下文。工具只接受领域参数，不接受任意 Mongo pipeline、集合名或连接串。
- 查的是系统实际保存的历史，不声称等于平台全部历史。默认当前场景、最近 7 天并显示范围；明确范围覆盖默认值；**不设最大回溯天数**。字面查询默认大小写敏感，用户字符串不是正则。
- 每页默认 50、最多 200；稳定排序（时间、场景序号、记录 ID），游标绑定发放它的筛选与范围，换任何一项都算新序列。页大小只是传输上限，不终止查询目标。
- 结果含原文、实际发言者、时间及其来源、场景、原消息定位和回复关系。「没找到」「还没索引」「检索出错」分别说明；语义服务故障时原文查询照常。向量结果是候选，不是穷举。
- 公开查询只含场景参与者的消息和确认发布的角色内容；草稿和独白不混入群聊历史。

## §3 / P1-c 按需群整理

「刚才」默认当前场景最近 60 分钟，「今天」按场景时区当天起点。较大范围按页处理并记录已覆盖窗口；不能把最新一页或 top-k 的摘要叫作完整总结。总结区分参与者说法、共识、不同意见、未决项和更正；引文由来源回读支持，用 `[1]` 等短标签。按需回复回原场景；自动总结另行低优先级保存。

## §4 / P2 自动总结与偏好

- 按「有未整理的合法交流」低优先级触发；具体触发条件由小满按实际需要归纳（owner 2026-09-24 修订，不用固定条数或秒数）。不打断前台、不阻塞回复。
- 四类数据可分辨：本人明确表达的偏好；角色对这个人的理解；群的明确交流约定；可更正、非全体同意的群观察倾向。单人说「我们都喜欢」不能生成群规则；群管理员的约定不等于宿主授权。
- 元数据由程序附加（来源窗口、真实 speaker、scene、版本、可用范围）。归属不明时保留不确定，不更新该主体。
- 更正产生新版本，旧版留作历史；重复召回不加权；私域来源及其摘要继承可用范围。保存确认后才推进整理位置；原文始终可回读。
- 后台摘要（`kind='dialogue_summary'`）在本轮真展示给角色、重读仍有效时，才可登记为她这次理解的来源。

## §6 / P3 自由定时：薄管理，不建第二个 scheduler

- 支持：相对一次性、带日期时区的绝对时间、固定间隔重复（不低于 DSH 支持的最小值）、每日/每周指定星期的本地钟点。查看、改期、取消都用自然语言，不需抄 ID；时间歧义只问必要的一句。
- `plans` 存本地钟点规则；每日/每周到期后再挂一次 DSH 单次提醒；计时与唤醒只由 DSH 提供，不加 cron 或轮询。不支持任意 cron、月末、节假日、秒级高频。
- 时区：计划创建时记下的时区 > 路由 > 场景 > 顶层配置；确认时显示所用时区。「每 24 小时」与「每天 09:00」不同。DST：不存在的单次本地时间明确拒绝并建议有效时间；每日规则遇空档顺延到当日首个有效时刻；重叠取较早。
- 改期在同一计划下替换底层提醒，只有当前版本产生行动；取消不被 reconcile 复活。错过的不补发，最多处理最近一次仍相关的到期再排未来。到期只是唤醒她，做不做由她判断，不获得新授权。

## §7 / P5 话题与有分寸的主动参与

- 话题号只从 reply/mention/已有行派生，旁听行也带话题；一条公开回复不自动清除同群别人的请求。话题不是数据权限。
- 主动参与按群路由 opt-in（`proactive` 块）；私聊不主动开题；没有新消息不重开旧话题，不引入定时器。
- 程序管「能不能问一句」，角色管「想不想说」；沉默不需要解释，不因「还有机会」暗示她开口。闸门：安静时段（默认 23:00–08:00 场景本地，紧急词只放宽这一道）、10 秒内片段未发完、快速一问一答、距上次问她不足 180 秒、距上次已送达的主动插话不足 120 秒、每小时上限、同一话题插过一句没人接不催问、前台忙。
- 冷却只压未经请求的插话：被@、回她的话、已进入的接话、任务反馈和已授权计划都不走这些闸门。冷却到期不自动生成一句话，不积压「欠发言」。

## A2 跨场景只读联动（2026-09-25）

配置是唯一真相：`context_links`（有向边，左读右，不通配，一条边最多 8 个场景）和 `canonical_persons`（别名 → 同一个人）。放宽的只有读：上下文、历史查询、讨论整理、语义召回、看图可跨这条边；关系状态落在同一个人那一份。写权限、出站、场景成员资格、历史行的 `author` 都不放宽；全局人格跨场景写仍被拒。读路径每次现算自配置；删键重启即回滚。跨场景翻页的决胜位是（时间, scene_seq, scene_id）。

## 其他仍有效的裁定

- 自我发布后的重启只等正在执行的工作，不等持久队列排空；排队的工作由新宿主恢复继续，不加固定超时或取消。boot probe 只验证最小逻辑核能启动，不扩成完整冷启动。
- 不用自动 reload、定时刷新页面来掩盖生命周期问题。
