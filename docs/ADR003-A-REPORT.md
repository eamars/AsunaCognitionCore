## 实现及验证范围

- RuntimeHost 持有 Application、Chat 队列、索引线程和可选通道监听。没有调用 debug-only chat()/terminal()。
- 原文先保存，接收返回不等待检索或模型；入站 ID 去重，重启补入已接收输入。原生 operation 回执继续用于角色阶段恢复。恢复时重新核对 policy 与路由；未知行动副作用不自动重做。
- 保留两个 lane，角色队列按场景公平调度；工作目录授权从本机固定配置改为显式身份/场景绑定，不给新场景继承 owner 文件或私域技能。
- 适配器使用三个实际 HTTP 接口：规范化收件、领取公开输出、报平台回执。外部公开正文先标待发，领取保存 attempt；无回执不算已发送，未知不自动重发。回传沿原始外部消息关联目标。
- 26 项相关回归通过（本机真实 Mongo，模型替身；包括聊天、UI、资源隔离、理解、模型配置和宿主新增契约）。Python 编译、两处 JS 语法检查和 `git diff --check` 通过。
- `tools/probe_host_seam.py --debug` 的真实 Mongo/HTTP 受控重放通过，最后记录为 `reports/host-probe-cb1522b845a8/result.json`：先存后处理、重复收件、scope 注入拒绝、丢失内存队列后恢复、只领取公开正文、无本地 sink 假回执、未知发送不重试、迟到及重复回执。请求与回执都是显式替身，未调用平台，不能算 REAL_QQ。
- 测试还覆盖反馈阶段已有原生回执的恢复及其原始平台 reply target；不是仅验证一条直接回复。

## 真实错误与处理

主动停止第一条处理中的 Web 输入时，原 DSH `/run` 返回 `httpx.HTTPStatusError: Client error '409 Conflict'`。该输入保留 INTERRUPTED 与完整 traceback，未产生公开回复。重启没有重做这一已主动中断输入，下一条已排队输入成功恢复。错误可在页面折叠摘要和执行详情中看到。

首次隔离重放的测试配置用了本机 persona 名，而隔离 fixture 只初始化了 P1，触发 `REQUIRED_PERSONA_MISSING`；修正测试配置后通过，未修改生产人格。首次相关回归也发现旧测试默认把 dm-a/A 当成 owner 授权目录；已在这些测试中明确其资源绑定，没有为使测试通过而恢复跨场景工作区继承。
