# ADR-005：交给小满的启动任务

由用户在现有 Asuna Web 对话中提交下面的任务。当前界面地址和部署以本机为准，本包不要求安装或完成 ADR-004。以下是新项目的真实委托，不是让 Codex伪造旧失败任务恢复。

2026-09-24 后续方向由用户更新：P1 已部署；继续 P2 → P5 → P3，P4 移出 ADR-005。完成的可应用改动由 Codex 直接部署，不增加 Codex 验证轮次。ADR-007 由架构师另写目标；届时尽量少给小满步骤指示，只守住执行 loop 可继续。

---

小满，这次 ADR-005 由你自己开发。目标是在你现在已经能交流和做事的基础上，让日常使用更方便：

你能知道 QQ 对方的昵称、当前群名片、成员或管理员身份；能按原话、关键词或意思查自己的授权聊天记录；能替群友整理讨论，也能自动保存总结、个人偏好、群约定和你对人的理解；能跟上话题，在合适的时候主动参与；还能安排和管理真实定时任务。

先做一个可以马上用的小功能：把 QQ 当前对方的信息读清楚，并让改名、换群名片之后仍然认得是同一个人。接着完成历史查询和来源回读。按文档的小片次序逐步做，具体方案、代码与普通错误由你自己处理，不需要每一步等 Codex批准。

Codex 不替你写宿主或 adapter。确实要改宿主接线，也在你实际获准的开发目录中由你完成，产出可应用改动后由 Codex 按本轮授权直接部署。不要直接动不在授权范围的运行配置、访问规则或其他人的数据。当前缺哪项写入或接口条件，就说清那一处；不用等待所有条件齐全才处理独立的工作。

保留当前人物、记忆、模型、DSH 工具与续接能力，不重建整个项目，不要求先完成 ADR-004 UI。不要为了检查而加工具步数上限、报告格式门槛或额外终止条件。出了普通错误，在原目标下查明和继续；不要靠别人重述任务才能动起来。

代码、必要检查、技能说明和使用方法都由你完成。已有成果就复用，不要为了验收重写一遍。每做通一小片，告诉我现在怎样使用；没完成或没验证的部分直接说明。

当前功能边界看 `DECISIONS.md`，QQ 资料看 `QQ_AND_VISION.md` 的 A 节，小片顺序看 `DELIVERY_PLAN.md`。不需要每次把这些文档当成你的角色自检规程。

## 关于权限与真实开发主体

本任务授权的是本轮功能研发方向，不自动扩大操作系统、数据或 QQ 平台权限。在现有可写开发域内可以自行编码、测试和修改；若需要新的项目开发权限或部署操作，由用户明确授权范围，之后不必逐行审批。不能通过修改运行时来给普通群友扩权。

“运行时负责可靠保存/权限”说的是软件职责，不意味着代码必须由 Codex 编写。小满可以实现这些接线；启用仍遵守当前实际授权。没有可用的宿主开发路径时，把具体接口/路径需求和已完成的独立工作留下，不另造一个能绕过宿主的 QQ bot。
