# ADR-006｜最小实现边界与开发顺序

> 范围修订：P2 的完整原生 WorkspaceBrowser/Chat 接入不执行。使用固定版公开基础组件与现有 Asuna 只读投影组合左栏及聊天，右检查器保留。原位流、稳定 key、来源/授权/停止语义与旧分支清理仍按下文执行。

## 1. 显示链，而不是执行链

```text
现有可信 Asuna 场景/任务关联 ──→ 当前观察范围与动作回调
现有 provider 只读观察流 ──→ Asuna 消息原位投影
现有阶段正文、公开记录与回执 ──→ 同一消息的业务标签/结算
                                     ↓
                         DSH 公开基础组件＋Asuna业务组合
                                     ↓
                         保留的右侧会话检查器

原始 provider bytes ──→ 既有审计（不送网页）
provider 非内容元数据 ──→ 对应消息的折叠诊断（按需读取）
```

禁止反向依赖：UI 渲染、未知字段、Web 连接、原包加载错误，不决定模型能否继续。不要增加请求格式、状态证书、恢复 agent 或 UI 轮询模型。

## 2. 只增加必要的业务映射

本机 DSH 完整会话流没有公开的 Asuna 绑定。只在现有 provider SSE 解码点提取可读增量，沿原有 UI 观察流传送；**不要增加另一套 token store、浏览器 provider SSE parser 或最终消息存储。**

Asuna 多出来的是：同一个用户场景下有多个来源脑和阶段，公开消息还会有平台回执。只读投影补足这些关联。映射字段由现有可信宿主产生，不让模型抄写 ID。操作前后已有的 task/request/episode 关系足以定位时直接复用；不得用 latest active、时间接近或文本相同代替关联。

同一模型 attempt 的显示 key 不变。持久记录替换相应投影，不把完整文本再次拼到片段尾部。真正的新 attempt 是另一条尝试，不偷偷抹掉原失败。不同数据源的内部 seq 不能直接当成一个全局序号排序。

### 数据可见范围

沿现有操作员授权和场景过滤；MONOLOGUE/CONSULT 在 Web 操作员过程视图可见，不因此向 QQ 开放。UI 不为点击一条日志直接赋予跨域文件访问。真实附件使用已有授权解析，不凭模型写的本机路径任意加载。

### 原生组装扩展点

固定版文档提供 `ctx.uiConversation.events.register(definition)` 和 `conversation.chat.node`，但它们需要完整 Host session 绑定；本轮在 `main` keyed slot 内组合公开基础组件，不接入这些完整 Chat 节点，也不把内部 MONOLOGUE 冒充正式角色 SPEAK。

本包示例的 `Snapshot` 只是组件边界的形状，不是要求新 API、数据库 schema 或 runtime event 协议。若已存在等价投影，直接使用它，删掉示例中的重复 helper。

## 3. 实际页面接入

目标仍是当前同一个本机 DSH 服务/URL，不额外启动 Vite 产品或一个看似一样的假服务。使用固定版正常 client plugin build 与 slot 生命周期，共享宿主 React/主题；不重复捆绑第二份 React，不从业务插件接管整个 document/createRoot。

导航与聊天改成原生组合后，原 iframe 的重复外壳不再保留为产品主路径。右检查器允许机械抽出到原生右侧槽位或保留现有隔离挂载区：保留原来的记录、筛选、选择和详情，只改变挂载位置。不得复制一份功能相同的新检查器，不重新设计它。

若完整原生窗口缺公开业务绑定，按复用地图报告具体缺口。不得因为“架构师写了原生”而去造一个伪造整个 Host 协议的服务。这条限制不授权回退自绘；相关缺口必须明确，用户决定最小替代方式。

## 4. 源码修改优先位置

公开 main 的相关位置作为导航：

- `dsh-plugin/ui/client.js`：当前 iframe 包装，需要变为真正原生 UI 插件组合。
- `dsh-plugin/ui/static/workbench.js`：当前正文覆盖、全量 DOM 重建和独立侧栏；被原生替代后删除相应死分支。
- `dsh-plugin/ui/host.js`、`src/asuna/ui.py`：沿既有只读接口绑定场景/源记录；仅在确实缺流透传时补最小观察接线。
- `src/asuna/ui_stream.py`：只读观察只传有序正文/思考片段；完整 raw provider bytes 只留既有审计，不改为另一套模型执行通道。

不要求所有文件都改。不能将当前整份 `workbench.js` 直接删掉，因为检查器和已有动作还在其中。先提取仍有调用者的部分，再删被替代的分支及专用样式；不 `git clean/reset`、不清 Mongo、不撤销已有任务。

## 5. 三个可交付小片

### P1：恢复正文，跑通实际原生消息

核对原生页与当前页；去掉 provider envelope 对真实正文的替代。用本机已有流订阅和原生内容渲染，在当前页面看到一个实际 MONOLOGUE/行动正文增长。网页折叠诊断只保留非内容元数据，完整原包由既有审计保留。其间不改模型设置或提示词。

### P2：公开基础组件的 Asuna 业务组合

使用固定版公开 Input/Button/DisclosureRow/正文/工具文本/状态组件，接 Asuna 原场景选择、筛选、输入与内部过程语义。右检查器保留。完成稳定消息原位结算和 CONSULT 的既有关联。不伪造完整 WorkspaceBrowser/Chat 所需绑定。

### P3：收尾与清理

沿原生滚动、连接和停止组件检查实际行为。保留部分失败、重连更新不重跑任务。清除本轮被替代的死 UI/样式/重复轮询订阅，不保留独立新版路由当永久第二产品。达到验收即停止，不全库“治理”。

## 6. 非空消息与活动提示

- 第一段实际可读内容/附件/工具事件出现，才产生相应业务消息标签。
- 队列本来存在则保留原生队列提示，不造尚未发生的空脑消息。
- 生成状态依据真实调用，不以“距离最后一个 token 超过 N 秒”自行判错。
- 结束即时结算，不增加 3/5/10 秒闪烁或隐藏计时器。
- 若调用真实失败且零正文，可呈现已有错误事实；不能因“没正文不显示”吞错误。

## 7. 不可混淆的结束

生成结束、工具等待、任务 RETURNED、用户取消、Web 断线、QQ 已接受是不同事实。现有状态怎么发生仍由原路径决定；本轮只显示。

当前停止服务端点不能被解释成停止当前生成。没有同义取消能力时保留明确的服务动作，不伪造一个取消按钮。不要为补齐原生菜单而建设新的取消/运行器平台。

## 8. 最小报告

只写：用户实际打开哪个现有地址；真实复用哪些原生注册视图/导出；必要 Asuna 映射在哪里；哪些旧 UI 已被删除；检查器是否保持；实际浏览器观察与剩余缺口。

禁止以“使用了 MarkdownText”替代“左/中原生化全部完成”的结论。也不以 typecheck/单元测试通过代替真实页面验收。
