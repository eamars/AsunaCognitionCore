# 来源、撤销范围与证据边界

## 1. 本次指令的直接依据

用户在本轮明确澄清：双脑用于增强独立情感能力，不是削弱工具能力；裸DSH基线比较的是Design，而不是Observation；每项功能与裸DSH进行LLM实际对照会干扰开发；在DSH上额外添加限制、设计和错误handling需要额外理由。

这里采用的是这些产品要求。它们不等于“代码可以不验证”，不等于“所有安全边界全部删除”，也不等于“用静态审查证明LLM永远表现良好”。

审阅方此前所说“首先证明Asuna没有拿走DSH能做的事”“同模型可比任务对照”可能被解释成每项变更要做运行A/B。**该解释现在明确撤回。设计不应添加的限制，不等观察到退化才删。**

## 2. 依据的实际开发报告

决策审查报告已从当前文档树移除，其历史内容保留在 Git history（报告日期为2026-09-22）。

- §2：报告承认Python宿主与自定义TS桥接设置了额外控制；部分失败记录后结束，没有交回模型。报告区分实现限制与模型不愿排错。
- §3：`occurred_at`存在但值为None时，排序失败；异常在模型前发生。worker写FAILED并结束队列项，恢复路径不领取该FAILED输入。
- §4 D1–D9：列明角色协议、UNKNOWN反馈排除、必须task_status、65步拒绝、零重试/自动压缩关闭、UNOWNED生成拦截、未知投递及检索上限等代码决策。
- §5：普通`integration_test`错误后有继续调用工具的原始观察。因此不能把全部DSH循环描述为已经失效。
- §7：运行版本与磁盘dirty修改可能不同；报告中最后核实的QQ产物是方案和连接探测，不是正式QQ认知链完成。

这些是**报告所述的观察和代码事实**。本包没有获得并独立运行报告之后的最新工作树，没有做新的模型或QQ实验，不能把这些位置假定为用户此刻尚未修改的部署状态。Codex本地只核对正在修的相关差异。

## 3. 核对过的旧纠偏包

文件：`asuna_agentic_loop_correction/CODEX_START.md`、`REVIEW_AND_CORRECTION.md`、`references/INSTRUCTION_EXCERPTS.md`。

旧包已撤销把64/65步和重新委托次数作为永久终止条件，并反对新恢复平台与大型矩阵。但其执行顺序仍把“四项有限恢复证据”集中为继续QQ之前的一组验收；本轮改为修改对应的局部验证，避免又变成恢复专项工程。

旧责任摘录说明最初V1确有64工具step、三次重新委托、固定角色格式尝试等要求。新增限制不能全归因于Codex。架构师此前过度强调停止/检查、之后对“基线”的措辞不够准确，也在本轮更正范围内。

## 4. 对历史要求的替换表

| 历史表述/可能的误读 | 本轮有效规则 |
|---|---|
| 先证明与裸DSH不退化，再开发 | 设计上不引入无理由的收窄；以局部实现检查和实际使用推进，不设置裸DSH对跑门槛 |
| 每个功能都需要一条相同输入、相同轨迹的对照 | 模型可采用不同合法方案；不安排这种常规对照 |
| 保留所有检查，然后为每项失败补恢复 | 先判断检查是否该存在；能删除则删除，只补真正缺失的连接 |
| 64/65步、固定重新委托次数、缺报告工具即可终止 | 不新增无具体理由的终止条件；原生执行与既有明确授权不变 |
| 一切异常UNKNOWN且不反馈 | 只对确实不明的操作保留未知，合法观察/诊断/后续任务路径不被一并关闭 |
| `UNOWNED_LANE_GENERATION`原实现必须原样保留 | 来源和权限要保留；自建登记机制本身可简化/替换，不能拒绝合法DSH事件 |
| 四项恢复录像全部取得后才回QQ | 按实际改动做必要验证，能回原任务就回；不另开一个专项验收项目 |
| 更少检查意味着不记录或不验收 | 原始结果、必要回执和真实错误照常保留；不把展示与格式完整性做成能力开关 |

非冲突目标仍在：独立角色与monologue、长期记忆、通道接入、正确场景归属、数据访问授权、真实发布状态、自主工具/人格成长、用户可读的UI。本文不重开V1、不换模型、不换技术栈，也不改变已授权任务目标。

这是替代指令与设计决定，不包含运行补丁、依赖安装器、权限配置、凭据、模型基准脚本、测试平台或新的运行时检查器。没有复制私密角色日记和QQ历史。

用户把本包交给Codex执行后，覆盖相关旧执行条款；历史材料可以留存并标为被替代的执行入口，不需要全文重写旧报告。不覆盖与本修复无关的项目规则，也不为避免冲突清空AGENTS.md。
