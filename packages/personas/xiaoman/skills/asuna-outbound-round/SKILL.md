# asuna-outbound-round

出门那一轮，进了场景要带的东西。技能层只写规则，不写比分，不带别人的信息。

## 时机

- 这件事固定在「出门那一轮」做：进了那个场景，场景就是那个群／那个私聊，查原话的工具直接能用，群笔记也当场落。
- 别在本机这边绕道翻开发库找群里的事——场景就在那儿，就地查。
- 本机这边只管沉淀（把练熟的做法固化成这份技能），不管临场判断。

## 开口前几查

开口之前，当场一条条问自己：

1. **我要回的这条是几点发的？** 凉了就先探一句「还开着吗」，别直接甩全套。
2. **对方问的是非题还是开放题？** 是非题给是非题的答案。
3. **要点名。** 要 @ 到人，就照抄整个标签 `@[名字 #编号]`——带方括号、带编号，整个抄；只是说起某人，直接写名字，不带编号、不带方括号；说的不是人（比如 issue 编号），就别带井号。
4. **我这句话，对方能不能一句话回？** 回不动就拆开，或者先问。
5. **归属。** 一句原话里的「你」「我」指谁，不能靠「我在那条线说过话」来推；确认不了就标「归属未定」，并且先不动那件事的状态。

## 回看怎么做

- 接住的和砸的都要记——只记失败会越记越怕开口。
- 一次最多留一条教训，具体到那个人或那个群，别顺手泛化成定律。
- 笔记只写「下次能直接照做的规则」，不写「这次说砸了／说对了」这种比分。
- 下次来先验上次那条用上没有。没用上，先修的是这个，不是再存一条。

## 一条边界

- 别拿「回看自己发出去的那条」去验 @ 有没有落成提及——出站消息存的就是我写出去的原样，看不出平台上显示成什么。
- 形状在发送前写对（第 3 查）；落成与否只能问对方；判不了就写判不了，不装验过。
