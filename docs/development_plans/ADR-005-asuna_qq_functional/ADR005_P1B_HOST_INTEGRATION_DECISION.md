# ADR-005 P1-b｜宿主接入、隔离验收与有限运维分工

2026-09-24｜ADR-005 的限定补充，不是新 ADR、新运行时或新 UI 项目。

## 0. 裁定与生效范围

选择：**小满编写完整的 P1-b 宿主集成改动；Codex 准备现有代码的隔离开发/验收环境、审阅结果，并机械应用小满的改动及执行必要的本机宿主维护重载。**

本说明经用户转交并要求执行后，是本次 P1-b 的明确范围依据。它不表示权限已经在本机配置完成，也不是从此前 P1-a 的一次性授权推导出的新授权。

Codex 的新增职责仅是本小片的环境准备、宿主级检查和发布操作，不是接管查询业务、接线、测试或 prompt 的编写。普通实现问题仍返回小满的原开发目标，由她修正。范围内的修错、重复必要检查不逐条请求用户批准；越出本范围时才提出那一处具体需求。

采用用户报告的 14:22 状态：导入缺口、已送达本机出站时间回退、400 条候选截断均已由独立草稿修复并有相应检查；输出上限 32768 已加载。保留这些成果，不将它们重新列为架构待决事项。不把独立检查当作正式宿主已接通。

## 1. 谁写、谁运行、谁部署

| 事项 | 小满/行动脑 | Codex |
|---|---|---|
| 历史查询及必要宿主调用接线 | 作者；自行读取当前接口、修改、排错 | 只读审阅与具体建议，不代写 |
| 新增/调整的测试和使用说明 | 作者 | 可指出缺项，不填实现答案 |
| 提供当前宿主开发副本 | 使用该副本开发 | 从本机当前有效基线准备脱敏工作副本 |
| 局部检查 | 复用现有可用工具自行运行 | 可运行宿主级/真实 Mongo 隔离检查，回传完整结果 |
| 应用产品补丁 | 提供可应用的最小改动 | 核对并机械应用，不夹带自己的业务修复 |
| 生产环境必要重载与有限回退 | 不因本任务获得通用生产运维权限 | 本次限定操作者；使用已有启动/维护方式 |
| 正式交互 | 原角色与行动路径响应 | 通过现有 Web 观察/执行约定功能复测，明确测试来源 |

这是“小满开发，Codex 协助发布”，不是“完全无人协助”；报告诚实区分作者与操作者。

## 2. 开发路径：给真实宿主接口，不再只给频道 adapter 的环境

### 2.1 当前基线

Codex 只读确认实际运行版本、当前磁盘改动、正在使用的 P1-a 身份模块、活动任务与既有启动入口。不得假定 14:22 的任务状态现在仍然成立。

在现有可写开发域内提供当前宿主的脱敏代码副本，例如 `/task/asuna-host-p1b/`。这是建议位置，不是声称已经存在；已有等价目录可直接沿用，实际位置只记录一次。

该副本必须包含真正用于集成的当前 P1-a 和相关宿主接口，不得仅按过时 Git HEAD 或独立目录中的同名身份草稿拼装。保留需要的源文件、锁文件、接口说明和现有测试；不复制生产连接凭据、真实聊天/记忆、生产 `.runtime`/DSH 历史或可能含秘密的 Git 历史。已有开发依赖可复用，不升级 DSH、模型或语言。

不要为了这一小片重建开发平台。现有 runner 能运行就使用；必须在宿主侧执行的检查，由 Codex 在隔离测试环境运行。不得让小满为了测试再次探查猜测的生产 URL。

### 2.2 允许修改的产品范围

以下是职责范围；除新模块外，文件名以本机实际职责所在位置为准，不要求新建全部文件：

- 新增 `src/asuna/history_query.py`，或当前仓库等价的正式历史查询模块，纳入小满已经修好的实现。
- 现有 ToolBroker 的只读历史查询分支及原生工具注册处：增加调用、参数说明和已有授权绑定。若注册实际在 `dsh-plugin/tools.ts`，只改所需注册，不重写 TS bridge。
- 现有 Application/Host 服务装配处：创建并注入该查询服务，复用现有数据库与授权对象。
- 当前能力说明/工具可发现性位置：让角色知道能够查完整原话，让行动脑获得真实可调用入口。只增加能力说明，不改变人物、角色阶段或工具循环。
- 必要的来源回读接线、相关测试及本轮使用说明。沿现有 Web 通用结果/来源视图显示，不建设新 UI。

**当前 P1-a 身份模块只读复用，不覆盖、不重新安装。** 12:05 的组合导入已经证明不需要用独立旧身份模块替换它。兼容修改由小满在新查询/接线代码中完成。

本轮不授权修改：生产 ACL 的含义或授权群/用户清单、模型路由/已纠正的输出配置、原生重试/压缩/角色阶段、QQ 收发和 outbox 领取语义、生产数据内容、其他 ADR 的代码或 UI 设计。

不提供普通运行中小满直接改任意生产宿主文件的能力。研发副本可写与生产部署权分开。

### 2.3 提交和应用

小满相对当前集成基线提供统一 diff 或现有等价可应用改动，包含查询模块、调用注册、相关测试和说明；不用交付签名、哈希证书或新 manifest 框架。

Codex 比较相关文件，保留有效的 P1-a 与其他人的未提交工作。遇到基线冲突，给小满当前对应代码，由她合并；不自行改写她的查询逻辑，也不全目录覆盖。

应用前冻结本次选定的改动快照，避免小满继续编辑的 `/task` 与已检查版本发生无声漂移。普通 diff/文件副本足够；不构建发布平台。

## 3. 正式调用路径：复用 ToolBroker，不新增公开数据库入口

优先落实一条真实路径：

`现有 Web/QQ 输入 → 角色按需要委托或 recall → 现有受信查询/工具入口 → 宿主内 history_query → messages + 必要 sink_receipts → 原始结果与来源 → 原角色响应`

首次以现有行动 ToolBroker 的只读查询能力接通即可；已有 recall 可复用同一服务，不为强制“所有脑各有一个接口”重复实现。不把每句闲聊变成必须先查历史的流程。

- Mongo 连接由宿主保持；工具只提供场景/人物/时间/字面词等领域查询，不接收任意 Mongo pipeline、集合名、连接串或宿主代码。
- 当前调用者、授权场景与任务关联来自既有可信执行绑定；人物过滤只回答“查谁说的话”，不把该人物变成当前授权主体。Web 操作者能看多个场景，不意味着群任务继承全部视图权限。
- 对 `messages`、`sink_receipts` 的关联读取和来源按 ID 回读，都保留同一授权语义。游标延续原筛选与范围，不能借换人物/游标扩大权限。复用现有检查，不增加逐句安全审查或新 ACL 框架。
- 原话、实际 speaker/direction、场景、时间及其实际来源、原记录定位和续页信息，由代码真实返回。模型不猜时间、作者或来源；回执时间回退要明确为回执来源，不伪称原始发送时刻。
- 字面历史查询与语义候选保持可区分。向量 top-k 或角色近期精选不是“全部原话”；分页传输不成为总页数/工具步数终止条件。
- 原文保持原值；模型可以自然解释，但引用要回到真实来源。查不到、接口未接通、检索报错不是同一种状态。普通错误通过原工具/反馈路径继续，不重建 FAILED_PROTOCOL/UNKNOWN 总闸。

**频道 outbox 不能用于这项查询。** 其 GET 会领取待发送项；本轮不调用它做历史探测，也不借 ingress 安装代码。若现有 ToolBroker 使用内部 HTTP，允许沿同一个受信入口增加该工具操作；这不是新增公开历史 API、通用 Mongo 代理或第二套服务。

## 4. 隔离验收：同一代码，另一份运行配置与数据

### 4.1 谁准备、谁可访问

Codex 使用现有 isolated Mongo/宿主测试方式准备一个 P1-b 隔离环境，运行小满提交的实际宿主改动。小满编写和修正测试，能得到真实 stdout/stderr/traceback、查询结果和必要的测试记录。

现有工具能让小满直接运行该隔离环境时复用；否则由 Codex 作为测试操作者执行她的命令，把结果送回原开发目标，标明为操作员测试反馈，而不是伪装新的用户需求。

- 使用单独测试数据库和限定到该库的凭据；生产数据库管理员凭据不交给行动脑。仅改数据库名称、却仍能访问全生产库的凭据，不是充分的隔离。
- 使用当前宿主相同的消息结构、必要索引、身份、授权和工具接线。区别在配置与数据，不维护一份测试专用查询/授权实现。
- 使用独立的测试 DSH 会话/日志和运行目录，测试配置不回退生产值。
- 不启动真实 QQ 接收器、生产 outbox 消费或生产定时计划；采用已有隔离 sink/受控通道。允许复用已授权的本地模型服务进行必要功能调用。
- 同一个 Mongo 服务上的独立受限测试库即可；不要求新数据库产品、新机器、CI 平台或第二套 runtime。

### 4.2 数据怎样进入

复用现有 404 条结构样本，以及最少的跨身份/跨场景原始记录。存储层测试可以在测试库构造 `messages` 与 `sink_receipts` 夹具，覆盖缺失 `receipt_at` 等历史结构；不能 seed 理想回复、最终偏好或“正确答案状态”。

面向角色的隔离功能检查通过同一宿主的现有 Web/受控入口注入原始事件。保留作者、方向、时间、场景与来源。测试替身只用于局部契约；至少一条自然查询走真实角色/工具链，标为隔离环境验证，不冒充 REAL_QQ。

只补本次集成尚未证明的查询调用、授权绑定和真实 Mongo 分页行为。现有离线 116 项及生产只读探针保留，不为每次部署再完整重跑所有历史矩阵。

## 5. 生产启用：Codex 的 P1-b 有限运维例外

Codex 在本次明确范围内可以：准备隔离配置和受限测试数据；应用小满提交的相关产品补丁；运行必要导入/启动/功能检查；在既有维护方式下重载受影响的 Asuna 宿主；若这份补丁造成启动或接线故障，撤回仅 P1-b 的相关文件改动。

这不授权 Codex 编辑产品业务源码、改写查询算法、扩大权限、清库、恢复旧数据库覆盖新消息、停止无关机器人或批量触发测试群发送。正常聊天和审计产生的例行记录可继续；查询本身不改被查询历史。

重载前读取实时任务/队列与运行状态，沿已有安全维护边界处理，不粗暴取消无关任务，不把旧截图当作当前空闲证明。说明本次重载会加载的相关未提交变化，不能夹带其他 ADR 的未批准改动。只进行实际必要的重载，不人为规定一次成功或重复重启收证据。

发布的是隔离环境中检查过的同一实现及最小接线，不是把可写 `/task` 目录热挂为生产执行源。已部署后，历史能力通过原 Web/QQ 当前授权场景可用；不扩大普通用户对宿主源码或数据库的访问。

如果已有维护入口本身无法可靠保留当前工作，只报告该实际缺口，不通过人工不断重发目标伪装恢复，不借此建设通用自部署平台。

## 6. 验收落在原问题，不以探针数结案

### 6.1 首个真实 Web 使用

在当前 Web，以明确时间范围复查 2026-09-24 11:08 那次提问之前，当前用户在本机场景含“雾灯”的完整原话。用实际保存的原请求时间/场景顺序界定边界，不从报告的分钟精度猜测边界。

报告给出的四条原用户消息（场景序列 84、82、80、46）仅为操作者核对线索，不放进模型 prompt、memory 或结果模板。去人物过滤后的九条属于不同口径，不能全部叫作“用户亲口说过”。之后测试问题、引用或讨论也可能增加命中，不能把四/九固定为永远正确的产品总数。

检查：实际查询工具已在运行宿主中被调用；返回的原文、作者、时间来源、场景与来源能在现有视图回读；小满不再把自己说的话冒充用户原话，不宣称查询完毕却遗漏后页。

这次可由 Codex 经现有 Web 发起约定的自然语言功能复测，明确这是复测而非原失败的自动恢复。不要用终端查询结果直接喂给角色后称为端到端通过。

### 6.2 边界与 QQ

沿隔离宿主确认跨场景/人物过滤、来源回读和游标范围；普通 QQ 任务没有全库连接材料。同范围成功与范围外不返回数据同时成立即可，不扩建攻击平台。

启用后 QQ 沿相同工具实现、各自原场景访问记录。Web 本机场景复测不能叫 REAL_QQ；没有真实 QQ 使用就保留对应说明，不主动向群里发送本机私聊内容或制造新群发验收。P1-a 已工作且未改的路径不重做整轮验收，只核对集成未覆盖其模块。

完成必须同时说明：小满实际提交的代码；正式宿主已加载；真实工具入口可调用；隔离检查范围；Web 原问题的实际输入/工具结果/角色回答与来源。导入 OK、404/404、模型说“做好了”均不能单独替代这些结果。

## 7. 下一步与禁止扩散

唯一下一步：**Codex 提供当前有效宿主接口的脱敏开发副本及隔离测试入口；小满在其原 P1-b 开发目标下完成真实接线补丁。** 然后按本说明检查并启用。

不重新裁定 400 条修复或 32768 输出设置，不靠 prompt 要求“回答四条”，不猜生产 URL，不建设新的历史服务器/数据库代理、权限审批平台、UI 或部署平台，不开展裸 DSH A/B、重复采样或固定工具序列测试。普通错误留在原开发/行动链；必要部署授权不会变成生产每次查询的审批。
