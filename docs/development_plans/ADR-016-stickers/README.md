# ADR-016：QQ 小黄脸与她自己的表情包架子

| 项 | 内容 |
|---|---|
| 状态 | **已实施**。owner 2026-10-06 决定 |
| 日期 | 2026-10-06 |
| 作者 | 实施者（Claude），应 owner 的要求起草 |

## 一句话决定

**程序给管子，用法归她。** QQ 自己的小黄脸能收能发；别人以表情包发来的图（静态、动态、商城表情都算，照片不算）她可以收进自己的架子，起名字、写用法，在能发表情包的会话里单独发一条。什么时候发、收哪些、怎么起名、多久清一次、给自己画一套，都是她自己的技能和笔记，不写进程序。

## 0. owner 的要求（2026-10-06）

1. 群里常发表情包，不是 emoji（这里的人不喜欢 emoji）。ADR-002/005 里早写过「表情包是她自己的成长任务」，一直没做成；旧居的她是碰巧学会的。这回要鼓励她自己把这门手艺练出来。
2. Kazusa 的 QQ 适配器认 QQ 小黄脸（只收不发，317 个 id 的名字表）；自定义表情包它从来没有。两样都要。
3. 她要能收集别人发的表情包。表情包和图片有细微差别，内部是不一样的。
4. 选择：程序部分由实施者做，她负责用法；只收表情包、不收照片；架子 60 个，轮换按她自己的喜好，放在夜间的自我整理里（owner 让实施者定）。

## 1. 平台事实（2026-10-06 查的真实流量）

- 表情包以 `image` 段到达：自定义表情包 `sub_type` 1（jpg、png、gif 都有，静态动态不由格式决定），小的具名表情包 `sub_type` 7（`[赞]`、`[666]`），照片 `sub_type` 0。商城表情也是 `image`，带 `emoji_id`、`emoji_package_id`、`key`，来自 gxh.vip.qq.com。
- 文件名是内容的 md5：同一张表情包再发一次文件名相同；但同一份字节也可能一次当照片发、一次当表情包发，所以「是不是表情包」看段，不看字节。
- 小黄脸是 `face` 段：名字在 `raw.faceText`（`/汪汪`），经典小黄脸不带名字，只能按 id 查表。0.5 之前的适配器读错了字段，所以她一直只看到 `[表情]`。
- NapCat 发送端支持 `face`（id）、带 `sub_type`/`summary` 的 `image`（客户端显示成表情包）、`mface`（商城表情的三个 id）。

## 2. 做法

- **适配器（napcat-qq 0.6.0）**：入站 `[表情:汪汪]`（`raw.faceText`，没有就查 `faces.json`：QFace（MIT）的 282 个名字加本部署见过的新名字，共 289）、`[表情包]` / `[表情包:臭]`，媒体项带 `sticker: custom|market` 和商城表情的 id。出站正文里认识的 `[表情:名字]` 原位变成 `face` 段；条目带 `sticker` 时单独发、可以不带字：`custom` 是 `image` + `sub_type: 1`，`market` 是 `mface`。领取声明 `supports=image,sticker`。
- **通道种类**：`napcat_qq` 提供 `FACES`（名字→id，同一张表）、`STICKERS = True`、`sticker_of`（适配器还没标记的老消息怎么认表情包）。核心不出现平台名字。
- **核心 `stickers.py`**：
  - 架子是 `stickers` 集合（每个人格的名字唯一、内容唯一）。收自定义表情包时把字节存一次到 `global-safe`（来源 `sticker:<消息>`：表情包是公开的梗图，不是谁的私人照片）；商城表情只存 id；她自己画的图直接引用原 artifact。
  - 能发表情包的会话里，回合带 `stickers_from_program`（名字、她写的用法、发过几次的分档词、几个、宽裕到满了）和 `faces_from_program`（这里最近有人用过的小黄脸名字），并给 `sticker` 工具（keep / drop / rename）。本机（主人私聊）列架子只供整理。
  - 她在要说的话里写 `[表情包:名字]` 就单独发一条，一回合最多一个；`[表情:名字]` 夹在话里。架子上没有的名字、两个以上、不认识的小黄脸、在发不出去的地方写，都在同一回合退回给她改。
  - 夜间沉淀每周带一次 `stickers_review_from_program`（架子到八成满时每晚都带）：收了两周没发过、或两周没再发的，最多 6 个。留不留由她，程序不替她扔。
- **上限**：`context_budget.STICKER_SHELF = 60`；回合里只列名字和用法（满架约 3–4 千字）。

## 3. 为什么这样分

- 管子（认得出、存得下、发得出、退回得清楚）是她自己造不了的：核心她改不了，适配器改了要发布。用法是技能：看谁在什么场合甩什么、自己的脸做一套反应、什么时候换掉——这些只有她在群里攒样本才学得会，写进程序就是替她决定。
- 只收表情包：照片可能是别人的私人内容，表情包是公开的梗图。
- 轮换放在夜里、一周一次：跟她整理笔记同一个节奏，不打扰白天；满了才每晚提醒。

## 4. 没做的

- 她看动画表情只看到一帧（DSH 把动图压成静图），这没改。
- 不统计「发了以后别人怎么回」，那是她自己读回的功课。
- 不替她预装任何表情包。
