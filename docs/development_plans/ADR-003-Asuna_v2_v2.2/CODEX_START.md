## 2026-09-21 入口修订（覆盖本包旧的终端指示）

按用户最新要求，正式交互和后续开发、调试呈现、交互验收统一使用 ADR-004 已有的 Web UI。`start-asuna.cmd` 启动 Web 宿主，`start-asuna-ui.cmd` 是别名。终端仅保留显式 `--debug` 的诊断/维护能力，不能作为常规客户端或 Web 故障时的回退；不得用 CLI 注入消息替代浏览器验收。Shell 启停进程和非交互诊断属于 debug 层，不是用户交互界面。

模型选择补充：角色脑/行动脑独立可配置，也可以指向同一模型。下文 Gemma/Qwen 仅描述当时部署，不是固定架构要求；“不换模型”不得解释为禁止用户在 Web 设置中切换。运行代码、UI 标签、兼容参数及 token 计数不能按职责绑定特定模型。

从 `chat.py` 提取／复用现有队列和行动回传，使 **Application 由常驻宿主管理，Web UI 作为正式客户端**。不得调用其中 debug-only 的 `chat()` / `terminal()`。提供适配器可调用的收件、取公开输出与报回执接口。保存输入早于检索／模型；不要在 NapCat 接收线程里等待模型。

3. **C：一个测试群＋两位参与者。** 验证回复链、话题关联、输入队列、真实数据隔离和新记忆；不做全平台扩展。
4. **D：接 DSH 定时器，验证一次无人发消息时的自主改进及恢复后复用。** 不用重复退出任务来模拟唤醒。

每一步的验收是 [ACCEPTANCE_DIALOGUES.md](ACCEPTANCE_DIALOGUES.md) 中对应的自然语言对话；保留真实输出和必要 traceback。不要重新搭评测平台。

## 谁写什么

**Codex 写宿主基础设施**：事件入口、可信身份与授权映射、发布回执、常驻生命周期、定时事件桥、自动记录／整理调度。**小满写平台能力**：Gemma 形成目标，Qwen 读资料、实现 NapCat 收发、调试、保存技能并根据反馈改善。不能给她一份完成的旧 adapter 让她改名后算自主成长。

复用固定 DSH 的 session、tools、skill filesystem、PromptSection/PromptContext、followup/消息队列和 compaction。当前 SDK 有缺口就保留薄 TS 桥；不要为“全原生化”重构一切。定时器扩展必须处理当前 `UNOWNED_LANE_GENERATION` 检查，不能简单关闭它。

## 不能重复的偏移

- 正常聊天仍然自然语言；只有小的控制方向需要程序可解析。ID、scope、来源、版本由程序赋值。
- Qwen 的普通编程错误回原 DSH 会话自行修；Codex只修宿主或明确适配阻塞。不逐行代写、反复改 prompt、重选 seed 求一份成功样本。
- 不先开发攻击矩阵、哈希证书、复杂话题分类器、全新 UI、技能市场或分布式系统。
- 本地固定 token 可集中配置，不因凭据治理延误主线；但 QQ 群友不是 LAN 管理员，不能读宿主配置、改权限或直连全库。
- 目标相同的长开发任务继续既有 Qwen 上下文，不每修一个 bug 新开会话。
- 先给私聊可用交付；Bonus 可以明确未完成，不能用它拖延 QQ 交付，也不能把未验证能力算通过。
