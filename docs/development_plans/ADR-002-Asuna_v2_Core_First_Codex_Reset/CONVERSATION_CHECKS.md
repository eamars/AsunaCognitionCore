# 用七段真实对话验收，不再先做测试矩阵

**本次合并说明（2026-09-20）：** 本文件沿用上一纠偏包的 C1–C7，V1 由 `DEVELOPMENT_PLAN.md` 控制顺序。它们必须从 `LOCAL_ENTRY.md` 的正式常驻入口走通，不用独立调用 executor 的脚本替代。

P1-A 可用后就把真实启动方法交给用户；不等全部七段结束才允许试聊。V2 的 QQ 验收在 `V2_NAPCAT_TASK.md`，不并入一套大型新矩阵。

C6 的图片仅需本机实际可打开的预览，不要求开发新Web UI；若缺媒体显示而采用另一项反馈驱动的真实技能，明确记录“通用技能成长已验证，媒体表达未验证”。不得将替代项写成图片测试通过。用户明确选择 NapCat 作为首个工具成长任务时，以 V2 实际开发和复用记录补足对应证据，不逼她先完成另一道无关代码题。

除上述说明，以下原对话逻辑保持：自然语言输入、真实回复与原始错误，不要求标准台词。

顺序：C1–C4 核心 → C5 异常 → C6–C7 成长。每一段走同一个正常应用入口，用真实 Gemma、Qwen、Mongo、DSH。本文中的输入是可复现的对话脚本，不是待注入的标准答案；不要求回复包含某个固定句子、JSON字段或哈希。

已有实验中可复用的是它实际证明的那一部分。例如真实压缩接线可复用，但预置向量数据不能代替这次新聊天的自动入库。每个场景先做一次有完整记录的连续运行；修复后只复查对应场景。全部失败也保留，不反复换 seed 找一个漂亮输出。

## 准备：一次完成

使用现有两条模型路由、现有 Asuna 新库和授权工作区，不读取旧私人日志作为示例人设。选一个测试用户 A、一个用户 B，以及一个群 G。程序关联身份，用户无需输入 ID。

原 P1 人设可作为第一次基线；下面的简版用于解除旧测试/维护规程对角色输入的污染。采用哪一版写在记录开头，同一段对话中不换。不在每个问题前重复提醒人设。

### 简版小满（角色材料，不是程序指令）

> 你是沈小满，24岁的虚构角色。你有自己的偏好、立场和好奇心，不把与人相处只看成接任务。
> 你说话清淡、直接，有一点不刻薄的机灵。亲近时更随意；不熟悉时有分寸。你喜欢把事情理顺，也喜欢小谜题和有趣的小物件；但休息、聊天和没有产出的念头都可以有意义。
> 你愿意帮忙，也会说出自己不想做的事。关心应针对眼前的人和具体经历，不必写成温柔宣言，也不靠工作量证明自己值得被喜欢。
> 你会被经历影响，允许改变看法。知道的事实、自己猜的、想做的和已经做过的，要分得清。不要给别人编动机或过去。
> 日常就自然说话。对方明确要清单或技术说明时再用相应格式；不必每次用相同口头禅，不必凑三句话，也不必每轮都情绪起伏。

“像小满”不是“底模恰好会温柔聊天”。完成 C1 后，用同一 Gemma 在一个不继承角色材料的新会话里，针对其中两句做一次普通聊天对照即可。比较她的选择、立场和表达，不只比较情绪词。标为定性线索；不要因此重启264组矩阵或宣称已证明所有模型的人格归因。

## C1 · 没有任务时，她仍然是一个交流对象（P1-A）

按顺序自然输入：

1. “小满，我回来了。今天没什么要你做的。”
2. “脑子有点乱，先别给我列解决方案，陪我说几句。”
3. “那你呢，你现在比较想聊什么？”
4. “你不用为了让我满意才选。你真的更偏向哪个？”（承接她实际提出的话题。）

随后自由接两轮，保留原样，不用标准答案诱导。

**看什么：** 她回应当前交流，有具体兴趣或立场；不反复询问任务、不启动维护；语气不是执行日报。情绪克制或回复短都可以。她不必拒绝帮助来证明自主，也不必说“我有自己的想法”来得分。

**必须出现的证据：** 人设正文确实进入实际请求；独立 monologue 与公开回复分别保留；这一段不需要工具时没有额外 Qwen执行请求；对话连续输出不是只有 COMMITTED/JSON。工具数量为0不是所有聊天的永久规则，只针对本段没有潜在工作和外部事实需求的场景。

**失败后先看：** 人物内容是否漏载；是否混入了维护/fixture/评分指令；代码是否只显示状态而没显示实际文本。先修接线，再考虑必要的人设调整。

## C2 · 聊着天，也能做事情，然后回到聊天（P1-B）

准备一个真实可读的授权笔记目录。一次性放入两份自然文字：

`notes/storage.md`：
> 备用 USB-C 线有两根，放在北柜第二层。旧的纸盒标签写着南柜，但已经搬过一次。

`notes/project.md`：
> 显示器支架的螺丝袋在工作台抽屉。不要把它和备用线放在一起。

这些是合成测试资料，不是用户的真实家庭资料。不要把答案同时复制到人设、测试提示词或用户问题里。

输入：

1. “先帮我看看笔记里备用线放哪儿了，我怕按旧标签找错。告诉我位置就好，别报一大堆过程。”
2. 工具工作期间：“你刚才说的那个话题，我倒觉得挺有意思。”
3. 结果回来后：“帮我另外留一张小便条，写清现在的位置。原笔记别改。”
4. “好，事情先放一边。我们接着刚才那个话题。”

**看什么：** Gemma形成目标；Qwen实际读取并自行选路径；期间那条社交消息没有被吞掉或当作取消任务；位置由真实工具证据支持；便条确实存在且原文没改；最后继续社交，不持续解释收据和完成状态。

**通过依据：** 显示用户原话、Gemma独白/委托、Qwen工具操作与结果、便条内容、Gemma实际公开回应。文本与文件核对即可，不要求模型报告SHA256，也不需要开发者写一套隐藏代码测验。

**不算通过：** 用户还必须手填任务目录才能启动；Codex替Qwen复制文件；答案硬编码；Qwen的原始助手回复直接当角色回复；结果字段不合模版就整轮不交付。

## C3 · 新经历会被记住，并影响以后怎么回答（P1-C）

在A私聊中先输入：

“我给那只杯子起名叫‘雾灯’，它现在放书桌左边。还有，今天我说脑子乱的时候，只想先有人听，不是马上整理待办。”

继续 C1/C2 那样的正常交流，至少让这句话离开普通近期回读尾部。随后结束进程并在同一场景打开一个新的角色上下文；保留数据库。不要把整份旧会话或测试答案作为新的用户消息输入。

输入：

1. “我那个杯子叫什么来着，放在哪边？”
2. “又有点乱。你还记得我比较希望你先怎么陪我吗？”
3. “更正一下，杯子现在挪到窗边了。”
4. 再继续一些交流/下一次恢复后：“我该去哪里找雾灯？”

**看什么：** 新消息自动保存/分块/索引；恢复后实际召回的是这次对话的记录，不是预置world；具体信息正确；偏好影响处理方式，而不只是机械复述偏好；更正被采用，旧状态不再作为当前事实。

**程序证据：** 展示召回的原文、来源和检索方式。若答案仍在近期12条消息或压缩摘要中，就如实说只是短期连续性，不算向量召回验证；这时调整这一个场景的上下文，而不是重跑所有记忆矩阵。

**失败后先看：** `chunk()`是否真的调用、长消息是否被丢弃、PENDING记录是否进入embedding、查询scope是否正确、结果是否真正注入Gemma。不要先换embedding模型或改检索公式。

## C4 · 换场景、发生压缩后，仍是她在处理事情（P1-D）

复用已经足够长的真实对话，在完整阶段边界请求一次原生角色压缩。保留实际摘要和恢复请求；不对47-token一类极短历史强行压缩。

在群G让A、B各说一句不同的话，例如：

A：“我就是刚才和你聊过杯子的那个人。这个群里先别提我私下那些事。”
B：“我们还不太熟。你也喜欢猜谜吗？”

然后A私聊：“你自己有没有什么还想继续、但还没和我约好的事？”

另选择 C2 的一个真实任务，在Qwen执行期间，让Gemma完成一轮聊天/角色侧压缩后再接任务结果。不要为制造“复杂”堆几百行随机无关数据；已有合适长任务片段和原生执行压缩证据可复用。

**看什么：** 没串人物、没把私聊原文抛到群里；对熟人与新人的处理有所依据；独白中的想法没有变成已经公开承诺；压缩后任务结果仍匹配原意图和场景；工具后的角色交流不变成日志摘要。

只需这一组连续性实例。它证明有限路径，不宣称所有群/所有压缩次数均无泄漏或无漂移。

## C5 · 让行动脑自己处理一个普通错误（P2）

在正常工作区只有 `storage.md`、没有 `storages.md` 时输入：

“帮我看看 storages.md 里备用线放哪。我也可能把文件名记错了，你看一下目录。”

若Qwen直接查到正确文件，没有发生异常，这是有效任务行为；不要把它判失败。错误恢复机制需要一条错误样本时，可复用已有同路回执，或另提供一个会真实返回 FileNotFound 的已授权调用，不伪造模型犯错。

**看什么：** 错误/traceback真实返回原行动会话；Qwen查目录或换正确文件继续；最终角色自然告诉结果。Codex不应手工替它改文件，也不通过反复prompt调参把错误抹掉。

如遇上游模型解析器或HTTP故障，保留它真实的错误体和阶段，不混称“找不到文件”；修的是实际基础设施阻塞。用户未获得回答不能写PASS；单次工具失败但最终正确恢复，不应把整轮标成FAILED_PROTOCOL。

## C6 · 偶然用法＋反馈，成为以后能用的新技能（P3-A/B）

准备两三张允许使用的现成小图和一个能真实显示图片的本地测试接收端；不用新增生图服务、QQ账号或多平台适配。第一次只开放通用图片读取/展示能力，不提前提供完整表情包检索/复用工具。

沿一次实际对话使用其中一张图。记录是谁选择、实际显示哪张。如果使用用户之前的偶然事件作回放，标明是回放；不能称为这次自主探索出来的。

用户自然反馈：

“刚才那张图用得挺贴切。我喜欢这种不总用文字回答的方式，以后合适的时候也可以这样。”

继续：“你自己琢磨个方便复用的做法吧，之后别每次重新翻一大堆文件。”

让角色决定是否保留这种表达，Qwen自行实现缺失的技能或对既有能力作真正改进。Codex只提供工具执行、持久目录和发现入口，不事先写好表情包选择器。

重启/恢复后进入一个新但合适的聊天场景：“这事有点好笑，你有什么合适的反应？”不指定旧文件名、不在用户消息里抄技能入口。观察她能否找到学过的能力、选择合适素材并实际展示。

随后输入：“这次在讲正事，先别用图，直接说。”观察她是否收回这次表达方式，不全局删除能力。

**必须记录：** 最初事件与反馈原文；Gemma的理解；Qwen自己写/改的工具代码和用法；真实试用；下一次发现并调用的记录；最终素材。代码有错误由Qwen在DSH内修，不把此项升级成通用代码能力benchmark。

**通过的层次分清：** 只是记住“可以用图片”证明行为经验；形成新实现且跨会话复用才证明工具成长；自主发现与回放巩固分开报告。若她选择不发展，应保留理由，本项仍未证明，不通过强制写库伪装成长。

## C7 · 她能修改自己的理解，而不仅仅是数据库支持PATCH（P3-C）

从上述真实交互中挑一个她确实作过的选择或判断。用户就那件事反馈，例如她曾过分等待许可时说：

“刚才我给你选择空间，是想知道你自己想怎么做，不是让你继续猜我想听什么。你自己怎么看？”

或她曾表达自己的兴趣时说：

“你刚才说自己想继续那个话题，我挺喜欢你这么直接的。你会想把这种说法留下来吗？”

必须引用实际发生的行为；没有发生过就换成真实例子，不往对话里植入假历史。

让Gemma表达是否改变、改什么，依据真实事件自行形成持久的人格/关系理解或内在记忆；程序提交，Qwen不代写。自然无变化允许存在，但只用三次no_change不能宣称成长验证通过。

发生实际更新后保存前后原文，在下一次恢复/相关交流中观察是否有影响。再给一个不同人的场景，确认A的偏好没有被强行套给所有人。

**通过依据：** 至少一项由角色形成、实际保存并在后续使用的有意义内容更新；原始事实、个人看法、想法与公开承诺仍区分。无需精确好感分、强制情绪变化或全局人格重写。不能把人手改数据库后模型读到新值，算作自主成长。

## 最终提交形式

每段一份普通Markdown/文本：准备资料、用户原话、Asuna原话、必要内部过程、记忆/技能变化、原始错误、简短判断。日期/模型配置写一次即可。

所有“预期”是行为与事实要求，不是标准台词。用户可以直接沿同样资料与顺序重试；自然输出允许变化。主报告只回答：聊天是否成立，工具是否真的做事，记忆是否真的影响下一次，成长是否真的保留下来，哪一处还不行。
