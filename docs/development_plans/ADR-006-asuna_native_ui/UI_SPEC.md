# ADR-006｜确定的页面行为

## 1. 唯一布局

```text
┌──────────────────┬────────────────────────────────────┬──────────────────┐
│ DSH 原生导航      │ DSH 原生聊天 / 同一消息流          │ 现有会话检查器    │
│                  │                                    │                  │
│ 实际会话/场景列表 │ 用户消息                            │ 原类型筛选        │
│ 原生选中与搜索    │ 角色脑 · MONOLOGUE   [实际正文增长] │ 原记录列表        │
│                  │ 行动脑 · 工具调用   [原生工具行]   │ 原详情和来源      │
│ 不复制第二套左栏  │ 角色脑 · CONSULT    [内部回答]     │ 不重新设计        │
│ 不自动暴露全部    │ Asuna · SPEAK       [实际回复增长] │                  │
│ 内部 task session│                                    │                  │
│                  │ DSH 现有输入/队列/发送交互          │                  │
└──────────────────┴────────────────────────────────────┴──────────────────┘
```

这是消息位置示意，不是新面板或要求每轮出现四个阶段。没发生的脑、工具、咨询不显示空占位。三栏相对关系和右侧宽度沿现有可用布局；左/中采用本地原生尺寸、主题和间距，不重做设计 token，不添加头像、连线、彩色状态卡或计数大盘。

用户后来明确允许左栏重新设计；以此版为准，不执行旧“左栏一字不动”的限制。

## 2. 左栏

- 使用固定版 `ui-sidebar` 的导航壳及 `ui-workspace` 已注册的浏览区域与列表行为。采用原生 flat/grouped 机制已有的适用部分，不另写 `renderConversations()`。
- 面向用户的一项是一个现有 Asuna 会话/场景。角色会话、行动会话只是其底层来源，不因为两个脑就额外显示两项对话。
- 标题来自现有会话/平台资料，缺标题显示已知 ID；不加 LLM 命名调用。不为视觉分类创建虚假磁盘 workspace 或持久 DSH session。
- 点击只选择观察场景，不启动模型、不恢复某个已停止目标、不自动向 QQ 发言。
- 新上下文沿既有 Asuna `/new` 语义，不把原生按钮直接连接到一个绕过 Asuna 的新 agent。消息输入仍走 Asuna 原宿主。
- 搜索、重命名、归档、fork 等仅在当前后端已有同义且可用操作时接上。不得为模仿原生菜单补一整套业务。不可用操作用原生的禁用/省略机制；原生没有此能力则记录具体组合缺口，不用 DOM 隐藏作弊。
- 普通历史条目没有“新”的动画。新消息产生的未读／状态沿原生机制；不能把每次 state 轮询当新消息。
- QQ 只读场景与现有 owner 群指令保持区别。切换侧栏不改变谁在说话、输入来自哪条通道或授权范围。

## 3. 消息正文与诊断分层

**正文优先。** 当前 `phase.output` 中的真实 `payload.content` / 对应 DSH Assistant 文本是 MONOLOGUE 正文来源。禁止把它替换为“原始 provider response”或总结。

| 实际对象 | 默认呈现 | 完成后的呈现 |
|---|---|---|
| 用户输入 | 原生用户消息；只按既有接收回执标排队 | 同一条，不因流开始重建 |
| MONOLOGUE | 原生过程区内一个角色消息；实际文本逐步增长 | 原文仍可展开；不是 native reasoning 的别名 |
| DECIDE | 仅在实际有输出时有过程条目；结构内容用原生代码/详情 | 不把结构控制字段当公开回复 |
| 行动脑输出 | 同一过程区的行动消息；原顺序正文和实际工具节点 | 非角色公开台词，不创建另一个用户对话 |
| CONSULT | 原咨询工具下的内部角色回复，关联原任务与原场景 | 不另建目标、不发 QQ；同一结果不复制两张卡 |
| SPEAK | 当前原生 Assistant 消息正文流式增长；清楚表示尚在生成 | 本地持久输出/平台回执到来原位结算；不追加副本 |
| 工具调用/结果 | 原生 tool 行与对应工具结果 renderer | 原调用 ID 关联；失败原文可展开 |
| provider 诊断 | 每条对应消息的“诊断 → provider 元数据”，默认关闭 | 网页 JSON 仅含非内容元数据；完整原包留在既有审计，不在网页重复正文/思考 |
| 图片/附件 | 使用当前已可用的 DSH 图片/附件呈现 | 不在 ADR-006 开发读图、下载或媒体生成能力 |

`reasoning_content` 与 `content` 是 provider 数据字段；MONOLOGUE 是 Asuna 的角色阶段。不得混为一谈。正文使用 DSH 的文本/附件内容块而不是网络 JSON；若实际返回 native reasoning，可在同一消息过程中按源顺序呈现，并保留可核对的原字段名，**不另造常驻 Thinking 面板**。如果只能确认 DSH block type，标真实 block type，不能反推一个未取得的 provider 字段。

本版明确替代早前“以 provider 原包为主要实时内容”的解释。网页流只传一次有序的可读片段；完整原字段和字节由既有审计保留，网页诊断只显示请求/模型/用量/结束原因等非内容元数据。默认界面必须让人读到小满真的生成了什么，生成中的思考可直接展开。

原生 `Compact` 可折叠已完成过程，但不能将每次 Gemma 的一个 DSH 子回合结束误当整个 Asuna 交流完成。使用已知 Asuna 交互边界映射显示过程，不改真实运行 turn。无最终回复的失败/停止记录不被成功折叠吞掉。用户手动展开的内容、文本选择与键盘焦点，不被新 token 强制折回。

## 4. “只有新消息时才显示”怎样执行

- 请求开始但还无可读片段：不新造空脑气泡、不出现两张固定脑状态卡。已有输入/排队状态仍可见。
- 第一个真实可读片段、图片引用或工具事件到达：为这个实际对象建立一个位置，显示“来源脑 · 实际阶段/消息类型”。
- 后续片段：更新同一位置。既不逐 token 弹 toast，也不把片段数显示成消息数。
- 生成期间：仅该条消息的原生 ongoing 状态存在。一个流完成、另一个开始，按各自实际记录显示，不用全局“正在思考”猜是谁。
- 正常结束：ongoing 立即变成静态结束信息；**无额外保持 N 秒、无消息淡出计时器**。正文不消失。过程折叠按原生已完成交互规则。
- 历史打开/重连取得旧记录：正常历史，不重播 token、不自动标“新”，不强行展开。
- 错误/被停止：保留部分正文和真实结束原因。停止的是该次生成不等于任务已取消；`max-tokens` 不涂成完成。
- 无新消息且没有实际活动：没有活动控件和空进度区域。历史、输入框与现有检查器正常保留。
- 读者在底部时使用原生跟随；读者上滚后保持位置，使用原生“回到底部”，不新增“你有 N 条双脑消息”的通知系统。

标签是消息归属，不是短暂飘过的弹窗；历史展开后仍应知道来自哪个脑、哪个阶段。

## 5. 一条消息如何从流式变成历史

以已有源会话、operation/request/message/attempt 关联建立显示 key；片段、阶段回执和正式 public message 通过真实关联指向同一位置。不能按内容相等、时间戳相近或“最近一个 Assistant”合并。

- 流中 `SPEAK` 是操作者可见的生成草稿，不写成已经向 QQ 说过。
- 生成结束后，正文在原位保留；平台状态可从待发送变为接受/失败/未知。不要为了等平台回执隐藏已生成正文。
- 若随后有实际修订/另一尝试，保留与前次的关系，不把两次文字拼成一个“完整答案”。
- 正常持久结算替换对应显示投影，不是再加一次最终文本。
- 重连补回未见内容只能更新观察，不能投递新的模型输入、工具或计划。

## 6. 断线、停止、错误

仅用现有原生连接控件显示页面连接中断；恢复同步完成后控件回到无提示状态，不常驻“连接正常”的大卡片。断线期间保留已见正文，明确后台状态未同步，不自动视为后台失败。

已有 `/asuna/api/stop` 经目前公开源码会停止整个宿主。**不能将它连接为 DSH composer 的“停止当前生成”。** 原生停止动作必须接现有同义取消入口；没有这种入口就禁用对应操作并列出缺口，保留现有明确命名的服务停止功能。ADR-006 不借此增加取消系统。

UI 重连、未知内容类型、原包读取失败不能改变模型、任务或发布状态。未知 block 可使用原生 fallback/详情保留，不编造正文。渲染不安全 HTML、泄漏凭据、跨场景显示不属于“忠实显示”；沿既有授权与原生安全渲染处理。
