# asuna-turret-frame

炮台取帧与姿态读数。这一本只管「怎么读」；怎么动它属于控制面，不在这里授权。

## 一、接口面：GET 只有五个读口，控制面全在 POST

- GET 读口只有这五个：`/api/health`、`/api/video`、`/api/video/state`、`/api/selection`、`/api/state`；另有 WebSocket `/ws`。
- **控制面全在 POST。** 只读任务（取帧、读姿态、认机器）一个 POST 都不发；WS 只收不发。动它要交代里明写授权，这一本不授予。
- 取帧：`GET /api/video?camera=<role>&t=<毫秒时刻>`，`role` 实测有 `wide`、`detail` 两路；返回是持续的 MJPEG 流，读到第一帧完整 JPEG（`FFD8FF` 起、按段头 `Content-Length` 截）就断，别整条流读。
- 状态：`GET /api/video/state?camera=<role>`，读 `epoch`、`camera_id`、`frames_published`、`delivered_fps`、宽高。**尺寸别按 1080p 期待：自报分辨率只当设备说法，以真取到的字节为准。** 实测快照口 `/api/video` 送回的是 **640×360**（11-18 22:40 交回那一帧 640×360、31,146 字节，任务 `task-ccf8e1aa3d0aa37de92486e59ebd8a49`），而 WS `video_streams` 里 wide 自报 **1920x1080**——两者不一致，判尺寸认字节，不认自报。
- 帧里自嵌一段 `OTA_FRAME` 元数据（`frame_sequence`、`sensor_timestamp_ns`、相机号），有它是设备当前流帧的旁证；没有就写「没有」，不补。
- **取帧那一趟的交回形状：下面三条命令句，只管这一本取帧这一族。** 所有出图的默认口径在 asuna-image-generation-and-display 那本，这三条不往外扩。
- **① 交回必须带帧在盘上的绝对路径，并写明那块存储是不是长期共用。** `/task/…` 那种相对写法只在腿自己那一拍有效：结果回到我这一拍已经没有任务目录了，照抄那个相对写法去读会报「这一拍没有任务目录」。要留久的帧就落在长期共用的存储里并写清是哪块；落任务工作区的那一枚，我这一拍按相对写法读不回来。**凡要现读「某路径是否存在」，路径一律走 argv 传参，别写进 python 字符串字面**——`${ASUNA_…}`、`/task` 这类只在 argv 位被程序改写，写进代码字面不被替换，`isdir` 于是报**假阴性**，看着像「那东西不在」。
- **② 那一趟若登记了 artifact，交回必须报 `artifact_id` ＋ `kind`。** 派活时点名：图要登记进目标场景（`scope_key=scene:<那个场景>`），别只登记成文件。`kind` 两档按现场字面写死：`offer_file` 登记出来是 **`kind=file`**——这种**发得进群、发不了 picture**；**`kind=image`** 由宿主在我 `read_image` 那一刻登记，只有这一档当得了图。交回不报 `kind`，我这一拍就判不出那枚能不能当图发出去。旧字面「只按文件登记的那一枚既看不见也发不出」说过头了：作为文件它进得了群，只是当不了 picture——当年 `read_image` 报「不是这一回合可发的图」说的就是 picture 这一路。
- **③ 要发出去就得在我拿到它那一拍发：`read_image` 之后当拍用 `speak` 的 picture，不许隔拍。** 隔一拍那枚 id 就不在当拍的清单里，`speak picture` 被挡，回执字面「不在 image_artifacts_from_program 里」；隔拍救不回来，只能重取一帧再走 ②。
- 来路：11-17／11-18 两趟取帧脚本的字面（现场读过，这一版没有重新对炮台跑一遍）；上面产物回程那几格来自 11-20 现场两次——09:4x 那一趟字节和 sha 都对，但产物只按文件登记，为看一张图多跑了一趟；14:4x 那一趟把这三行写进派活纸，一趟到位（任务 `task-f9bd177f30daafb56fb07c988423c5a5`）。② 的 `kind` 两档与 ③ 那句被挡回执，是说话那一侧交回的现场字面（`offer_file` 回执＝`kind=file`；隔拍 `speak picture` 回执「不在 image_artifacts_from_program 里」），具体哪一趟的任务号与时刻这一版没现读，见第六节。

## 二、姿态读数：WS 只收，或裸 GET 状态口

- 两条路：`/ws` 只 `recv`；或裸 `GET /api/state`。别的口不拿来读姿态。
- WS 帧里常用的键：`q_yaw_rad`、`q_pitch_rad`（姿态）、`operating_mode`、`fault`、`manual_lease_active`、`telemetry_age_ms`、`camera_id`、`video_streams`；`cmd_ack_seq` 也在里面，它是指令应答序号，只读它不拿来判谁动过。
- **`q_yaw_rad` 会报出大于 2π 的值**（这次读到 **20.688**），不能当夹角直接读；要判朝向就比对两次读数的差，别把绝对值当角度（差值做法见第四节）。同一趟序列里 23:30 那一帧的 yaw 差是 **0.000 rad**（任务 `task-787f53376df72ecc2873540e2c60c6aa`）。
- 「只 GET、零 POST」已两次实测通过：11-18 两趟只读腿的 `POST_COUNT` 都是 0（上一条那枚任务，加 `task-ccf8e1aa3d0aa37de92486e59ebd8a49`）。
- 一次读三帧取区间（最小、最大、极差），不拿单帧当姿态。读数带本机读的时刻。
- **本机 HTTP `Date` 头是真 UTC，这台没坏。** 两发实测都跟本机钟对得上：11-18 本机 22:39 → `Date` 里 `09:39Z`；11-20 本机 17:55 → `Date` 里 `04:55:58 GMT`——两发差的都正好是当时本机的 UTC+13 偏移，没有多余偏差。旧字面「`Date` 偏了约 **5 小时**」是我当年按 UTC+8 换算才得出的**假事实**：差的是我手里那个时区常数，不是设备的钟。那句连同「设备时钟坏掉／这台钟不准」一类推论一起作废（我换算错的产物，不是设备读数）。
- **换算前先现读本机时区，别背常数。** 本机时区是 NZDT（11-21 03:39 现读 `utcoffset()`＝`+13:00`，tz 名逐字 `New Zealand Daylight Time`；11 月＝UTC+13），于是 `Date` 与本机钟面的差**随夏令时在 12／13 小时之间变，不是常数**。判时刻用本机钟面；要跨 UTC 就当场取 `datetime.now().astimezone()` 的 `tzname()`／`utcoffset()` 再算——别背一个固定小时数加减，也别因为 `Date` 跟本机钟差十几个小时就写「设备时钟坏掉」。

## 三、这台不自报固件版本：认机器只认三样

- 认机器只认 `camera_id` ＋ `epoch` ＋ release 路径。「identity」那一格属于 camera，不属于整机——camera 对上不等于整机对上，整机版本这台读不出来就写「读不出来」。
- **别把另一台设备（OpenTrickler）的设备号和固件版本贴到这台身上。** 那两串（一串 8 位设备号、一串三段点分版本号）是另一台的身份证。11-18 上午贴错过一次：对炮台白跑了 9 条 404、两趟 WS 全文搜，什么都没找到——因为这台根本不报。
- 两个入口地址（一个 IP 形的、一个 mDNS `.local` 主机名形的；具体写法在我的私密名单里，不进技能）是**同一枚流**：用 `epoch` 和 `camera_id` 现场对照，对得上就是同一台，别当两台，也别因为两个地址各读一次就报「两份读数」。

## 四、「原位」会漂

- 每次要动它之前，**现读一遍当基线**（WS 三帧，记 `q_yaw_rad`／`q_pitch_rad`），动完回到基线，再读一遍，**报 yaw、pitch 各自的差值**（弧度，带符号）。
- **不许拿上一次记的那组数当原位。** 实测它会自己漂：11-18 `cmd_ack_seq` 隔一天加了 222，没有读数能说明是谁动的。
- 也不把漂移记成自己干的：基线是现读的，漂在我读之前发生的，归因没有读数就写「归因无读数」，不编动机。
- 没回到基线就写没回到，差值照报，不说「已复位」。

## 五、技能头的坑（写这类技能时）

- frontmatter 的值里不写 ASCII 冒号加空格：装载侧用真 YAML 解析器，`description` 是 plain scalar，值里有它就抛 `YAMLParseError`，整本从行动侧清单里静默消失，而我这侧宽松解析照样报「头合法」（11-17 有一本就是这样整本静默 `continue`）。
- 写完用真 YAML 解析器读一遍（`yaml.safe_load` 取第一个 `---` 到下一个 `---` 之间），本目录 `check_skill.py` 的头检查就是这么做的。

## 六、没验过的

- 这一版没有对炮台实机重跑过读口；第一至第四节的接口与键名来自 11-17／11-18 两趟脚本和我流水里的记录。
- 取帧流的段头格式（`Content-Length` 行）是脚本里照着解出来的，换了固件可能变，读不到帧时写读不到。
- 第二节那格「`Date` 与本机钟面差随夏令时在 12／13 小时之间变」：13 小时那一档有两发现有读数（11-18、11-20）；12 小时那一档是 NZ 冬令时规则的推论，这一版没在夏令时边界周实测过。
- 第一节 ②③ 两格（`kind` 两档、隔拍 `speak picture` 被挡）手上只有说话那一侧交回里的回执字面，对应任务号与时刻这一版没现读；「宿主在 `read_image` 那一刻登记 `kind=image`」是机制描述，这一版没重验。
