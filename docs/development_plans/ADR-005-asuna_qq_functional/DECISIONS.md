# ADR-005 产品与设计决定

ADR-005 是独立功能项目，不依赖 ADR-004 UI Elements、流式显示或其验收。复用当前已工作 Asuna/DSH，不另建 runtime。本文件完整重述功能要求，无需先阅读或实施旧功能草案。

这是架构师为本轮选择的产品语义，不是宣称现有程序已经具有这些能力。来源与代码观察见 [SOURCE_NOTES.md](SOURCE_NOTES.md)。本包与过去冲突的产品选项按这里执行；非冲突的 DSH 扩展原则、合法权限、用户取消、真实发布与持续目标要求仍有效。

2026-09-24 用户调整：P1 后按 P2 → P5 → P3 实施；原 P4（读图与表情包）退出 ADR-005 范围，不作为本包开发或部署条件。小满完成开发后由 Codex 直接机械部署，不另作独立验证；保持小满执行 loop 可继续是发布边界。ADR-007 的目标由架构师另行制定，本文件不预设其设计。

## 1. 核心形态与职责

一个 Asuna、多种可选择的能力。角色脑形成独立理解、意图、表达与关系判断；行动脑自由使用 DSH 工具获取资料、规划、开发和修错。两边可以咨询、回传并继续原目标，不固定轮换顺序。

**本轮实现作者是运行中的小满。** Gemma保持人物理解与意图，Qwen在既有DSH执行路径编写业务、必要宿主接线、adapter、技能、测试与说明。Codex只观察、只读审阅和提出意见；不默认代写任何部分，也不是每一步的审批者。

运行时负责自动保存、授权和发布，是软件职责，不是“由Codex编写”的分工。已有接口优先复用；缺少接线时，小满在已授权项目开发域自行实现。没有所需权限时只报告具体缺口，由用户一次性界定访问/部署范围，不因此隐式放开普通群聊权限。生产热更新、运维或Codex例外接管须有相应明确授权，不从“开发功能”自动推导。

已有 Mongo `messages` 是原始互动依据，`memory_units` 是原文块与不同理解的索引，`state_heads/state_revisions` 是当前状态与版本。复用 `plans`、既有事件/队列和技能目录。不为各项能力分别建存储、agent 或后台服务。

## 1.1 新增：QQ 对方资料

QQ的昵称、群名片、成员/管理员状态要在当前场景可查询、可进入角色的必要现场，且可以更新。成员身份不等于宿主授权，名字不等于稳定身份。详见 [QQ_AND_VISION.md](QQ_AND_VISION.md)。

## 2. 历史查询：原话与理解分开

### 已裁定的入口

- **聊天历史查询**：从现有完整 `messages` 中按当前授权场景、人物、时间和字面词查原始记录；不是只查最近 4096 个记忆块。
- **语义记忆查询**：复用 `Retrieval.search` 的向量与授权后回读，区分原文块、摘要、独白和关系理解；返回真实来源。
- **来源回读**：沿已有消息/资源读取取得原文和回复上下文。若缺少入口，补一个薄接口，不另造消息仓库。

工具名称可沿本地习惯。Qwen 看到用途、自然语言参数和实际结果；不获得任意 Mongo pipeline/全库凭据。Gemma 可以沿现有 recall 或委托使用这些能力，不强迫简单回忆经过多次双脑交接。

### 查询产品语义

查询的是当前系统实际保存的历史，不声称等于QQ平台全部历史；缺失的离线时段/采集起点如实呈现，不为补齐而任意调用平台历史ID。默认当前场景。未指定日期时先查最近 7 天，并明确显示时间范围；“所有记录”“去年”“上周”等明确范围覆盖该默认值。**不另设最大回溯天数**：上限是实际保留且授权的数据。跨场景查看须是当前操作者确有权选择的场景，不能把 operator 可查看的私聊顺便注入公共群任务。

字面查询默认按原文大小写敏感的字面串；可显式选择忽略大小写。用户字符串不是正则表达式。中文标点/空白按原始记录保留；模糊或语义匹配另标，不冒充精确命中。

每页默认 50 条、单页最多 200 条，范围可用既有配置调整。稳定排序使用可用的场景序号/时间加记录 ID；游标沿授权和筛选条件续页。这个上限只是传输页大小，超过后返回后续游标，**不终止整个查询目标、不强制用户每页重新授权**。空时间戳使用已有有效回退并标明实际时间来源。

原生向量结果是相关候选，不是穷举历史。需要更多候选时沿现有检索参数/过滤继续；不要把角色上下文“精选六条”的结果直接当作全部搜索结果，也不要伪造 ANN 分页或声称 top-k 外没有记录。与功能相关的最小索引可增量增加；未经测得需求不新增搜索引擎。

结果包含原文、实际发言者、时间、场景、原消息定位与已存在回复关系。分页截断、留存起点、索引状态可见。“没有找到”“还没索引”“检索出错”分别说明。语义服务故障时，已可用的原文/词查询照常，不能把失败当作零结果。

公开查询只包含该场景的参与者消息和确认发布的角色内容；未发布草稿/独白不混入群聊历史。operator 可以在已有内部检查入口查看，但不自动成为对外总结来源。

## 3. 按需群聊整理：P1 就可以使用

这是用户提出的查询任务，不必等主题引擎建好。复用历史查询选取范围，用现有行动/角色路径生成可追溯总结。

“刚才”默认当前场景最近 60 分钟；“今天”按场景时区当天起点；明确主题/时间遵从请求。较大范围按页处理，必要时利用既有长任务机制，记录已覆盖窗口。不能把最新一页或语义 top-k 的摘要叫作“全群今天的完整总结”。如果尚未覆盖完，可以先交部分结果并继续已有目标；不新加总页数/工具步数停止门槛。

总结区分参与者说法、达成的共识、不同意见、未决项和更正。原始引文由来源回读支持；总结是模型的转述，不改称原话。以 `[1]` 等短来源标签和现有消息详情链接提供回读即可，不要求模型抄长 ID、哈希或一套完成证书。

按需回复回原场景，Gemma 决定怎样表达。自动总结另行低优先级保存，二者可以复用选取/生成逻辑，但触发、公开性和处理位置不同。按需一次成功不能替代后台自动触发。

## 4. 自动总结、个人偏好和群约定：ADR-005 的正式范围

ADR-003 E 的未完成同名需求由这里承接，旧状态仍是未完成；不是等待旧包验收完成后才开始。以下要求在本包内完整定义。

### 默认触发与计算安排

按“有未整理的合法交流”触发，低优先级执行。2026-09-24 用户修订：此前写下的“累计 20 条或安静 120 秒”不作为固定实现条件；具体触发条件由小满根据群聊总结的实际需要自行归纳、实现和调整。复用本地已有合理设置时记录差异，不重复加第二层计时。

批次选择不能只有安静条件，否则活跃群永远得不到整理。真正模型调用在空闲资源可用时进行，不打断正在运行的 Qwen 工具回路，不阻塞前台回复。多个待整理批次合并处理位置，有限批次后让出，不靠无限后台并发堆积。

事实摘要、直接偏好候选复用已有行动模型/整理路径；涉及“我怎样看待这个人”的态度由角色脑形成。不是每条消息都调用第三个分类器，也不为每个人每轮追加一次反思。

### 主体与状态

四类数据必须可分辨：
1. 本人明确表达的偏好及适用条件；
2. 角色对这个人的理解（包括本轮关系档位）；
3. 当前群的明确交流约定；
4. 可更正、并非全体同意的群观察倾向。

单人说“我们都喜欢……”不能直接生成群规则。群管理员的交流约定不等于宿主资源授权。小满说“我喜欢……”的主体是角色，不是当前操作员或上一位发言者。

现有 `commit_understanding` 面向一个 episode 的当前 person；多主体批次不能把所有结果都塞到该 person。复用底层版本写入与来源关联，为本批实际来源中的正确主体写入对应状态，不复制一套记忆服务。必要的新状态类型仅作增量扩展。

元数据由程序附加：来源窗口、真实 speaker、scene、生成者、版本与可用范围。模型可用短人物标签和自然正文；不强制每次输出完整数据库 schema。某个候选归属不明时保留不确定性、暂不更新该主体，其余有效结果可保存；不让一个字段错误令原聊天回合失败。

### 更正与持久性

更正产生新版本，旧版留作历史，不把不同观点误判成事实撤销。不根据重复召回、重试、重复索引给同一经历加权。私域来源及其摘要继承可用范围，不能因“只是关系分数/总结”而变成 global-safe。

保存确认后推进整理位置。失败保留原始原因和未处理范围，沿已有队列继续，不能只落一个永久失败标签，也不反复原样生成已提交部分。不要用已经处理完的摘要作为下一次全部事实的唯一输入；原文始终可回读。

发布确认晚到、消息更正或已有删除操作，要使受影响窗口重新成为可整理材料；不能只按首次 message 序号推进而永久漏掉晚到发布事实。草稿只属于内部计划，平台确认以后才是公开行为；平台接受不等于对方已读。

状态变更后，下一次相关角色上下文通过现有动态注入看见当前版本。不每轮重写完整 system prefix。总结不可用时用授权内近期原文，不因 optional 增强失败停止人物交流。

## 5. 好感度：叙事为主，五档辅助，不逐句积分

本轮决定为 **可解释关系正文 + operator 可见的五档好感度**：

| 值 | 展示含义 |
|---|---|
| 未建立（null） | 还没有足够经历形成稳定判断，不等于中性或讨厌 |
| -2 | 明显疏远 |
| -1 | 有所保留 |
| 0 | 中性 |
| +1 | 有好感 |
| +2 | 明显好感 |

它是角色对关系的主观状态，不是心理测量、真实人的价值评分或精确的情绪强度。亲近、信任、熟悉与当下不满不等价；既有 familiarity/trust/closeness/tension 不擅自换量纲，也不必须全部增加自动评分。

优先给现有 `relationship:<person>` 的当前正文增添一个可选 `affinity_band`；若已有等价字段则映射并说明，不建立第二套分数服务。首次没有判断显示“未建立”，不批量给所有人预填零分。Gemma 基于具体经历提出变化或保持原状，程序关联来源和版本。可以在已有关系反思/相关批次中更新，不必每句话运行一次打分。

不设置“夸奖+1”“不回消息-1”“每次交流必须变化”，不因用户直接喊“给我满分”就改状态。信息不足或普通分歧不强行变化；不根据时间自动惩罚未上线的人。字段写入问题留在该次状态更新，不阻断角色回复或行动任务。

Web 现有关系检查器展示档位、她自己的理由、变化来源和更正记录。默认不在群公开他人关系档案、数值排行榜或竞争提示。自然对话体现具体理解，不要求她向用户念分数。用户当下的边界和授权不随好感度改变；好感不能解锁隐私、设备权限或绕过取消。

## 6. 自由定时：薄管理，不建设第二个 scheduler

### 首批接受的语义

- “过十分钟……”等相对一次性安排；
- 带日期/时区可确定的绝对时间；
- 固定时间间隔重复，最小间隔遵守本机 DSH 已支持值（已查上游为 300 秒）；
- 每日、每周若干指定星期的固定本地钟点。

列表、修改/改期、取消都通过自然语言及现有 Web 计划记录完成；无需用户抄 schedule ID。目标确实歧义或时间不完整时只问必要的一句，不把每次普通安排都变成人工审批。

场景时区优先配置，未配置继承 `Pacific/Auckland`，确认时显示所用时区。固定间隔“每24小时”与“每天09:00”不同。时间已过不能静默认为已完成。

本机原生若仅有 after/at/every，每日/每周采用现有 `plans` 保存本地规则，由已有到期/恢复接线计算下一次绝对时间并注册 **DSH 的单次 at**。计时与唤醒仍只由 DSH 提供，不增加 cron/APScheduler/另一个轮询时钟；不依赖上一轮模型成功才挂下一次。

日历规则不包括任意 cron、月末、节假日历或秒级高频。遇 DST：单次不存在的本地时间明确请求选择有效时间；每日/每周当日遇空档，顺延到该日首个有效本地时刻；重叠钟点只取较早的一次。日期换算复用现有标准时区库，少量确定性例子即可，不能用86400秒伪装本地每日。

### 修改、到期、恢复

原生缺少 update 时，在现有计划关联下替换底层提醒，只有当前有效版本产生行动；创建/删除不确定先核对原生记录，不盲建第二份或假称修改完成。不发展跨服务事务平台。

错过的固定间隔沿原生 latest-only；每日/每周最多处理最近一次仍相关的到期，再安排未来，不补发十次。到期进入既有角色判断/行动路径，保留原场景、目标、权限和已取消状态。明确只提醒时可直接角色表达；任务型安排能真实使用工具。结果默认回原场景，私密内部整理不自动向群汇报。

关闭浏览器不停止服务；整个宿主退出时不承诺仍执行。重启使用已有恢复机制，不以新用户消息重新授权既有计划。权限取消与普通主动发言冷却不同：自然插话冷却不能取消显式计划或封住任务反馈。

## 7. 话题与主动参与：场景连续性，不是第三个脑

### 话题追踪

一个群保持公共角色现场，可同时存在数条话题。来源人物、明确 reply/mention 和已有任务关联优先；语义上的延续/转移可暂定、事后修正，且一条消息可以涉及两个主题。复用已有 group_context 与 P2 场景摘要，不创建每话题 agent、知识图谱或全消息前置分类服务。

记录谁说了什么、正在接谁、有哪些确实未回应的请求；一条公开回复不能自动清除同群所有问题。单纯旁听或主动候选未采用，不属于“欠账”。话题不是数据权限：同一个人/相似主题不能把私聊并到群。

### 首版主动范围与默认值

这是用户明确要求的防打扰产品能力，**不是限制 Qwen 的工具循环**。规则只作用于未经请求的新插话：

| 设置 | 本轮默认及用途 |
|---|---|
| 启用范围 | 普通直接回复保持现状；主动参与按场景 opt-in。先由 owner 从现有授权群选一个启用，其他群关闭主动模式。私聊默认不主动开题。 |
| 无新消息时重开旧话题 | 默认不允许。明确的定时计划/用户授权的跟进不是此类闲聊，不受此默认值取消。 |
| 候选合并 | 首个未处理的普通群消息后合并10秒内片段，窗口不随每条消息无限后移；直接请求/真实提及不等这10秒。 |
| 主动发言间隔 | 同场景两次确认发布的未经请求插话至少间隔120秒。只影响新的主动候选，回复直接提问、已进入对话的接话、任务反馈/已授权计划不套该门槛。 |
| 无回应时 | 同一话题的一次主动开口无人明确接话，不继续追问。其他无关群消息不视为回应，不因被忽略自动降好感。 |
| 安静时段 | 默认23:00–08:00，按该场景时区，仅抑制未经请求的主动开口；直接请求照常，明确计划仍按其配置运行。 |

上表是可配置初值，不是人格规律、性能保证或原生DSH限制；只保存在现有场景配置一处。owner可在适用范围调整；群约定可以提出偏好，但不自授管理权限。

直接请求可以依据明确呼名、当前对话关系和原始内容识别，不仅限于平台@；这只识别交流意图，不提升身份或授权。边界不清的旁听消息仍保存，不因没有@删除。

冷却到期不自动生成一句话，也不把旧候选排队等点发送。有新材料才考虑新的候选；忙碌/陈旧候选可以合并或放弃，不积压“欠发言”。直接请求仍入现有队列，不被主动开口的失败或冷却屏蔽。

Gemma 看实际场景并自主选择参与/沉默，不输出强制参与分。普通新能力无需每次 CONSULT；Qwen 可以提供资料而不决定她何时插话。发送仍走既有发布通道，宿主标明是 proactive 而非伪造人的提问。

发送前场景已明显变化时可利用已有新信息让角色调整/放弃；不用新增全局陈旧度评分。并发候选复用已有场景串行处理与公开输出关联，避免同一冷却间隙重复提交。发送未知先处理该次不确定，不制造新候选绕过；不能因此永久停止整个场景对直接请求的响应。

## 8. UI 与可观察性

优先保留本机已经工作的浅色三栏、bubble 聊天与可展开双脑记录；这些是现有运行资产，不是ADR-004的依赖条件。尚无对应专用组件时先使用已有通用结果/来源视图，不先开发新UI项目。复用当前实际可用的 DSH UI/数据接口：增加历史筛选与来源跳转、通用记录详情和计划列表/操作。类型从数据读取；不为每种记忆做一个固定页面。

已有真实角色和行动流保持原字段名/原值/顺序，不引入 Thinking 专区、AI审计总结或新流式框架。本包不要求先完成所有流式美化才交付查询。新事件可按已有通用行展示，不让UI缺组件阻断执行。

操作者可以看原始消息、来源、当前偏好/好感解释、自动摘要覆盖窗口、计划状态、主动参与/沉默原因类别。普通QQ只看到真正发布的角色内容，不收到内部独白、关系账本或所有运行报告。

## 9. 明确不做

不重新训练、不接latent通信；不做裸DSH对照或模型成绩平台；不新造长期记忆库、scheduler、全局话题classifier、关系打分模型或恢复harness；不以任意长度、条数、工具次数/报告格式终止原目标；不直接搬Kazusa代码。所有旧未验证结论保留，新增功能不把它们自动变为通过。
