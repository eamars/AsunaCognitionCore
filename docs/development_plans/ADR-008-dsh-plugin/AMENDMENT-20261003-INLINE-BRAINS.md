# ADR-008 修订案：主会话内连续展示双脑记录

批准日期：2026-10-03。用户明确同意主会话展示方案，并要求先写入修订案后继续开发。

本修订替代 UI_SPEC 第 2 节“角色主会话 + 打开行动会话”作为默认交互的决定；只批准下述记录组织方式，其余原生 UI 和插件边界继续适用。文档记录设计决定，完成情况以当前实现与运行证据为准。

## 批准的可见行为

操作者留在原角色主会话，在同一个主记录流中查看角色脑与行动脑的实际产出。使用现有紫色“角色脑”、蓝色“行动脑”标签，不增加第二套描述标签。无需打开行动子会话才能阅读任务执行过程。

角色判断、行动执行、工具调用与结果、咨询及后续执行按实际交互关系连续呈现。长任务允许多次交替，不限定一次角色到行动的固定顺序。来源归属依据持久关联和实际产出，不根据正文或模型名字猜测。原生思考与工具折叠行为继续适用，展开可读完整记录。

只读观察内部执行内容不改变发布行为；仍由既有发布路径决定哪些角色表达发送至 QQ。QQ 主会话继续只读，本地保持一个原生输入区。

## 实现边界

两脑保留独立模型路由、上下文、真实原生 session 与持久记录。展示组合引用原始记录，不向角色上下文复制行动历史，不建立第二份聊天消息数据库、token 缓冲、分页器或消息渲染器。

优先通过 DSH 公开绑定、Conversation/Chat 扩展位置与原生节点渲染实现。当前版本没有现成的跨会话主时间线，必须先以隔离原生 profile、合成推理和实际 Web 页面验证组合接点。若需要 DSH 层接点，变更必须为支持该组合的最小可审阅扩展，不能修改 node_modules、全局替换 assistant-step/main.conversation 或复制整套 Chat。

本批准不包含新侧栏、第二个输入区、独立滚动的嵌入聊天窗口或额外常驻导航。原生子会话历史可保留用于诊断，但不再承担默认阅读入口。

## 验收

在真实原生 Web 页面证明同一主记录流出现两脑实际记录、原生工具调用与结果，以及咨询后继续执行的顺序；确认标签来源、完整展开、流式更新、刷新/重连、历史读取和失败记录。普通非 Asuna 会话沿原生行为。观察或重载页面不触发任务重放或发布。

UI 连续展示与执行协调分别验收。角色主动介入正在执行的行动任务、跨任务延续等已发现执行缺口仍需各自运行证据，不因本修订被视为已实现。
