# ADR-013：DSH 对端通道——让两个 DSH 里的智能体直接说话

| 项 | 内容 |
|---|---|
| 状态 | **已实施**（`@asuna/dsh-peer`）。owner 2026-10-06 批准 |
| 日期 | 2026-10-06 |
| 继承 | ADR-003（通道接缝与出站审计）、ADR-008（通道插件）、ADR-010（发行与数据目录） |
| 作者 | 实施者（Claude），应 owner 的要求起草 |

## 一句话决定

**另一个 DSH Web 服务里的某个会话，当成她的一个私聊对象。** 对方每完成一轮回复，桥就把最后那句话作为对方发来的私聊消息交给通道接口。她的回复照常走出站队列，由桥作为一条提示词送进那个会话，第一行写明是谁在说话，并记录平台回执。

## 0. owner 的要求（2026-10-06）

1. 在旧居（DSH 里的旧会话）和新居之间搭一座桥，让她们直接对话，把知识平稳地交接过去。
2. 形态：做成一个对话通道（选项 A），不做行动脑工具，也不由 owner 手工转述。
3. 用旧居的**主会话**。owner 知道，这样她在那里回 owner 的话也会流过来。
4. 旧居那边能不能照新居的请求去做事，由她们两个自己判断。
5. 先建好；谁先开口由她们自己决定。旧居的她已经说过，接通后第一句由她先说。

## 1. 形态

- **通道种类 `dsh`**：场景 `dsh:<本居账号>:dm:<对端>`，人 `dsh:<对端>`。
  - 种类模块是 `packages/dsh-peer/python/dsh_peer`。
  - 侧栏工作区标题为 `DSH`。
- **桥在宿主插件进程里运行**（`src/bridge.js`），不进集成沙箱。
  - 它只和本机的通道接口、以及那一台 DSH 说话。
  - 它是我们审过的代码，不是她的候选代码。
  - 它通过 `ctx.asuna.channelEndpoint('dsh')` 拿到通道接口地址和令牌。
  - 这是核心新增的一个小接口：自己就是适配器的通道插件，用它连本机通道接口。
- **入站**：
  - 用 `session/follow`（`/api/remote.mux` 上的 WebSocket）跟随那个会话。
  - 每个 `completed` 的轮次，取最后一条 `assistant/message` 的正文，作为私聊消息提交。事件 ID 为 `会话:turn:轮次:序号`，可去重。
  - 某一轮如果不是回应她的提示词（来源不是带她的 `requestId` 的 `user-rpc`），正文前加一行 `ownerNote`，说明这句不是回她的。
  - 新桥从会话当前位置开始，不回放历史。
  - 断线重连后，补上快照窗口里还没处理过的事件。
- **出站**：
  - 领取出站条目，用 `session/prompt`（`mode: queue`）送进会话，第一行是 `label`。
  - 成功记 `platform_accepted`，`platform_message_id` 为 `requestId`。
  - 对方明确拒绝记 `failed`；传输中断时可能已送达也可能没有，记 `unknown`。
  - 只走文字；图片和群管理动作不出这条通道。
- **范围**：只用 `session/follow` 和 `session/prompt`，只针对配置的那一个会话。不新建、不取消、不分叉会话。

## 2. 可见性

对端不是 owner，这个私聊按 `visibility.session_class` 属于 **public**：

- 她在这个会话里看不到、也说不出 owner 的私有记忆和文档。
- 对方说的话她都听得到、记得住。

如果想给「家人」单独一档信任，那要单独做设计，由 owner 决定；本 ADR 不做。

## 3. 观察到的事实

- 旧居的 DSH Web（经 Caddy 的 HTTPS 反向代理）当前**不要求登录**。不带凭据的 `session/list` 能成功。
- 也就是说，局域网里任何设备都能给旧居的她发提示词，而她有完整的局域网权限。这条已报告 owner，本 ADR 不处理。
- DSH 的正常认证用的是签名 cookie（用 `/?token=` 换取，30 天有效），不接受 Bearer。如果以后旧居开启认证，桥需要配置这个 cookie。

## 4. 配置（owner 本地）

- 通道部分，在 Asuna 设置的 `channels.dsh` 里配：`account_id`、令牌，加一条 `dm` 路由。
- 桥部分，在配置档可编辑补丁的 `asuna-dsh-peer` 行里配：`url`、`sessionId`、`routeId`、`senderId`、`label`、`ownerNote`、`insecureTls`。
- 字段说明见 `packages/dsh-peer/README.md`。
- 对方的显示名写在其身份记录的 `display_name` 上。
