# ADR-003.1 纠偏执行记录

2026-09-22。依据 `development_plans/ADR-003.1-Asuna_v2_correction/CODEX_START.md` 和 `DESIGN_AND_CURRENT_FIX.md`。原决策审查报告保留，不覆写历史结论。

## 本次删除与缩小的限制

- 删除桥接层 65 步拒绝，以及同一工具调用链中的 64 次 broker 门槛和 `task_status` 后禁用工具的门槛。计数仅保留为记录。
- 删除 provider `maxRetries: 0`、compaction `auto: false` 与 `maxOverflowRetries: 0` 覆盖。本机固定安装版 sdk-minimal 已包含 `llm-retry`，原生 compaction 支持 pressure 与 overflow 恢复；未升级依赖，没有增加无限重试。
- `task_status` 变成兼容性可选标注。行动侧自然语言与真实工具记录直接回传；`RETURNED` 表示回合返回，不自动证明目标完成。正常返回不会自动发起下一轮。
- 行动扩展层逃逸异常保存原始诊断并回传为未完成，不再统统变成屏蔽反馈的 UNKNOWN。任务 UNKNOWN 不再禁止角色解释情况；具体发送的 UNKNOWN 与不重复领取规则不变。
- 已创建的合法行动不再因无关角色阶段失败而在宿主恢复时被取消；删除委托深度上限。角色的独白、结构化意图和公开表达仍保留。
- 原生 continuation 不能仅因没有 Asuna `active` operation 而拒绝。生成钩子只处理显式压缩记账；可信入口仍核对桥接 bearer、Python 绑定的场景与 epoch，工具执行仍逐次核对主体、任务版本、授权和取消。不把另一个内部字典换成新的生成资格门槛。

## 实际缺失的接线

1. 可选 RAG 出错时，使用已经通过授权的直接历史、必要角色状态和原输入，向角色附带脱敏 traceback；不再次调用坏检索器来报告错误。权限拒绝仍单独传播。技能目录预览失败同样作为诊断，不阻断已有目标。
2. 修复显式 `occurred_at=None` 的排序错误；词法候选限定为授权范围内最近 4096 项，向量路径仍覆盖授权历史，不再因范围变长抛 `LEXICAL_SCOPE_LIMIT`。候选不完整时停用依赖完整范围指纹的缓存；未删除历史记录。
3. 恢复旧版检索失败且未创建 episode 的输入时保留原 ID、正文和错误；不恢复所有历史失败输入。原输入不是新的 QQ 入站或新的用户目标。
4. 角色可通过既有任务关联选择 `continue_task_id`；宿主确认相同主体、场景、policy epoch 和集成授权，且此前任务未取消/失效，再续用原行动会话绑定。行动结果后的继续也复用这一路径。它不授予新的资源，也不扩大已授权目标。
5. 为本次重载中断的角色生成，沿既有 `advance` 入口续接尚未完成阶段，保留原场景与诊断；新生成有可追溯的 resume 序号，已完成的工具与公开输出不重放。不是通过换 ID 规避已删除的步数门槛。
6. 桥接 HTTP 错误正文和原生非正常结束原因进入诊断，不再仅留下无正文的状态异常。实际投递不明仍禁止盲目重发原操作；其他核实/继续通过原会话进行。
7. 行动脑实际自测发现宿主 outbox 超时。根因是 ToolBroker 等待 integration 子进程时仍持有数据库副作用锁，而子进程回调 outbox 又需要该锁。现在在锁内完成授权和 INTENT 记录后，释放该锁再等待 integration；运行器自身的并发锁仍保留。已接受的调用可以记录真实结果，但不能修改或复活已取消的任务，后续调用仍校验取消状态。这是宿主锁范围修复，不修改行动脑的 adapter。
8. Web 补充宿主诊断时，角色尝试续接仍在运行的行动，触发本轮新增的 `TASK_CONTINUATION_NOT_AUTHORIZED`。原行动没有停止，但该条角色消息被错误地终止。现在重复接管仍被拒绝，具体原因作为 control_result 进入角色公开解释，不再抛出到整条消息；局部检查确认原行动保持 RUNNING、没有重复任务。这个检查只保护同一会话的执行所有权，不审批其内部工具或排错。
9. 为加载 outbox 修复进行一次必要的本机宿主维护重载。旧 shutdown 路径将任务记为 CANCELLED/host_stop，因此增加窄范围续接：同主体、场景、epoch、集成授权的新明确续接请求，可以复用 host_stop 记录的原会话；旧任务保持已撤销的执行权限，不改为 RUNNING。用户取消及 STALE 仍拒绝，自动任务反馈不能使用该例外。取消前保存原 execution_binding，避免版本增加后指向另一个会话。隔离检查分别覆盖宿主停机可续接与用户取消不可续接；初次检查发现绑定用了递增后版本，已修正。

以上接线分别用于防止可选增强阻断输入、续接已有任务和传递真实错误。未建立第二套恢复状态机、数据库或修复 agent，未增加宿主自修改权限。角色协议歧义仍由角色自己的格式修正路径处理；没有将行动侧改为固定角色阶段。

## 必要验证与现场错误

检查使用既有 isolated Mongo/WSL 工具契约测试，认知输出为明确的测试替身，不冒充真实模型恢复或 QQ 收发：

- 无 `task_status` 的自然语言能够回传，并附加实际读取/写入记录。
- 可选状态标注之后、旧工具次数上限之外仍能调用授权工具；原文只读保护与取消后的拒绝保持有效。
- 延续任务保存原行动会话绑定；扩展层异常的原始原因可进入角色回传。
- 失败检索不丢原输入，不产生重复接收记录；诊断可在没有 RAG 的上下文中呈现。
- 含空时间戳且超过旧词法上限的授权记忆可以继续有界检索，原记录保留。
- 用真实 ChannelServer HTTP、实际数据库锁和隔离数据库重现 integration 回调 outbox 的超时，再以同一检查确认修复。该检查只有子进程替换为直接 HTTP 调用，不作为真实平台证据；另确认调用期间取消任务不会被结果记录复活，取消后的调用被拒绝。

测试过程中修正了两个测试夹具问题：旧通道路由夹具缺少实际配置必需的 sender_id；批量记忆夹具缺少 Mongo schema_version。没有通过放宽生产授权或数据库校验使测试通过。

真实 Web 重载发生过一次实施失误：初版兼容恢复条件过宽，选中了较早的运行器验收失败输入。随后停止了该次宿主恢复，将条件收窄。读取真实结果确认，该旧输入进入角色回合后被识别为已完成的重复验收，未创建新的行动任务。这个额外角色回合确实发生，不能声称完全没有误恢复。

停止宿主时，当前 QQ 输入的角色生成也被中断，留下 `DSH_BRIDGE: Error: NO_DURABLE_SESSION_LISTENER` 记录。该错误发生在关停期间，不作为模型能力结论。通过已有持久输入状态和审计记录，仅将原 QQ 输入明确续接；没有删掉其旧 traceback 或要求用户重发。

未进行裸 DSH A/B、重复采样、轨迹匹配、成功率矩阵或专门的 66 步模型试验。没有把局部检查解释为所有错误路径已被真实触发并恢复。
