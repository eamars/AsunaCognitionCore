# ADR-011：两个脑都用原生工具调用

状态：**已实施**（M0–M5，现网验收 2026-10-05）。owner 两轮共七问已答。取代 ADR-010 的 `PROPOSAL-DECISION-DISPLAY.md`。之后的修订：工具清单按对话固定（ADR-038），`message_action`/`stop_action`/`answer_action` 合为 `task`、`note_idea` 等合为 `ideas`（ADR-055），`pin_memory` 已删（ADR-038），行动脑上下文见 ADR-053。§ 编号沿用全文，代码注释引用它们。

## 一句话决定

角色脑是一个普通的 DSH 回合：先用 `think` 写下心里话（显式、留档、可回看），再用少量 Asuna 工具行动，最后一段正文就是她说出口的话。两个脑之间用工具传话，来往在主对话里显示为「协作线程」，行动脑自己的思考和工具折叠在消息之间。文本加 JSON 的阶段协议（MONOLOGUE → DECIDE → WRITE/SELF/REFLECT → SPEAK）整体退役，不留兼容层。

## 0. owner 的要求（2026-10-05）

1. 不再把 JSON 当正文显示；两个脑的输出要清楚。
2. 用工具调用在两个脑之间传话；放弃「角色脑不调用工具」这个迁就弱模型的前提。行动脑可以当作子代理。
3. 两个脑的工具不重叠、边界清楚。
4. 保持她的自主，给自我改进留空间：足够的指南、最少的边界、保证系统能启动的底线。
5. 心里话要显式、可导出、可审计、可存档（原生 CoT 做不到；与 Kazusa 的显式 CoT 同一思路），并且简短。
6. 两个脑的配合要在主对话里流畅可见，不藏进子代理面板；展示这种配合是项目目标之一。
7. 改动只能有一条发布路径，便于管理和审计。
8. 界面语言跟随 DSH 配置，只有人格和角色的内容用人格的语言。
9. 改进的灵感可以来自任何地方，但只能在她的自我改进回合里整理和决定，不能是别人的直接改动请求。

## 2. 设计原则

1. 角色脑管「她是谁、和谁的关系、想什么说什么」（心智动作：想、回想、感受、记下、打算、交代、说或不说）；行动脑管「世界和能力」（文件、沙箱、网页、历史检索、图片、适配器、改代码）。一种动作只属于一个脑（例外：`read_image` 两个脑共用，见 §5.3）。
2. 工具就是动词，正文就是说话：不带工具调用的最后一步正文就是对对方说的话；不说话就以 `stay_silent` 结束。
3. 心里话显式留档，每回合先 `think`（§3.2）。
4. 两个脑的配合摆在明面上（§7）。
5. 能复用 DSH 的就复用：运行层用 DSH 子代理机制，界面复用 DSH 的折叠、工具行、侧栏子会话。新做的只有协作线程和角色脑工具的轻量行。
6. 能不能用某个工具由程序决定（现行做法：清单按对话固定，回合规则以拒绝说明何时可用，ADR-038）。
7. 错误回给她本人：参数或权限不对就作为工具结果说明原因和可选项，她在同一回合自己改。
8. 界面语言跟随 DSH（插件自带 locale，至少 zh-CN、en）；她说的话、心里话、文档、人格名用人格的语言。给模型看的提示和工具说明不算界面。
9. 一类改动只有一条路径：代码、技能、包、提示只走 `development_publish`；她的身份数据只走角色脑的写工具。两条都留可审计记录。
10. 不变的约束：核心不含人格名；状态以解释过的文字交给模型、模型用类别词写回；会话类别由程序算；只有说出口的话会发布；个人数据留本地；每个可选动作各自成败。

## 3. 角色脑的回合

- **3.1** 一条入站消息 = 一个原生回合：上下文作为第一条输入 → 必须先 `think` → 按需调用工具（worker 校验执行）→ 最后正文走现有发布路径（拆条、节奏、附图不变）。Episode：PREPARED → TURN → COMMITTED / SILENT / WAITING_TASK / FAILED_*。
- **3.2 心里话 `think`**：她自己的口吻，两三句要点，上限 300 字，超了退回让她精简；详细推演留在原生思考里。DSH 没有 `tool_choice`，由 worker 兜底：`think` 之前的其他工具被拒，回合结尾检查本回合写过 think。存成 `memory_units`（kind `monologue`），可被 `recall` 检索，写进审计；本场景最近几段心里话带进下一回合。原生 reasoning 原文只进审计证据，不进记忆。
- **3.3 幂等**：用原生 `tool_call_id` 作效果键，崩溃重放不重复生效。
- **3.4 预算**：`recall` 每回合最多 3 次；工具调用总数有上限，超了告诉她「这回合先到这里」。
- **3.5 最后正文的检查**：不能空、不能是 JSON、不能明显在说工具或程序。不合格就在同一回合追加一句提示（界面上画成「退回重写」一行），最多一次；仍不合格记 `FAILED_PROTOCOL`。`stay_silent` 结束的回合不检查。

## 4. 两个脑之间怎么传话

每个任务是她会话下的子会话（`asuna-worker` provider，`asuna-action` 预设）。DSH 的可续接子代理会沿用父会话预设、装不进行动脑的授权工具，所以沿用单次子会话建法（同一执行绑定续用同一个原生会话），留言由插件投递：在跑时 `agent.inject` 下一步送达，否则在同一会话再开一轮。Mongo 里的任务行、栅栏、授权、修订语义都保留。

| 来往 | 工具 |
|---|---|
| 交一件新事 | 角色脑 `delegate {title, brief}`：她的交代就是行动脑的第一条消息 |
| 补充、改目标、续接 | 角色脑 `task` op message |
| 叫停 | 角色脑 `task` op stop |
| 行动脑问她（同步等回答） | 行动脑 `ask_character`；她在内部回合 `think` 后用 `task` op answer 回答，不发布 |
| 行动脑报进展（不等） | 行动脑 `report_progress` |
| 行动脑做完 | 回合结束，最后一条消息就是报告；她开一回合读报告、决定说什么 |

委托是异步的（她可以继续聊天）；提问是同步的。工具名用中性动词，不用 DSH 的 `subagent`/`send_message`。DSH 自带的完成卡片不单独出现。摘要是后台工作，不挂成子代理。

## 5. 工具与边界

- **5.1 角色脑**：`think`、`recall`、`delegate`、`task`、`stay_silent`、`attach_image`、`write_document`、`update_self`、`understand_person`、`set_policy`、`feel`、`plan`、`group_action`、`promote_memory`、`ideas` 等心智动作。不拿文件、沙箱、网页、原始历史、开发和集成工具；要做就交给行动脑。
- **5.2 行动脑**：网页、工作区（`sandbox_run` 不挂载 `/skills`）、`query_authorized_history`、`read_image`、`ask_character`/`report_progress`、`ideas` op note、`skill`、适配器的 `integration_test/start/stop/status`（`integration_dev` 删除；`integration_start` 和重启后的恢复只运行已发布的适配器）、`development_*`。`persona_job_run` 从行动脑运行一律 dry run：身份数据只由角色脑写。行动脑系统提示调用 `suppressRuntimeContext`。
- **5.3 去掉的重叠**：运行中的人格文档只由 `write_document` 写（行动脑改种子只影响新装，她用 `adopt_seed` 接收）；技能和适配器代码只走开发工具。读图（owner 修订）：两个脑共用同一个 `read_image` 与同一套围栏、落盘、回执；她的回合里只在她的路由收图且有可拉的图时出现。

## 6. 自我改进

- **6.1 两层，各归一个脑，各一条路径**：身份与状态（文档、Character Core / Current Self、参数、心情、对人的理解）由角色脑写，每次留带理由的修订，门槛 owner_private。能力（人格包、核心代码与提示、通道包）由行动脑用 `development_*` 编辑候选、`development_publish` 生效，有回执、探针和改动清单。开发工具只随 owner 私聊里的委托和她自我改进回合的委托（及其结果回合）给出，不需 owner 逐次批准（现行范围见 `grants.development_granted`）。行动脑不直接写她的身份数据，只在报告里建议。
- **6.2 想法来源可以很广，只在自我改进回合里决定**：任何场景两个脑都能把想法记进她的想法本（`ideas`），用她自己的话，程序附来源引用；非 owner 场景只能写不能读。非 owner 场景永远拿不到开发工具：别人说「你把代码改成……」，她最多记一条想法。自我改进回合里她读未处理的想法，写下采纳、暂缓或放弃及理由，决定做的再 `delegate`。写进代码、技能、文档的东西不能带别人的个人数据。
- **6.3 指南**：与人格无关的核心技能 `asuna-self-improvement` 随 cognition-core 发布。
- **6.4 启动底线**（沿用 ADR-007、ADR-008）：稳定入口 `start-asuna.cmd` → `asuna-launch.mjs` 不导入 Python；受保护路径（含 `persona.js`、`channel.js`、`settings.js`）；核心组成锁；启动探针在子进程里真正 import 插件入口并校验 `persona-model.json`、`cordis.patch.yml`，人格包和通道包同样；需要重启的发布不在运行中自动切换；新选择连续起不来就改回上一个 ACTIVE 选择（只回退选择，不回退源码）。

## 7. owner 会看到什么

- **7.1 协作线程**：她第一次 `delegate` 后，主对话里出现「她 ⇄ 行动脑 · {title}」线程，有状态和耗时，可在侧栏打开完整过程（DSH 原生子会话侧栏）。紫色气泡是她，蓝色是行动脑；两条消息之间行动脑的工作折叠成一行，展开是 DSH 原生记录。线程记在她会话的 `asuna/collab` 事件里，行动脑的工作只记原生会话的序号区间，不存副本。每个动作都要有可见的界面变化（owner）：对话往前走后到来的条目在那里另起一块；工作中显示「正在做 {时长}」；宿主重启暂停的任务显示「已暂停」。她对 owner 说的话不在线程里。
- **7.2 角色脑工具行**：用 `tool.call.toolview` 槽位注册轻量行；标题来自 locale，心里话行显示第一句。DSH 的权限选择器在她的人格预设和行动脑预设会话里被遮住（不改 DSH）。

## 8. 压缩

两个脑 `thresholdRatio` 0.75、`headroomTokens` 6144（原定 85%，现网溢出后 owner 改定为他原生 DSH 部署长期用的值）。不改 DSH 的实现；已经超过窗口的会话换新会话，记忆在数据库里。

## 11. 本 ADR 替 owner 定下的

- 行动脑不写身份数据。
- Character Core / Current Self 和人格文档仍是两个存储，只统一门槛；合并另议，开发期直接删重建，不写兼容代码。
- 只有认知核的 APPLIED 发布才请求 worker 重启；同一项目里还在等的旧发布记为 `SUPERSEDED`。
