# 执行决定：增强角色，不包住或削弱 DSH 行动循环

## 1. 基线究竟比较什么

以**本机固定版本 DSH 的接口、配置和调用语义**为设计参照：Asuna 在它之外增加了哪些前置依赖、工具裁剪、输出要求、拒绝条件、状态转换或恢复覆盖？这些变化是否是具体用户需求所必需，作用范围是否最小？

这不是参考某次裸 DSH 的完成时间、措辞、工具序列或是否一次成功。也不是宣称 DSH 对全部故障都能自愈。查看相关源码/配置就能判断的限制，不需要昂贵的 LLM 实验才承认它存在。

例如，在 DSH 下一步之前新增 `step > 65 → reject`，就是一个额外终止条件。即使某次任务只用了十步并成功，该设计事实也没有改变；不需要另跑一次裸 DSH 或 66 步实验。

**设计判断、实现验证、产品使用是不同工作：**设计判断决定是否应该加这条限制；实现验证检查接线是否符合决定；真实对话用于检查产品实际可用性。三者都不能冒充另一个。没有对照实验不是延期修正明确设计问题的理由，代码审查也不是已经完成真实 QQ 接入的证明。

## 2. 双脑分工保留，行动侧不因此降格

Gemma 基于人设、关系、记忆和现实反馈形成独立的感受、意图与表达；独白保持独立可记录，不退化为给 Qwen 的答案换语气。

Qwen 在已授权目标与资源范围内，使用 DSH 的既有执行机制自行获取资料、规划、编写代码、使用技能、调试、继续任务。Gemma 的阶段机不逐步控制这些过程。只在目标、承诺、授权或需要她判断的意义发生变化时回到角色；普通实现错误不要求先经过完整情感回路。

宿主补充场景归属、必要上下文、交接、真实发布与持久记录。它不是第二个执行 harness，也不是对每个工具结果再裁决一次的监工。

角色公开表达的归属约束，有“保持同一个角色”的具体理由；它不等于禁止执行模型输出内部自然语言、返回诊断、产生代码/附件，或让每次合法工具操作等角色重新签字。运行权限限制资源与目标，不减少授权工作域内的探索路径。

既有有效阶段不为本次纠偏重写；但既有实现也不能仅因“已建好”而免于删减。

## 3. 新增设计的理由怎么给

只在新增或改变实际运行限制、前置依赖、错误处理或原生机制覆盖时，写一段普通开发说明：

> 为满足哪个具体需求；本机 DSH 现有方式缺在哪里；本修改增加或禁止了哪条路径；为何不能不加、复用原生机制或缩小作用范围；出错后已有合法任务怎样继续。

这段说明放在现有修改说明里即可，不要求每个函数、每个 UI 元素都写，不要求模型运行时给自己的行为提交理由。**说明不是自动授权**；“安全起见、便于审计、架构完整、保证格式统一”本身不构成充分理由。

真实资源限制与用户取消依然有效；不把原生限制一律改成无限，也不凭空设新的数字。边界确实不清楚时，只提出那一处具体问题，不把整个项目改成等待审批。

## 4. ADR003 的当前处置

以下行为来自 Codex 的报告，尚未由本包审阅方取得最新工作树独立重跑。位置以报告里的函数/符号为线索，行号可能变化。只读需要修改的路径，不先审核整个仓库。

| 报告项 | 本轮决定 | 不得换一种方式重建同一问题 |
|---|---|---|
| D5：`runtime-v2.ts` 的 65 步拒绝 | 移除 Asuna 额外硬拒绝，沿现有 DSH 执行与用户停止机制运行 | 不改成更大数字、不换 operation 规避、不新建进度评分器/预算服务 |
| D6：provider 重试、自动压缩、overflow 的无依据关闭 | 按安装版相关配置确认并取消 Asuna 无依据覆盖；保留有明确用途的本地模型/资源设置 | 不统一开启无限重试、不升级 DSH、不声称删除配置就证明恢复成功 |
| D4：必须有 `task_status` 才接受结果 | 移除特定报告工具作为结果入场资格；保留自然语言、已有工具事实和原任务关联 | 不换成强制 JSON/完成证书，也不看到一次工具成功就判整个任务完成 |
| D3：所有逃逸异常进 `UNKNOWN`，反馈被排除 | 缩小不确定性到实际不明的操作；错误、结果与后续核实仍可交回原会话 | 不全改 `READY`，不为保留这个总闸而再建一个恢复状态机 |
| D2/D9：检索前处理失败后输入永久离队 | 修时间戳和有界检索；把可选检索增强与可信输入/目标续接解耦；使用已有回读/诊断入口补最小缺口 | 不重新读取同一个坏依赖才能报错、不丢原输入、不强制用户重发、不建立第二套记忆库 |
| D7：没有自建 `active` operation 就拒绝所有生成 | 保护可信来源与场景归属，而不是保护 `active` 字典本身。已有 operation 绑定可复用，但合法 DSH continuation 不应因为缺 Asuna 专用登记而被无理由拒绝 | 不简单关闭身份校验；也不坚持旧“必须保留此检查”措辞，为所有原生事件再造复杂登记系统 |
| D8：投递或副作用不明只留错误标签 | 保留本次不确定结果，核实状态和继续认知；针对该动作防重 | 不循环重发原请求、不自动重放所有任务、不让其他合法工作跟着失效 |
| D1：角色阶段协议失败被当作整个目标结束 | 保留独白/意图/公开发言区别，仅校验真正驱动下一动作的信息；歧义反馈给角色自身处理；既有 Qwen 任务不受无关角色格式错误取消 | 不把 Qwen 也套入相同固定阶段，不靠情绪/禁词/漂亮 JSON 测试来维持运行 |

D7 是对旧指令的明确细化：**要保留的是来源和权限语义，不是 `UNOWNED_LANE_GENERATION` 的原始实现。** 在固定版本支持的会话/事件扩展点中采用最小方案，不把传来的提醒正文伪装成用户授权；也不要提前借本修复建设完整定时系统。

D1 不授权凭模糊独白执行新动作。信息确实不足时保留目标并问清/修正；对已经获准且正在执行的任务，无关的角色格式问题不是停止理由。

## 5. 当前修复顺序：删除多余依赖，再补真正缺的接线

**先确认现场。** 对照 ADR003 的 HEAD、运行进程与 dirty 修改；报告说明磁盘代码与实际加载版本不同。保留原失败输入、Qwen 方案、开发目录、技能、凭据配置和原日志。不 reset/clean、不 `add -A`、不批量回滚群聊/UI成果。

**随后修直接阻塞。** 检查已写的检索修正是否适用，修好实际排序与候选边界；移除前处理失败把原输入永久终结的依赖。只要已核实身份、权限、必要角色状态与原目标仍在，可选 RAG 失败不应禁止相同权限内的已有上下文或诊断。材料缺失如实标明，不伪称记忆召回成功。

**同时修原行动任务的回传与继续。** 按表处理后置报告门槛、UNKNOWN屏蔽、额外限步和无依据配置。先看是否能删除门槛，而不是条件反射地对每个被拒结果再发一次修正提示。确实缺少目标所需事实，才通过现有会话反馈追问或继续；不能每次正常 DSH stop 都自动叫醒下一轮。

**做必要检查后继续原 NapCat 任务。** 不等“所有异常都产生过一条模型恢复录像”。用当前正式 Web/CLI 继续已接受的原目标；Qwen 自行完成适配器，Codex只修宿主缺口。需要重新加载受影响服务就按已授权运维方式处理，不关闭无关任务；无法可靠恢复原 DSH 历史时说明并使用已保存任务材料，不能宣称恢复了 KV。

本轮暂停新增 UI、群聊、定时器、Bonus 功能，避免分散到旁支；保留已做内容。阻断消除后立刻回 QQ 私聊主线，而不是继续完善“恢复工程”。私聊可用后继续原 V2.2 的群聊、定时自主成长、总结/偏好顺序。

## 6. 错误与安全：不追加第二个 harness

普通工具失败留在当前原生执行回路。扩展层出错，保留原始原因并通过已有可信入口交回适合的会话；不是把宿主异常假造为某次从未发生的工具结果。

“发出去了没有”不明，约束的是再次发送这个动作；已授权读取回执、查看状态、解释限制或处理其他独立步骤仍可进行。目标进展、动作状态与错误详情可以使用现有字段/记录，不要求迁移数据库创建新的三套状态表。

权限拒绝针对被拒资源；允许范围内替代与解释，不允许换工具绕过同一拒绝。收到取消就是停止该授权，不被后台恢复重新激活。必要身份/权限根本无法确认时，不增加数据访问范围。

审计展示、可选总结、向量增强不能成为所有正常执行的额外通过门槛；必要发布回执和数据正确性仍如实保存。不以“少做检查”为理由隐瞒写入失败、捏造已送达或开放全部凭据。数据库/宿主/模型确实不可用时可能只能等待依赖，不能承诺模型总能自行修复。

可诊断不等于自动有权修改宿主。此次宿主 bug 由 Codex 在已有授权下修；Qwen仍能知道问题、诊断、在授权 adapter/技能目录继续，不让用户反复重发目标。未来主机自修改是独立授权问题，本次不增加自动部署整个宿主的能力。

## 7. 角色、记忆与成长不能被这次纠偏抹掉

稳定人设与记忆注入是 Asuna 的真实扩展，不删除它们来变成普通 DSH 聊天。减少的是全量审计/检索/总结成功才允许思考的额外依赖，不是抹掉角色身份或他人的隐私范围。

工具能力、人物理解和记忆仍可随经历成长。自写技能仍通过已有 DSH 技能/工具路径发现与使用，不换成封闭动作菜单。角色可以提出尚无现成工具的新意图；既有实现可以在授权范围内自行改进，不要求先过一套新增成长评分或注册平台。

结论：**先减少 Asuna 对原生机制的干预，再补独立情感与真实交互所必需的扩展。不要把每一层抽象都变成下一层必须通过的关卡。**
