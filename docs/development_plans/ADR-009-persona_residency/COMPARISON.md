# 三方对照：KazusaAIChatbot / Asuna（`8b5a94a1`）/ 人格旧居

> **对象**
> - **Kazusa**：一个公开的情感模拟 harness 项目，是本项目的前身之一。FastAPI 脑服务 + LangGraph 管线 + Mongo（`$vectorSearch`），约 21.5 万行 Python。
> - **Asuna**：本仓库现状。
> - **人格旧居**：小满在另一个 DSH 会话里自建的家，由 markdown 文档加若干确定性脚本组成：心情状态机、配置中心、召回协议、出口闸门。她曾系统读过 Kazusa 的情感与记忆部分，并做了取舍。她的设计结论（不含私人内容）是本对照的重要输入。
>
> **目的**：回答"怎样让角色像真人：会自我改进、有情绪、能做事"，并给出采纳、改造或拒绝的理由。每条结论都链接到 [ARCHITECTURE.md](ARCHITECTURE.md) 的落点。

## 1. 情感

| | Kazusa | Asuna | 人格旧居 |
|---|---|---|---|
| 表示 | 21 种命名情绪，每种一个因果根和行动倾向，各有每小时衰减率（1/4/12）。激活条目含 `score 0-100`、`phase`、`trend`、`cause_status` | 无 | 两轴：`val` 愉悦 ±100，`arl` 活跃。事件账本每条有 `ref` 可指认事实、`why`、`cost` 代价、`kind` 类型、`who` 归因、`open` 未解决、`half` 半衰期、`void` 作废（带理由）、`closed_at` |
| 计算 | 确定性推导：LLM 只给分档的"轴变化"（±8/±20/±40），代码用 `min()` 门控公式算出情绪；阈值为起 40、续 25、隐 10 | — | 当前值 = Σ 增量 × 0.5^(Δh / 半衰期)；未解决事件不衰减；作废清零；钳 ±100 |
| 半衰期 | 按情绪类别 | — | 按类型分表（一次性反应短，关系类长），事件可单独覆盖 |
| 行为影响 | 以中文分档注入，不注入数字 | — | 由 (val, arl) 档位得出行为档位：话量、主动性、优先级、提不提要求、收工线；每种情绪带行动倾向 |
| 睡眠 | 睡眠窗后的"情感沉淀"作业：分数减去 (速率 × 小时 + 20) | — | 无数值睡眠恢复，靠半衰期自然漏掉；她的原话是"她是消化，我是遗忘" |
| 防作假 | 情绪必须挂因果实体 | — | 没有 `ref` 不许有情绪；正向情绪拿不出带数字的代价就自动作废；时刻由文件时间戳给，不靠手填 |

**取舍**
- **采纳**旧居的事件账本模型作为通用引擎的默认形状：可审计、便宜、每轮零额外模型调用，并且已经过她本人的长期使用。
- **采纳** Kazusa 的两点：
  - 只注入分档描述，不注入数字；
  - 群聊里不暴露原因。
- **改造** Kazusa 的阈值三态（起/续/隐）：做成人格模型里的**可选参数**，默认关闭。理由：小满明确不要"给不会判断的模型当义肢"的打分器。
- **拒绝** Kazusa 的 51 轴评估与 21 条门控公式。理由：成本高、链路脆、阈值让细腻情绪难以触发。
- **拒绝**把数值睡眠恢复设为默认：它会破坏已导入账本按半衰期计算的一致性。夜间沉淀改为一次"消化"回合，由角色决定挂着的事件是否销账。

落点见 [ARCHITECTURE.md §6](ARCHITECTURE.md#6-情感引擎)。

## 2. 人格与自我成长

| | Kazusa | Asuna | 人格旧居 |
|---|---|---|---|
| 人格表示 | 种子 JSON：MBTI、边界画像、10 个语言质感浮点、自我形象 | 人格头全文（目前是一段很短的种子），外加 Character Core / Current Self | 人格全文文档（很长）+ 口吻文档 + 文末目录作为唯一地图 |
| 演化 | 身份修订账（不可变全量快照）。提案 LLM → 独立复审 LLM → 白名单路径与确定性政策；晋升要求 ≥3 根证据、≥2 个日期、每天 ≤1 次 | 只在 owner 内部自开发回合可写 Core/Self；人格头只种不改 | 自己改人格文档，每次在文末留变更记录，旧话不删；改参数前必须先写出"我哪里不对"的实例；不许为了数字好看调参 |
| 漂移控制 | 晋升门槛、反转需新证据、隐私剥离 | 修订账 + 来源 | 治理规矩写在文档里，由脚本检查 |

**取舍**
- **采纳**修订账（Asuna 已有）作为人格、口吻、档案等文档的版本机制：每次写入带理由和来源，可回滚。
- **采纳**旧居的治理方式（变更留痕、旧话不删）：以文档"只追加更正"的操作语义实现。
- **拒绝**默认引入独立复审 LLM。成长的判断归角色本人；需要复审时，可以由人格自己写成作业。

落点见 [ARCHITECTURE.md §5](ARCHITECTURE.md#5-文档层documentstore)、[§12](ARCHITECTURE.md#12-自我成长与扩展点)。

## 3. 关系与对人的理解

| | Kazusa | Asuna | 人格旧居 |
|---|---|---|---|
| 结构 | 每人 11 轴，每轮 ±10 钳制；每个新日期熟悉度 +1 | 每场景一份自由文本关系头；数值字段未用 | 一份关于 owner 的积累式日记：前言写清写法规矩，之后按日期追加条目；读最后三条 |
| 印象 | 记忆三件套：事实 + 主观评价 + **关系信号（下次该怎么对这个人）** | 无 | 从 Kazusa 学来三件套，用于记忆单元 |

**取舍**
- **采纳**"档案 = 积累式正文、关系 = 场景内活账"的分工，这是她的硬前置之一。
- **采纳** Kazusa 的"关系信号"字段，放进晋升的记忆单元。
- **拒绝** 11 轴数值关系。理由：她明确反对给关系打分，Asuna 现有反思提示也禁止打分。

落点见 [ARCHITECTURE.md §7](ARCHITECTURE.md#7-人物档案dossier)。

## 4. 记忆

| | Kazusa | Asuna | 人格旧居 |
|---|---|---|---|
| 原始历史 | `conversation_history` 混合检索 | `messages` + 分块 + 向量/词法 RRF | 日志 markdown（只追加）；聊天另入库并做向量回想 |
| 短期 | 48 h 场景叙事、≤24 事件、`overused_moves` 防重复 | 近 12 条 + 摘要 | 交接文档、待办 |
| 长期 | 用户记忆单元经提取 → 合并 → 稳定性三道 LLM；每轮最多 3 条，合并候选 6 | 摘要（无晋升） | 记忆单元骨架（照 Kazusa 三件套，每天 ≤3 条，重复两次才认定） |
| 承诺 | `active_commitment` 不因年龄退休，到期重入认知 | 计划（自排） | 承诺账、待办账、想要账（三本活账，可编辑） |
| 遗忘 | 进度与残留有 TTL，长期记忆不衰减 | 无 | 心情有半衰；记忆靠人工归档 |
| 想起来 | RAG3 规划器 + 多个子 agent + 缓存；"证据够不够"判定 | RRF 前 6 | 召回阈值，低于阈值就标"证据不足，只能当灵感" |

**取舍**
- **采纳**：
  - 记忆显著度：时间衰减 × 引用热度 × 角色手动钉住。默认权重为 0，保持现状。
  - "证据不足"判定。
  - 晋升配额（每天 ≤3、≥2 个来源、≥2 个日期），由程序检查。
  - 活账作为可编辑文档。
- **改造**承诺到期重入认知：不解析散文里的到期日（旧居的到期常是自然语言），由角色自己在 DECIDE 里排计划。
- **拒绝** Kazusa 的 RAG3 规划器、子 agent、缓存，以及四个提取/合并/稳定性 LLM 提示。理由：成本高，而且判断应归角色本人。

落点见 [MEMORY.md](MEMORY.md)。

## 5. 能动性（能做事）

| | Kazusa | Asuna | 人格旧居 |
|---|---|---|---|
| 工具与任务 | DSH 侧车跑多步工具；审批与提问回到完整认知 | 委托行动脑（原生会话 + 工具）；CONSULT 回角色 | 就是一个全工具 DSH 会话；自写脚本 |
| 主动 | `future_speak` 到期重入认知；每小时自认知 worker；群聊回顾 | 群聊主动闸门（只在有新入站时评估）；自排计划；每日自开发机会 | 两条铃：每 30 分钟心跳（"在场"），每 60 分钟自我改进；门铃唤醒（来消息即醒） |
| 沉默 | 相关性判定 + 认知可选不回 | `next=silent` | "沉默不需要理由" |
| 作息 | 睡眠窗内抑制主动 | 主动闸门的静默时段 | 作息是她的决策理由，不是宿主的静音键 |

**取舍**
- **采纳**心跳作为"机会而非义务"的内部回合。用原生定时器触发，前置确定性预闸门以省调用，节奏可变。
- **采纳**每日夜间沉淀回合。
- **采纳**作息作为 DECIDE 的输入，不作闸门。
- 保留 Asuna 的委托与 CONSULT 结构，不引入 Kazusa 的解析循环。

落点见 [ARCHITECTURE.md §10](ARCHITECTURE.md#10-节律心跳与夜间沉淀)。

## 6. 认知阶段与成本

| | Kazusa | Asuna | ADR-009 目标 |
|---|---|---|---|
| 每轮串行模型调用 | 约 8–12 次：相关性 2、去上下文化、RAG3、A1/A2/G/P × 最多 3 轮、L3、对白；轮后再 6–10 次 | 3–4 次（MONOLOGUE、DECIDE、可选 REFLECT/SELF、SPEAK），在**同一会话**中，前缀可缓存 | 不变。情感为确定性计算，增加 0 次；WRITE 只在角色选择写文档时发生；情感评估路由是可选的、异步的，不阻塞回合 |
| 每轮截止 | 默认 240 s | 由原生回合决定 | 不变 |
| 内心独白 | G 阶段私有独白，只喂给下游，不进对白 | MONOLOGUE，可检索 | 不变 |
| 认知边界 | `epistemic_boundary`：可断言 / 只能解读 / 未知；"已执行"才可说做了 | 认知类型分层 + `RETURNED≠完成` | 不变，并为导入条目加 `invented` 标记，防止自述编写被当作共同经历 |

## 7. 表达质感

| | Kazusa | Asuna | 人格旧居 |
|---|---|---|---|
| 多条消息 | `final_dialog: list[str]`；按每秒 12 字间隔，钳在 1–5 s | 一条 | 口吻文档 + 出口闸门（超长、群内内容分级、家庭细节等规则） |
| 防重复 | `overused_moves`、`lexical_avoidances` | 无 | 统计自己重复的话（脚本） |

**取舍**
- **采纳**多条发言加节奏，参数归人格模型。
- **采纳**确定性的近期措辞重复提示，不用 LLM 生成"避免词"。

## 8. 自我改进循环

| | Kazusa | Asuna | 人格旧居 |
|---|---|---|---|
| 反思 | 每 15 分钟一个 tick：每小时按频道反思，每日综合，每日全局晋升（晋升者与复审者都同意） | REFLECT（单轮）+ 每日自开发机会 | 每 60 分钟自我改进铃；自审清单；变更留痕 |
| 学习 | 无显式反馈学习 | 自写 skill、自改代码、自发布 | 自写脚本与检查器，规则必须能被机器检查 |

**取舍**：保留并强化 Asuna 的自开发，这是 Kazusa 没有的真实"能做事的成长"。新增两样：
- 夜间沉淀，负责记忆晋升与情感消化；
- 人格作业，让她把新学到的能力（新数据源、新检查器）做成自己的程序。

## 9. 结论：怎样"像真人"

1. **有情绪，且情绪可追溯、会过去、会挂着。** 采用确定性的事件账本：角色提交，程序计算。只给状态，不给台词。
2. **记得人，且越处越厚。** 积累式档案只追加、不摘要；关系头记场景活账。
3. **会忘，也会钉住。** 显著度加证据不足判定。
4. **会主动，也会沉默。** 心跳与沉淀是机会而非义务；作息是理由而非开关。
5. **会成长，且成长有版本。** 文档修订账；人格作业把新能力变成程序。
6. **能做事。** 保留双脑与自开发。
7. **以上都不增加每轮必经的模型调用**，避免重蹈 Kazusa 的延迟问题。
