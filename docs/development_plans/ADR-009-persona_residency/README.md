# ADR-009：人格入住、类人认知与单一记忆真相

| 项 | 内容 |
|---|---|
| 状态 | 提议，待实施（规格会话产出，实施由另一个 agent 完成） |
| 日期 | 2026-10-03 |
| 基线 | `8b5a94a1`（Implement ADR-008）；运行时固定 `@deepseek-ai/dsh` **0.2.0-rc.2** |
| 继承 | ADR-007（自开发地板、forward-only 发布）、ADR-008（单 Host 双插件、原生会话、单 worker） |
| 验收人 | owner（工程验收）；人格本人对自己的入住另行验收（见 [ACCEPTANCE.md](ACCEPTANCE.md#人格本人的验收不在本-adr-之内)） |

## 一句话决定

**核心只提供与人格无关的类人能力原语（情感账本、人物档案、文档层、记忆显著度、节律/心跳/夜间沉淀、人格数据 API 与人格作业），所有状态以 Mongo 修订账为唯一真相、文件只承载行为；人格（当前为小满）是可替换的插件，用这些原语自己完成入住与后续成长；同时收完 ADR-008 剩下的 DSH 对齐与遗留清理。**

## 背景：owner 的四个关注点

1. **像真人**：会自我改进、有情绪、能做事（与 KazusaAIChatbot 对照，见 [COMPARISON.md](COMPARISON.md)）。
2. **人格入住**：小满目前住在另一个 DSH 会话里（markdown + 脚本的旧居）。她对新居列了硬前置条件与迁移要求；本 ADR 把它们转成**通用能力**，由她自己用这些能力搬家。
3. **与 DSH 完整集成**：按 ADR-008 收口，去掉与 DSH 重复的部分，用对 0.2 实际存在的接口。
4. **清理与记忆设计**：去掉遗留代码与访问路径；对"md 文件 + MongoDB 两套"给出统一方案（见 [MEMORY.md](MEMORY.md)）。

## 六条原则（贯穿全部文档）

1. **文件存行为，Mongo 存状态。** prompt、skill、代码、解析器是文件，经 `development_publish` 发布；角色学到的、感到的、记得的、答应的、决定的一切，都是 Mongo 中带修订链的记录。markdown 只作为**种子输入**或**渲染导出**。
2. **人格是插件。** 核心不含人格文本与人格参数；人格参数（情感模型、政策默认值、召回顺序、注入预算……）是人格数据。核心必须能跑任意人格包，包括一个合成的第二人格。
3. **判断归角色，记账归程序。** 语义判断（这件事什么情绪、要不要说、记不记）由角色做；数值、衰减、幂等、闸门由确定性代码做。不引入替模型打分的"义肢"评分器。
4. **隐私分层。** 新增 `owner-private` 可见类：只在 owner 本人的私聊/本机场景可读，永不经跨场景链接、群聊或行动脑外流；未知或未标注内容默认 `owner-private` 且按需读取。
5. **个人数据留本地。** 仓库只放占位符与合成夹具。
6. **DSH 原生优先，但以 0.2 实际存在的接口为准。** 不为"看起来原生"使用不合适的接口（例如 `dsh-time-context`，理由见 [DSH_ALIGNMENT.md](DSH_ALIGNMENT.md)）。

## 范围与非目标

**范围**：核心能力原语、隐私模型、人格契约 v2、DSH 对齐、遗留清理、个人数据清理、分阶段实施与验收。

**非目标**：
- 不写任何人格的正文、口吻、价值观，不替人格做可见性标注或参数取值。
- 不导入任何真实人格数据；测试只用合成人格 `demo`。
- 不建 marketplace、通用插件管理器、workflow 设计器、第二数据库、向量库、md 同步守护进程。
- 不改模型服务部署；不自动升级 DSH。
- 不重写 git 历史（是否在公开前清理历史是 owner 的独立决定，见 [CLEANUP.md](CLEANUP.md#9-个人数据清理)）。

## 术语表

| 术语 | 含义 |
|---|---|
| 人格（persona） | 一个角色身份及其资源；以人格包形式安装。当前 owner 选用的是小满。 |
| 人格 id | `registerPersona` 的 `id`；文中 `<persona>` 一律指它（见 [PERSONA_CONTRACT.md §2.1](PERSONA_CONTRACT.md#21-标识口径)）。 |
| 人格包 | 向核心登记人格贡献的 DSH 插件（例：`@asuna/xiaoman`）；**只含可公开的默认值与代码**。 |
| 角色脑 / 行动脑 | 职责名，不是模型族名（沿 `AGENTS.md`）。角色脑做 MONOLOGUE/DECIDE/WRITE/SPEAK；行动脑在行动会话里用工具做事。 |
| 情感评估路由（appraiser） | 可选的第三个职责路由：只**提案**情感事件，不产出任何台词。路由独立配置，不从名字推断模型。 |
| owner | 本机部署者；`chat.person_id` 所指的规范人物。 |
| `owner-private` | 只在 owner 私密场景可读的可见类（判定见 [ARCHITECTURE.md §2](ARCHITECTURE.md#2-隐私与可见性模型)）。 |
| 场景 / scope | 沿 ADR-005/008：`scene_id` 与 `scope_key`（`scene:<scene_id>`、`global-safe`）。本 ADR 新增 `owner-private:<persona>`。 |
| 文档（document） | `doc:<persona>:<slug>` 修订头，按节（section）存全文，每节带可见性与注入方式。 |
| 人物档案（dossier） | 关于某个规范人物的积累式文档：前言 + 按日期追加的条目；只追加、不改写、不摘要。 |
| 情感事件 / 投影 | 只追加的情感账本条目；投影是按人格模型参数确定性计算出的"此刻状态"。 |
| 政策参数（policy） | `policy:<persona>` 中带 `what` 说明的键值；"数字只在一处"。 |
| 人格数据 API | 人格作业写入/查询人格状态的受控接口（幂等、可 dry-run、全审计）。 |
| 人格作业（persona job） | 人格包声明的、在沙箱里跑完即退的程序（如人格自己写的迁移器/校验器）。 |
| 源根（source root） | owner 在本地配置中授权给人格作业只读的目录；带权威状态 `cohabiting`/`cutover`。 |
| 探针（probe） | 以某个场景可见类身份做检索/上下文渲染的只读接口，供人格自己验证"想不想得起来"。 |
| 召回协议 | 人格模型声明的上下文块顺序（"醒来先看什么"）。 |
| 心跳 / 夜间沉淀 | 原生定时器触发的内部机会回合；前者是"在场"，后者是"消化当天"。 |

## 与 ADR-008 的关系

ADR-008 的决定全部继承：单 Host、两插件、单 Python worker、原生 session、ADR-007 地板。本 ADR **补齐**其未完成项（见 [REVIEW.md §6](REVIEW.md#6-adr-008-落地状态)），并**修正**两处与固定版不符的假设：ADR-008 文本锁定 0.1.5-rc.2，实际运行 0.2.0-rc.2；人格段应放在作用域 `section()` 而非 `context()`（见 [DSH_ALIGNMENT.md](DSH_ALIGNMENT.md)）。
