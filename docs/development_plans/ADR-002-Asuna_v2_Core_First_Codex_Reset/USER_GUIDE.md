# 给实际使用者：怎样开始与 Asuna 对话

## 现在先把哪份文件给 Codex

把本包交给本地 Codex，要求从 `CODEX_START.md` 执行。它目前还需要接通入口，因此本包不提供一个假装已经装好的启动命令。

你首先应收到：**一个能直接使用的本机启动脚本，以及一份已填写的 `RUN_ASUNA.md`。** 那份说明必须告诉你实际在哪个终端启动、怎样停止、出错在哪里看；不是留着容器名和项目路径让你猜。

## 入口交付之后

启动一次，直接说话。无需选择 Gemma 或 Qwen，无需区分聊天／工具模式，无需告诉她先读人设、再写独白、再检索数据库。

随便聊：
> 小满，我回来了。今天没什么事，就是想和你说几句。

让她做事：
> 帮我看看笔记里备用线放哪儿了。原笔记别改。

做事期间继续交流：
> 不急。你刚才说的那个小谜题，我还想听。

留下新信息：
> 我把那个杯子叫作雾灯，现在挪到窗边了。

给反馈：
> 刚才那句比一大段解释好。以后这种场合你可以直接一点。

不要求她逐字说某个范例。她也可能误解、找不到信息或遇到工具错误；重要的是能继续交流、如实说明，并把需要查的交给行动脑。

`/trace` 查看这次实际的记忆、独白、工具和错误；平时不需要开着。`/quit` 的具体效果以已交付的启动说明为准：V1 通常结束前台应用，V2 可关闭客户端而让已明确启动的服务继续运行。

## 怎样让她开始开发 QQ 接口

这不是给 Codex 的“请帮我写 QQ bot”。等本机聊天、工具往返和基本成长可用后，在 Asuna 的正常对话里使用 [QQ 任务原话](tasks/ASK_ASUNA_TO_BUILD_QQ.md)。

你只需提供或确认现有 NapCat 的连接配置来源、用于测试的账号和允许交流的对象。token 放进本地配置，不粘进普通聊天。缺少登录时由你完成扫码；她不应自行操作其他账号或给所有群发测试消息。

Asuna 应自行形成目标，由 Qwen 阅读文档、编写和调试适配器。Codex 只负责缺失的宿主接入点；它若实际代写了代码，应明确说是共同开发，不能算作 Asuna 独立获得能力。

成功以后，你从 QQ 对她说话，仍然是同一套人格与记忆系统。不是另一个只会调用语言模型的 QQ bot。本机入口继续可用，也作为查看错误与停用接口的地方。

## 什么情况下说明系统还没做好

每次都要你手工运行 executor／index、输入长 JSON、提醒读人设，或者她说“已接通 QQ”却收不到实际消息，都不是你的使用方式不对。

把当时的输入、真实回应和 `/trace` 中相关错误给 Codex即可，不需要你替它设计测试矩阵。还没做好的功能应标明，不用“PASS数量”解释为什么你实际上不能用。
