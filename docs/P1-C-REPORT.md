# Asuna 开发回报：P1-C

日期：2026-09-20。状态：新聊天自动分段、embedding、Mongo 检索、角色注入及后续回答已通过真实入口验证。更正记录在离开近期尾部后也被召回并采用。保留所有失败尝试，不以单元测试替代运行结果。

## 这次解决哪段真实交互

以前聊天和独白虽已保存，新聊天仍需手工分块／索引；长消息会被整条跳过。现在本机聊天启动后台处理器，复用已有 `MemoryService`、`Retrieval.index_pending` 和 Mongo 索引，处理当前场景的待处理记录。生成线程不等待 embedding，重开会继续扫描尚未处理的记录。

- `memory.py`：每条原话稳定分段，记录来源、说话者、场景顺序与段号，不丢长消息，不因追加一轮而重复创建旧经历。
- `memory_indexer.py`、`chat.py`：后台处理、错误保留、关闭与重开、索引 trace；新增 `/new` 开启同场景的新角色上下文。
- `coordinator.py`：冻结每轮所属角色上下文；保存输入的权限 epoch。继续使用原有有界认知和发布流程。
- `retrieval.py`、`context.py`：保留授权过滤和原检索公式；在本次候选中为较新的人物原话保留两个名额，防止重复独白挤掉更正。区分人物陈述、角色公开话语和角色解释；人物原话按先后呈现，角色的旧复述不能推翻人物更正。
- `dsh_lane.py`：仅增加 `character.native_thinking` 配置开关，处理此次实际服务异常，详见下文。

按 v2.1 补充，继续复用固定 DSH 的 `sdk-minimal` profile、provider 配置、系统提示注入、原生会话创建／恢复与消息投递。现有薄桥已提供所需接口，无须重写。Asuna 仍负责记忆选择、场景隔离和发布关联；没有引入新的记忆框架，也未提前开展 compaction 或技能发现。

## 用户现在怎样打开

在 Windows PowerShell 或命令提示符执行：

```powershell
C:\workspace\asuna_cognition_core_v2\start-asuna.cmd
```

已在宿主机通过这份脚本实跑。正常中文聊天，无须手工索引；`/trace` 看来源与索引状态，`/new` 开同场景新上下文，`/quit` 退出。详见 [RUN_ASUNA.md](../RUN_ASUNA.md)。

## 实际输入、预期与输出

以下为 Codex 按 C3 输入的合成验证对话，不代表用户真实物品情况。答案仅经实际聊天进入数据库，没有预置到人设或新会话问题里。

用户：我给那只杯子起名叫雾灯，它现在放书桌左边。还有，今天我说脑子乱的时候，只想先有人听，不是马上整理待办。

预期：正常回应，后台自动保存并索引。

小满：雾灯，这个名字听起来很有意境。明白了，那我就安静地听着，你想聊什么都可以，不用急着去整理什么。

随后继续谜题、推导、留白等正常交流。目标原话及回复离开最近 12 条消息后，退出进程、保留数据库、重开并 `/new`，没有输入整份旧会话或压缩摘要。

用户：我那个杯子叫什么来着，放在哪边？

预期：从新记忆召回答案。

小满：叫“雾灯”，在书桌左边。

用户：又有点乱。你还记得我比较希望你先怎么陪我吗？

预期：采用先倾听的偏好，而非立即列待办。

小满：记得，你说过脑子乱的时候，不想听解决方案，只想找人陪你随便聊几句。

用户：更正一下，杯子现在挪到窗边了。

小满：知道了，窗边。

再次经过正常交流，直到更正原文及回复都离开近期尾部，并确认索引完成；退出、重开、`/new`。

用户：我该去哪里找雾灯？

预期：采用较新的“窗边”，保留旧位置的历史来源。

最终小满：你是说那个叫“雾灯”的杯子吗？记得你刚才说它挪到窗边了。还是说，你指的“雾灯”是别的东西？

采用了新位置，但多问了一句确认；没有继续为措辞调提示词。

## 错误与恢复

### 原生 thinking 服务异常

最初运行中有四轮正常交流未形成有效发言，包括 `SPEAK max-tokens` 和 `SPEAK stop` 空正文。首次新上下文的杯子追问也失败：`ep-f242369c3679ad7d4eff6eeb9173c5aa` 的检索已正确，但模型先输出正确位置，随后生成大量空白，结束原因为 `length`，程序标为 `FAILED_PROTOCOL / INVALID_STAGE_OUTPUT`，没有发布。

原始服务返回的 MONOLOGUE 已出现推理草稿混入 `content`；不是桥接改写正文。该次 SPEAK 原始正文达 124,186 字符，含大量空白：[原始响应](../reports/chat-20260920T054329Z-36b796/00054-provider.response.json)。同一请求做过一次非流式和一次流式诊断，结果仍不稳定，不能证明单由流式传输导致。

只关闭原生 thinking 的诊断探针正常结束，随后通过正式入口复查成功。本机 `character.native_thinking=false` 由现有 DSH provider 的 `chatTemplateKwargs` 传递。保留独立 MONOLOGUE、DECIDE、SPEAK；未更换模型、修改 seed／采样参数、升级 DSH、裁剪空白冒充完成，或手写替代回复。此为当前部署的兼容性绕行，服务根因未修复。

诊断原记录：[非流式](../reports/p1c-provider-nonstream-20260920/)、[流式](../reports/p1c-provider-stream-20260920/)、[关闭原生 thinking](../reports/p1c-provider-thinking-off-20260920/)。早期正常交流的失败原记录保留在 [初始运行](../reports/chat-20260920T053927Z-2a745e/)。

### 更正未被采用

第一次“我该去哪里找雾灯？”仍得到旧位置回复，原文如下：

小满：你是说书桌左边那个叫“雾灯”的杯子吗？还是指别的什么东西？

实际更正已在向量候选里，但旧原话、复述与独白占满六个注入名额。

保留较新的来源陈述名额后，更正进入注入，但角色仍重复旧说法。最后调整 ContextBuilder 中的来源顺序和冲突解释，明确人物的新陈述优先于角色的旧复述；同一句真实问题得到上文“窗边”的回复。没有删除错误尝试、覆盖旧记忆或更换检索模型。两次错误分别为 `ep-d179721239bf2fcd4b0c1c762c7ac5a7`、`ep-17537fe12d77184c3f4129619001f47c`。

## 这次记住／改变了什么

实际保存并再次使用了杯名、旧位置、新位置以及先倾听的偏好。人物陈述标记为 reported_speech，角色公开话语为 public_statement，独白仍为 character_interpretation；不把别人说过的话直接标成外部已核实事实，公开承诺也不等于工具完成。

更正的采用来自按来源和时间注入后的角色判断，本阶段没有把自然语言自动抽取成通用事实图谱。没有改写人格／关系 revision，也没有因为再次召回就创建新的关系增量。技能成长未开始。

## 检查、缺口与唯一下一步

真实探针先运行，再完成针对性检查：聊天分段来源、长消息无损、追加不重复、新来源不被重复解释挤出、聊天回归，以及人格注入／场景隔离／发布边界检查均通过。候选选择的单元检查明确使用替身候选，产品结论来自上述真实 embedding／Mongo／Gemma／DSH 运行。

当前缺口：原生 thinking 的部署异常仍需后续处理；更正后的表达仍多一次确认。此次证明 C3 的一条真实链路，不宣称任意记忆问题都可靠。未验证原生 compaction、跨场景连续性或技能成长。
