# ADR-015：命令改用 DSH 自己的沙箱，不再依赖 WSL

| 项 | 内容 |
|---|---|
| 状态 | **已实施**。owner 2026-10-06 决定 |
| 日期 | 2026-10-06 |
| 取代 | ADR-010 D5 的 `wsl-bwrap` 后端；ADR-001/003 里「没有网络、只能读任务目录」的隔离要求 |
| 作者 | 实施者（Claude），应 owner 的要求起草 |

## 一句话决定

**行动脑跑的命令、自开发的命令、人格作业和 QQ 适配器，都交给 DSH 的沙箱包一层再跑，只限制写入；不再要求 WSL。** 谁能跑命令，由任务拿到的工具决定：`sandbox_run` 只给主人自己场景里的任务。

## 0. owner 的要求（2026-10-06）

1. 除了必要的，少一个依赖是一个。DSH 已经有沙箱，就不要自己再造一个。
2. 本机会话本来就不打算做网络隔离；QQ 等其他会话，限制已经由能用的工具规定了。除了 DSH 默认的沙箱，不要再加别的沙箱或网络限制。之前的设计是 Codex 过度设计的习惯。
3. 过时的测试先删掉。

## 1. DSH 的沙箱（0.2.0-rc.2）

- 接口是 `ctx.sandbox.confine(argv, {mode, workspaceRoot})`：把命令包一层，返回包好的 argv，自己不启动任何东西。插件的后台代码也能用。
- 各平台的实现：Windows 是受限令牌加低完整性加作业对象（`dsh-sandbox-windows-acl`）；Linux 是 bubblewrap 或 Landlock；macOS 是 Seatbelt。
- 只管写入，只有一个可写目录（另有一个私有临时目录）。读取、网络、CPU 和内存都不限制。Windows 上它自报 `partial`（硬链接可以绕过）。
- Windows 上，被授权的目录要求当前账户能改权限、能取得所有权。授权会永久留在那个目录上。

## 2. 做法

- **宿主（JS）**：
  - 启动时告诉 worker 能不能包（`sandboxStatus`：包一个探针，不运行，也不碰目录）。
  - worker 请求时用 `workspace-write` 包一个命令（host_request `sandbox`）。
  - `development_run` 也直接用它。
- **worker（Python）**：
  - `sandbox_backend.py` 只剩两种后端：`dsh` 和 `none`。
  - 命令由 worker 自己启动：stdin 是空的，环境变量只留启动必需的几项，输出上限 256 KiB，带超时。
  - `python3` 换成 worker 自己的 Python。参数里写的 `/task`、`/app`、`/data`、`/integration/config.json` 换成真实路径，她已经写好的 brief 和适配器参数照样能用。
- **文件工具**：`list_files`、`read_file`、`write_file` 是固定操作，由 worker 自己在任务目录里做，受保护的源文件只读。
- **QQ 适配器和集成**：
  - 没有监管进程、中继和守卫了。运行直接连配置里的端点。
  - 适配器配置里写的本地中继端口，会改写成设备的真实地址。
  - `tls` 端点由取文件脚本自己做 TLS，不验证设备证书。
  - 试跑用的是真实配置，所以能真的对平台做动作。集成工具本来就只给主人。
- **适配器日志锁**：`fcntl` 在 Windows 上换成 `msvcrt`。
- **这台机器**：数据目录在仓库的 `.runtime`，owner 同意给自己的账户加完全控制（只这个目录）。全新安装的数据目录在 DSH home 下，本来就有完全控制。

## 3. 放弃的东西（owner 已知并同意）

- 命令能读到这个账户能读的一切，网络也不限。主人场景以外不给 `sandbox_run`，靠这一点来挡住陌生人。
- 2026-10-05 的两条裁决不再由程序强制：
  - 未审的适配器试跑只能读 QQ；
  - 局域网设备一台一台开。
- 资源限制（CPU、内存、文件大小）没有了，只剩超时和输出上限。
- 删掉的测试：网络和凭据隔离、只读源、中继和守卫、命名空间里的用户条目。删掉的诊断工具：三个 WSL 探针。
