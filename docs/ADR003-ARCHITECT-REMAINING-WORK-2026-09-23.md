# ADR-003 V2.2 未完成工作与验收裁定材料

**提交架构师审阅｜2026-09-23（Pacific/Auckland）**

本文按现行 Web UI 入口与 ADR-003 V2.2 的 A→B→C→D→E 顺序整理。架构师无需访问代码即可判断每项的设计要求、已观察结果与缺口。本文是进度和验收建议，不自行改变原验收标准，也不把平台接受、任务 `RETURNED` 或计划到期等同于用户可见效果或实际成长。

## 当前结论

宿主 A 与 QQ 接入 B 已形成可运行基线；N1、N2 有真实 QQ 入站、出站和平台回执，N3 按既有阶段裁定已通过。原生行动循环、QQ 私聊与续接、可选 `consult_character`、原生压缩和原反馈续接均保留。咨询只是行动脑可选择取得角色内部判断的能力，不要求每项任务调用，不新领 RUNNING 任务，不公开一条 QQ 回复，也不自动产生新目标；其专项已结束。

**ADR-003 尚未完整验收。** C 的 N4–N6 各有部分真实证据，仍缺组合场景或关键结果；D 的 N7 有实际无输入到期与固定间隔创建／取消，N8 的原定时链自主改进仍未成立；E 的本机私聊自动总结已有局部接线，但个人／群偏好闭环尚未交付。现有基线可以继续使用和开发，不应因这些缺口回滚 N3 或暂停整个服务。最近一次只读状态核对没有活动中的行动任务或计划；后续操作仍应先核对现场状态。

## 为什么反馈修复不能算 N8

原定时行动的反馈 episode 为 `ep-8684cf79da18d2bf0648815fc93c0a44`。实际请求设 `max_tokens=4096`，上游报告 `prompt_tokens=68578`、`completion_tokens=30`、`total_tokens=68608`，恰达已配置的 68,608 上下文容量；HTTP 200、结束原因 `length`。这是输出空间仅余 30 token 后的截断，区别于 C3 曾见的 `INPUT_BUDGET_EXCEEDED` 宿主额外门槛，也区别于上游 HTTP 400 输入溢出和 JSON 协议缺项。最终反馈用户段长 42,387 字；DSH 原生 `agent/pre-step` 压力检查发生在该段写入会话表面之前，不能把这次新增输入计入本步压力。2026-09-23 已补窄接线：在同一个 pre-step 里，把已领取、尚未附加的输入交给 DSH token meter 估计，与原生 0.8 压力阈值和预留输出预算核对；过阈值时调用同一个原生压缩引擎处理已闭合历史，再让原消息进入原请求。不重新建立硬预算拒绝，不提高 `max_tokens`，不对满窗口重复续写。隔离数据库＋真实 DSH＋本机假模型接口的探针观察到两次正常生成之间恰有一次原生摘要；相应回归及相关局部测试共 26 项通过。该探针证明接线可行，尚未把补丁加载到正式 Web 宿主或以真实模型重演 68k 边界。

原先 `FAILED_PROTOCOL` 还被错误传播为反馈无资格再排队。此前已补 `advance`、feedback 和既有队列的接线：保留失败输出与原任务结果，把同一内部反馈继续交给原角色会话。现场原反馈完成，任务仍 `RETURNED`、反馈 `DELIVERED`。未加专用一次重试、固定终止次数、新恢复 agent 或新用户消息。这消除了反馈生命周期阻断，却不证明角色沿原定时目标完成了成长。

## 下一步的重点与建议顺序

1. **先关 C 的实际验收缺口。** 使用现有授权群和参与者观察 N4 的双人交错话题与回复归属；缺第二真人时可做同宿主受控重放并标清来源，真实多人状态保留 `BLOCKED_EXTERNAL`。N5 定点处理已发生的 `get_msg` 越界面：只读源码核对确认 owner 的 `integration_test` 仍可通过原始 NapCat `/api` 发送任意动作，所以 adapter 的自身消息 ID 约束不是宿主实际访问边界。后续在保持正常授权工具和排错能力的前提下，限定该已知读面；不再对任意历史 ID 做线上试读，不建大安全专项。让 N6 已保存的长消息离开近期尾部后自然提问，并分别核对尚缺的恢复和发送证据。只修观察到的缺口。
2. **随后完成 D 的 N8。** 从真实 QQ 使用问题或用户具体体验反馈出发，交由小满自己判断并选一个有用途的改善；观察真实修改、执行结果、角色经验／能力的持久更新、重启后自然复用及“只聊天不查工具”。已有 adapter 0.2.3 可作为技术基础，但人工任务不能替代新的自主链。计划到期与任务 `RETURNED` 只记录各自阶段，不写作成长完成。
3. **并行推进 E 的独立个人部分。** 已有自动摘要接线先通过正式 Web 的自然交流核对事实和主体归属，再在现有状态版本上补个人偏好、明确更正与重启后的实际使用。群偏好等到可信多人场景，区分个人意见、明确约定与观察倾向。后台整理失败不阻断聊天，不重建上下文管理器，也不预写成长脚本。

## 关于略过尚未测试部分的建议裁定

**可以省去同等条件下的重复运行，不能省去缺失的行为结果。** N1/N2、已裁定 N3、咨询专项、四群邀请、原生压缩、N7 的一次真实无输入到期与 300 秒计划创建／取消、原反馈定点续接已有直接证据；若代码与配置未改变相应路径，不必再为这些项目做裸 DSH 对照、重复采样、咨询能力矩阵、额外群发或多次计时。验收对话的措辞是示例，真实自然交流覆盖同一行为即可，不必逐字复演。

侧面证据支持**可完成性**，不能替代这些首次结果：OneBot 平台接受 at 段不能证明 QQ 客户端提醒；回复上下文字段和一次正确回答不能证明 A/B 交错全链；34 次无 canary 不能证明所有跨范围入口；长文 READY、只读向量选中尾块与另一短记忆重启召回不能证明该长文离开短期尾部后的自然召回；原生定时到期、人工任务的 adapter 改动和原反馈恢复不能证明 N8；自动摘要的本机假模型探针不能证明真实总结质量或偏好更正。因此建议保留 N4–N6、N8、B1–B2 的未测项为 `PARTIAL`／`NOT_RUN` 或确实缺外部参与者时的 `BLOCKED_EXTERNAL`，不以 SOURCE_REVIEW、受控重放或旁证改写为 `REAL_QQ`。若架构师决定改变完整 ADR-003 的验收范围，需要明确修改该范围；在现行要求下，不能以略过这些首次验证宣称全部完成。
