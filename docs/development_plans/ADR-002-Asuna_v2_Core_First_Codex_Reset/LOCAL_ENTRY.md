# 本机入口：必须真正交到用户手里

**这是 Codex 要实现并现场验证的交付要求，不是本包已带有可运行 Asuna 的声明。**

## 1. 选定最小入口，不再让用户选择模式

第一入口采用常驻终端聊天，目标命令 `asuna chat`。可以复用已有入口名，但必须在交付的 `RUN_ASUNA.md` 写出真实命令。不要另造 Web UI；若现有界面能够无额外平台工程地接入同一核心，可稍后复用，不能成为现在的前置。

一次配置：本地用户身份、默认私聊场景、实际模型路由、Asuna 数据库、授权工作区、技能持久目录。以后启动不要求用户重复输入 JSON、scene ID、workspace 或数据库名。

普通使用只有：启动 → 自然语言交流 → 需要时看 trace → 退出。聊天、回忆、行动与反馈在同一个入口，不分“工具模式”和“聊天模式”。

## 2. 常驻必须是真的

Application 与必要模型会话在整个交互期间复用；每句话不重新创建两条 DSH 进程，不更换 preset，也不重新铺满系统前缀。人格/关系变更通过明确的后续状态注入，保留现有缓存友好路径。

终端输入接收不被模型或工具阻塞。采用已有线程／异步队列即可，不开发分布式调度。Gemma 同场景生成有序；等待 Qwen 时可以处理新的普通交流，工具结果作为独立事件返回原场景。

若已有同步 SDK，先把阻塞工作放到已有或最薄的 worker；不要为了入口重写 SDK。硬件一次只能执行一个模型时如实标明等待，不能把线程存在写成推理并行。用户按回车后消息至少已进入队列，不能丢到工具输出里。

终端刷新不能把正在输入的文字覆盖、把两段模型流混在一起。只显示本次新发布的内容，不每轮重印数据库全部历史。

## 3. 默认显示什么

默认会话画面示意只包含用户输入，例如：

```text
你：小满，我回来了。今天没什么要你做的。
小满：（这里必须是 Gemma 实际生成的公开回复，本包不提供标准答案）
你：先帮我看看笔记里备用线放哪儿了，别改原笔记。
```

角色名称来自配置，不强制以“小满”做任务关键词。先发言或等事实由角色决定，不用固定应答造“秒回”。确实需要的系统状态可标成 `[系统]`，例如连接失败；不能伪装成角色发言。

无任务的闲聊不启动例行维护。独白、DECIDE 内容、Qwen 原始助手答案、thinking、SDK 事件和工具日志默认不混进对话。Gemma 请求列表或技术说明时可自然采用相应格式；不要为所有场景强制三行或禁止 Markdown。

默认只提供 `/help`、`/trace`、`/quit`。这些是程序命令，不进入角色记忆，不调用模型。自然语言任务取消仍经过正常交互；如已有可靠的管理取消命令可复用，不强制新造一套。

## 4. 展开 trace：看实际发生的事

`/trace` 展示最近这次交互的可读时间线，并能指向原记录：

- 实际使用的人设和召回内容，注明来源；不是只显示哈希。
- Gemma 的独立 monologue、意图与实际发言。
- Qwen 的工具、命令、关键输出、原始错误及如何继续。
- 新增／修改的记忆与技能；真正的发布状态。

只展开允许查看的场景。凭据值脱敏，但异常类型、位置、原因、stderr 和 traceback 不得被统一替换成空泛提示。DSH 没给 traceback 时保留原始错误体，不虚构调用栈。

不重复调用模型“解释刚才为什么这样做”来代替日志。失败的发言、空输出和明确沉默必须能区分。

## 5. 本机与实际运行环境必须说清楚

Codex 从现有配置判断代码实际运行于 Windows、WSL、容器还是另一个已连接的主机。不要为了方便迁移环境，也不要把容器里的路径直接交给 Windows 用户当本机命令。

**只为实际采用的路径制作一个可用启动脚本：**

- Windows 使用：例如 `start-asuna.cmd`／PowerShell 入口，可以连接已经存在的容器或 WSL；填入已核实的目标，并保留交互终端。
- Linux／WSL 使用：例如 `start-asuna.sh`，进入实际仓库，调用已配置的环境和聊天命令。
- 已在其他运行主机上：沿用用户已有连接方式，明确“哪个终端执行什么”，不新建公网服务。

以上文件名是交付要求，不是在本包里伪造一份能找到本机环境的脚本。启动器不应每次重装依赖、拉取代码、重置记忆或升级 DSH。密码/token 不写进脚本或命令行，配置来源只记位置和变量名。

若需要一次性准备，Codex 在本机做并记录；交付后用户不需要每轮 source 配置或调起 executor。

## 6. 退出与恢复

V1 的 `/quit` 结束本次前台应用；未结束任务必须明确停止或保留为未完成，不假称后台仍工作。保存已发生的消息和状态；不要等一项无关长任务结束才允许退出，也不能误杀其他应用的进程。

重开同一入口恢复同一用户和场景，不复位人格／记忆。输入一条不在最近上下文中的问题，验证实际检索；单纯重新加载全部旧 transcript 不算向量召回证明。

V2 中 QQ 适配器需要常驻时，采用单一宿主的服务生命周期：聊天客户端退出与整个服务停止分开，详见 `CHANNEL_SEAM.md`。这项拆分在 V2 需要时实现，不阻塞 V1 的前台入口。

## 7. 现场交付检查（不是新测试平台）

Codex 必须从用户实际能使用的启动路径启动一次，输入三条中文，其中包含一次追问；确认不会每轮初始化，不回显 JSON，不丢文字。

再从这个**同一入口**完成一次真实工具往返和一次记忆提问，不能换成直接调用 executor 的测试脚本。用户可以自行继续输入，入口不随着演示脚本结束自动消失。

最后用 [启动说明模板](templates/RUN_ASUNA.template.md) 生成仓库内的 `RUN_ASUNA.md`，填入实际命令、停止方法、配置位置、可用/未实现功能和错误查看办法。P1-A 刚完成即可交一版，后续阶段更新状态，绝不把部分完成写成“所有功能已就绪”。
