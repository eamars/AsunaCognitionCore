## UI 原生复用原则（ADR-006，长期有效）

Asuna 扩展 DSH，不另建一套相似的 UI 控件库。

**非必要禁止增加自定义控件。只有固定版本 DSH 不提供可满足需求的类似控件时，给出充分具体的理由，才可提出自定义设计。** “更方便”“更漂亮”“统一架构”“数据不同”或“以后可能用到”不是足够理由。

实施顺序：复用现成功能视图／slot → 复用公开组件和受支持组合方式 → 补最小数据绑定或 Asuna 语义标签。仍无法满足才提出自定义方案，不先做完再补理由，不自己批准。

理由只放现有设计说明或 diff：查过的固定版包／导出／props；需要但不存在的行为；为何现有组合解决不了；新增控件的最小范围；如何保留原生交互及移除重复代码。设计者给出方案、用户确认，实施者执行。不得建设理由 schema、审批服务、模型评审或运行时闸门。

下列不属于“复用原生”：照截图抄一套 CSS、复制私有组件、从压缩 bundle 抠组件、依赖未导出路径、用若干原生按钮包住全新的自绘会话列表、升级 DSH 来回避本地约束。

已批准的 Asuna 专有语义适配（如脑来源／阶段／场景映射）不需要逐行请示，但它不授权新视觉系统或改变 agent 行为。真正的技术阻塞只限制该局部交付，不停止已有模型、工具和 QQ 服务。

本原则是开发期设计规则，不进入 Gemma 人设或 Qwen 工具 prompt。不得让运行中的小满为每次操作提交“UI 合规理由”。ADR-003.1 的原生能力不受扩展层无理由限制原则继续有效。
