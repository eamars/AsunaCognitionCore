# ADR-004 功能提案：可查询的记忆与真实世界互动

**提交架构师制定开发包｜2026-09-23｜状态：Proposal，尚非实施指令或验收结论**

> 仓库中已有 `ADR-004-asuna_ui_elements_v1_kit`，其范围是 Web UI Elements V1。本提案沿用用户指定的“ADR-004”称呼；请架构师确定正式编号或子编号，避免把功能开发误并入现有 UI 包。

## 用户要求与本次纠正

用户希望 Asuna 从“QQ 可以收发、能运行工具和定时器”继续走向日常可用的角色应用，具体提出：聊天记录查询、向量搜索、关键词查询、表情包、自由定时任务、群友要求整理群聊、好感度系统，以及 ADR-003 Bonus 的自动总结、个人偏好与群约定。用户进一步要求话题追踪、主动加入话题、主动发言冷却时间等更接近人类聊天节奏的能力。

**偏好和约定的功能验证不必等待第二位真人。** 可以把具有不同可信身份、群、私聊和回复关系的模拟事件注入同一宿主入口，在隔离数据库中验证来源归属、更正、状态更新、恢复和实际使用。记录应标注为受控注入，不能把它写成真实 QQ 多人平台验收。上线后再观察真实多人体验即可。模拟数据必须保留说话人和原文，不能直接往目标偏好状态写“正确答案”来冒充提取成功。

用户目前没有在产品中看到表情包、自由定时、群聊整理和好感度的实际表现；这属于明确的体验缺口，不应以底层函数、旧原型或离线探针替代交付。

## 建议纳入开发包的能力与可观察结果

### 1. 可查询的聊天历史与记忆

让用户自然地问“上周在这个群讨论过什么”“谁提到过相机抽屉”“找出含这个词的原话”，也能在 Web 检查查询结果。支持按场景、人物、时间和关键词查原始消息；语义查询复用现有向量检索和索引；结果带原文、时间、发言者、场景、回复链和可点击／可追踪的来源，不把模型总结伪装为原话。未索引、无结果和检索故障应如实呈现。对同一输入分别证明精确词命中与非字面语义命中，且范围外来源不会混入。现有检索函数是底座，开发包应核对其覆盖的是 `memory_units` 而非完整聊天记录，决定原文查询的薄接口及必要索引，避免另造第二套记忆库。

### 2. ADR-003 Bonus 的总结、个人偏好与群约定闭环

自动总结在对话批次或安静间隔后低优先级执行，附宿主生成的来源窗口、人物、场景、实际发送确认和时间；用户按需要求总结是另一入口，不能替代自动触发。A、B、小满各自的偏好，以及角色对人的关系理解，要分别保存。群内一个人的主张不能直接成为全群约定；明确约定与观察倾向分开。后来的更正更新当前版本，旧记录保留为历史；重启和后续自然回复使用当前版本。

验收可在隔离数据库里通过宿主注入模拟 A/B、群和私聊原始事件，经过真实的整理／状态更新路径，再从 Web 查看来源和后续行为。需要有“原文→自动整理→明确更正→当前状态→重启后应用”的证据，而不是直接 seed 最终状态。真人多人平台体验另记上线后观察，不阻挡功能开发与受控验收。

### 3. 表情包与媒体互动

明确接收、理解可用的图片／表情信息，以及从可用候选中选择并实际发送表情包的边界。角色可以在适合的聊天语境里自然使用，而非每次回复都发图；用户可通过真实 Web／QQ 路径看到发送对象、平台回执和实际内容。媒体记录应区分“看到候选”“选中候选”“平台接受”“用户可见”，避免仅写“看过图”标记就宣称理解或发送成功。请架构师确定首批支持的 OneBot/NapCat 媒体格式、素材来源与失败回退。

### 4. 自由定时任务与到期行动

在现有 DSH 原生计划、宿主 owner／范围和角色阶段上，支持用户以自然语言安排一次性及合理重复任务，查看、修改或取消，届时由角色判断并执行适用行动，结果回到原场景。保留创建时授权和到期时复核，错过时间、取消及失败状态可见。不把提醒文本或计划触发本身当成任务完成，也不为此再建一个调度器。验收应覆盖一个用户自选的真实用途，而不是仅重复 ADR-003 的两分钟测试词句。

### 5. 群友按需要求整理群聊

群友可在当前群请求“整理刚才／今天关于某事的讨论”。从当前授权群的可读记录选取有界来源，保留参与者、话题、未决项和明确更正；摘要回当前群或由角色按现有发布路径回应，能追溯所依据原话。不把其他群或私聊内容混入，也不把某位群友的推断写成群决定。可以先以模拟多人群事件验证完整路径，再在上线后的真实群里验证可读性和平台效果。此按需功能与后台自动群话题整理共用来源和状态，但触发、输出和完成记录应分清。

### 6. 好感度／关系动态

用户明确要求能感受到关系随互动变化，而当前只有关系文字修订的基础，尚没有可观察的“好感度系统”。请架构师决定它采用**可解释的关系状态、可见数值，或两者结合**；这涉及产品表达，不应由实施者临时把每句话计分。无论形式如何，变化应有实际互动来源、适用人物和场景，并允许误读后更正；不能从单条转述推断对方态度，也不能把好感度用作授权或访问控制。验证应展示一次有根据的变化、一次无根据时不强行变化、重启后保持，并在自然对话中体现而非只在数据库中加一行。

### 7. 话题追踪与有分寸的主动参与

在同一场景里追踪同时存在的话题、参与者、最近的回复对象与尚未回应的问题；新消息要能接上原话题或识别转移，不把群里一句回复误接到另一人的任务。适当时小满可以主动加入正在进行的对话、回应有意思的变化或提出自然的问题；也应能判断别人在彼此交谈、话题已经结束或没有必要插话，从而保持安静。主动参与应沿已有角色阶段、消息发布与授权路径，不由行动脑或定时器绕过角色直接发群消息。

需要为**主动发言**设置可解释的冷却和频率约束：短时间连续群消息、已经被忽略的主动话题、深夜或群里密集交流时，减少再次打断；有人直接提问或明确提及她时，仍可正常回答。冷却应按场景、事件与发言结果起作用，不成为固定“每隔 N 分钟必说一句”的脚本，也不让沉默被误判为服务停止。请架构师裁定是否允许在没有新消息时主动重开旧话题，以及默认启用范围；这与用户明确授权的定时任务是不同能力。

可先用模拟多人物、多话题、回复链和时间间隔的事件序列验证“接对话题、该加入时加入、应安静时安静、冷却后仍能响应直接请求”；上线后再观察真实群的打扰程度和用户反馈。记录实际触发、角色判断、发送或不发送的结果，不要求角色每次公开解释自己为什么沉默。

## 建议架构师作出的范围裁定

1. **编号与交接：** 与现存 UI Elements V1 的 ADR-004 名称分开；决定本提案的正式编号和开发包位置。
2. **ADR-003 Bonus 归属：** 明确 E/B1–B2 是在 ADR-003 收尾，还是作为本开发包的承接项；不得在报告里把未完成项静默改为已完成。ADR-003 的已知 `get_msg` 越界面、长消息自然召回和 N8 自主成长缺口仍按原记录处理，不因新功能提案消失。
3. **优先级：** 建议先把历史查询和自动总结／偏好用于真实日常需求，再接话题追踪与主动参与、群友按需整理、自由定时和媒体，最后结合可用的关系状态呈现好感度。架构师可按产品价值调整顺序；不要要求固定双脑顺序或每次工具操作先咨询。
4. **首版产品选择：** 指定好感度的表现形式、表情包素材／格式、查询的最大时间范围与分页、自由定时可接受的重复规则、群总结的默认来源窗口，以及主动参与的默认场景、冷却语义和无新消息时是否允许主动开题。开发包可据此写最小验收，而不是让代码自行决定产品语义。
5. **证据边界：** 模拟身份／事件注入足以验证偏好、约定、查询和群总结的功能逻辑；真实 QQ 多人体验作为上线后补验。受控注入仍经过宿主，不可直接写答案；浏览器中的正式可见结果、原始工具过程和错误照实保留。

## 开发边界

复用现有 Mongo 原文、分块／索引／检索、DSH 工具与消息机制、原生定时、角色与行动路径、Web UI 和 QQ adapter。新增的是产品能力及必要宿主接线；不重建上下文管理器、不以新上下文代替长期运行修复、不要求逐句审批，不让好感度或群约定改变宿主授权。现有 QQ 私聊、反馈续接和可选角色咨询继续工作。

本提案提交的是需求、现状和建议裁定点；架构师据此生成可执行 ADR-004 开发包和验收范围。
