# 给用户：V2.2 怎样使用

本文件描述目标使用方式，不是声称命令已经安装。Codex必须在你的实际Windows环境填写并验证`RUN_ASUNA.md`，保留原`start-asuna.cmd`的便利。

2026-09-21 修订：当前 `start-asuna.cmd` 统一启动 Web 宿主，日常使用、开发调试呈现和交互验收都在 Web UI。CLI 仅显式 debug/维护；下文 QQ 是尚待接通的后续目标，不是当前另一个正式入口。

## 先配置一次

Codex读取并妥善保存现有本地NapCat地址/token，核对登录账号；你只需确认由哪个QQ私聊测试、是否与旧bot共用同一账号，以及之后允许哪个群。固定LAN token可以保留，不需要每次聊天审批。

本包的候选配置来自旧裸DSH原型，不自动登录或发送。若实例实际值不同，以本机当前配置为准。QQ扫码由你完成，不能通过“自主开发”绕过登录授权。

## 第一段：让她开发QQ

在 Asuna Web UI 聊天区发送 [这段任务](tasks/ASK_XIAOMAN_BUILD_QQ.md)。她应明确进入执行，而不是只答应以后做。开发期间照常聊天；报错由行动脑继续解决，缺必要配置时再问你。

一旦私聊接通，你就可以说：“小满，我从QQ来找你了。”不需要输入工具指令、scope、task ID或先去本机按回车。

## 日常

闲聊、查资料、小任务都从同一处说。你可以直接说“先别给建议，陪我说几句”“帮我核对一下，别动原文件”“这个做法挺好，以后可以保留”。不需要分别找Gemma和Qwen。

本机客户端可以关闭，前提是已明确启动的Asuna宿主还在。Codex要提供启动/停止宿主与adapter的方法；停掉整个服务后当然不会继续工作。

## 自主计划

定时功能交付后，正常说“这件事晚点自己继续”“每三个小时空闲时想想还有什么值得改进，没必要就别硬改”。真正的计划应由程序登记，原生DSH到期事件唤醒；不是她只在聊天里说“记下了”。

## 记忆与偏好

正常告诉她新信息即可。Bonus交付后，你可以问“刚才我们聊了哪些事”“你觉得这个群平时喜欢怎样交流”。她应区分事实、你的偏好、她的看法和群倾向，不要求你给好感度打分。

调试在本机 Web UI 的“内部执行过程”和右侧检查器查看；必要的底层 CLI 诊断只在显式 debug 层使用，不用终端聊天替代 Web。QQ普通消息不应能获取别人的私聊/独白、system prompt、token或全库记录。你本机管理身份有更大权限，但不要把公开群当作私密管理终端。

## 你应收到的交付

实际可用的启动、停止、查看错误办法；一段QQ真实对话；一段任务往返；一次新记忆恢复；一次定时自主活动与实际成长。总结/群偏好若未完成，明确列出，不影响已可用的私聊先交给你。
