# 阶段异常与继续推进规则

本规则补充 `V2_2_PLAN.md` 的正常推进流程。A → B → C → D → E 是默认顺序；缺少外部条件时，按真实依赖继续独立工作，不把未完成阶段记为通过。本文是开发要求，不代表能力已实现或验收已完成。

## 1. 统一处理与状态

每阶段开始先核对当前源码和运行事实，列出已有、缺失和未验证项；计划中的旧源码描述不是当前缺口的证明。开发任务、观察和交互验收使用现有 Web UI；QQ 接通后补真实 QQ 验证。Shell 诊断、受控重放和源码检查不能替代真实交互。

| 状态 | 含义 |
|---|---|
| VERIFIED | 指定范围内的验收已实际完成，附证据来源与适用场景 |
| PARTIAL | 部分能力已验证，其余尚未完成或发生实现故障 |
| BLOCKED_EXTERNAL | 明确缺少登录、账号、测试群或外部服务等条件，列出待补条件 |
| NOT_RUN | 尚未执行该项验收，不推断成功或失败 |

状态按子项记录，例如“私聊 VERIFIED；群路由重放 VERIFIED；真实群聊 BLOCKED_EXTERNAL”。受控重放通过不使整个群聊阶段 VERIFIED；本机验证不使 QQ 能力 VERIFIED。程序错误属于待修实现问题，不能归为外部阻塞。

每次失败保留实际现象、最相关的原始错误、所属层和下一项验证。普通实现错误由原开发回路继续修；宿主缺接口或授权环境不符合任务时由 Codex 修基础设施。相同失败再次出现且没有新证据时，先检查契约、依赖和工具能力，改变有依据的修复方式，不原样重复任务、不换 seed 求成功。

仅缺必要外部信息时集中询问一次；等待期间继续不依赖该答案的工作。未获授权的账号、群和发送目标不由候选配置或模型猜测补齐。每次回报只突出一个当前主要阻塞和一个紧邻动作，其余未验证项留在状态表中。

## 2. A：宿主基础设施

**前置核对**：当前 Web 启动、配置、模型路由、Mongo、DSH 会话/技能与宿主生命周期。角色脑和行动脑按实际独立配置核对，不绑定历史模型名。

**必要结果**：输入先持久化再排队；接收不等待模型；身份和范围由宿主绑定；公开输出与实际回执分开；重启可恢复已接收未处理项；关闭浏览器不停止已明确启动的宿主；实际接口说明可供开发使用。

**条件缺失**：缺配置或服务时列出具体依赖，保留既有数据，不 seed/reset。可以继续接口实现及非交互诊断，但模型/数据库不可用时不能宣称完整认知、持久化或 Web 验收通过。缺旧 DSH 历史时明确使用新上下文恢复已有记忆，不宣称恢复原会话。

**失败与恢复**：变更前记下可用启动方式、实际配置引用和需要恢复的版本；数据库改动优先增量兼容。失败时恢复本次变更影响的可用版本/配置，不覆盖已有记忆或其他人的改动。若无法安全回退数据变更，保留故障现场并修复，不用整库重置代替恢复。

**继续条件**：B 的真实试运行依赖实际宿主接口、持久开发目录和受管理 runner 可用。仅有接口草稿时可准备文档，不能把完整 adapter 实现任务交给小满后让她猜缺失能力。

## 3. B：小满自主开发 QQ adapter

**前置条件**：A 的必要接口与集成环境可用；有指定 NapCat 连接、已核实账号和至少一个明确授权的私聊目标。缺登录或目标时可继续准备开发环境与离线协议检查，真实收发标为 BLOCKED_EXTERNAL，不尝试未知对象。

**允许自主选择**：传输方式、依赖与代码组织只要符合实际 NapCat 配置及宿主契约即可。与计划示例不同不等于偏离目标；只约束必须成立的行为，不逐行指定实现。

**三个检查点**：

1. 开发初期：由小满在原会话说明消息如何进入宿主、公开输出如何发送、回执如何关联、进程如何持续运行。Codex 对照实际契约指出缺项；这是开发反馈，不增加逐步人工审批。
2. 最小收发：在受管理试运行中验证一条真实入站、一条角色公开输出及对应平台回执。失败保留原始错误，在原行动会话修复。
3. 持续运行：验证连续消息、任务期间再聊天、客户端关闭、adapter 重启及错误呈现，再按已有授权启用。N1–N3 成立后立即交付私聊。

**必须纠正的偏离**：另写回显机器人、行动脑代替角色直接答复、绕过宿主发布/权限、收件等待整轮模型、把连接成功当发送成功、自动开放全部群。指出可观察的违约行为与预期结果，让小满修正；此版本不得进入正式启用。若已启用且出现错目标发送或越权，停止受影响的 adapter/功能并保留证据，不扩大影响。

**失败版本与持续失败**：开发目录、试运行与启用目录分离；半写文件不自动上线；保留此前可用版本。普通错误继续交给原行动会话；宿主问题由 Codex 修。持续无法完成时报告 PARTIAL、实际缺口与下一项诊断，不偷偷代写再算自主成功。确有共同开发时标明各自贡献，N1 自主开发结论单独评估。

## 4. C：群聊条件缺失与补验

**前置条件**：B 私聊可用；真实群验收需要一个明确授权的测试群及两位可识别参与者。开放额外参与者前，先完成 N5 所需的隔离检查；群缺失不降低权限要求。

**没有群或第二位参与者**：通过同一宿主入口进行隔离的受控重放，验证场景/身份映射、回复链、交错话题、事件去重、输入完整性、恢复和跨 scope 过滤。重放不得指向未授权真实目标，测试数据与真实人物记忆分开。记录为 LOCAL_HOST_REPLAY，真实群聊项为 BLOCKED_EXTERNAL。

**仍可交付**：已验证私聊继续使用；长消息、新记忆恢复和实际阈值压缩可先在已授权私聊或本机验证，写明范围。不能由这些结果推断真实群平台行为、多账号身份或群偏好已通过。

**继续与补验**：在宿主可靠持久化、当前场景隔离和计划授权机制满足要求后，D 可在本机或已授权私聊继续；E 可在其实际依赖满足后验证个人总结/偏好。获得测试群后补做 N4–N6 的真实群部分及 N5 必要检查，不为补验重跑已无变化的全部 V1。

## 5. D：定时触发与成长分别验收

**前置条件**：宿主事件与恢复路径可用、计划范围可确定、DSH 原生定时桥可接入。缺测试群不阻止本机/私聊计划；缺 QQ 时可提前验证本机定时基础，但不声明 QQ 成长已完成。不得用另一个调度器或人工发消息冒充 DSH 到期。

**分开记录**：计划创建、无人输入时实际触发、角色判断、实际改善、重启后复用、取消分别给出状态。只有触发而没有有效改善时，报告“触发 VERIFIED；成长 PARTIAL/NOT_RUN”，不将 N7 成功等同 N8 成功。

**无改善或失败**：角色可以合理选择不改；保留判断，再从真实使用困难或具体反馈中继续，不编造问题、不预写成长脚本。优先用 QQ 经历；QQ 条件缺失时可使用实际本机/私聊经历，明确来源和验收范围。行动错误留原会话修，桥接错误由 Codex 修；计划取消和权限复核仍必须成立。

**继续条件**：定时桥暂时受阻不停止已可用 QQ；E 的独立后台整理不依赖定时成长成功，可以在消息来源、隔离和持久化已可靠时推进，D 缺口继续保留。

## 6. E：证据不足、错误修订与缺群

**前置条件**：适用场景身份、来源、原文与实际发布状态可靠，后台整理受同一 scope 限制。默认在 QQ 与定时成长后做；上游仅缺外部条件或独立定时能力时，可按本规则先验证本机/私聊子项，不挤占当前可推进的私聊交付。

**触发与失败**：沿用 `MEMORY_AND_PREFERENCES.md` 的完整交流、消息批次、安静间隔或按需整理。实施时选定实际触发条件、有限批次和处理位置，写进使用说明；后台资源忙或失败时保留原文与待整理状态，不阻断聊天。按需生成成功不能替代自动整理验收。

**证据不足**：主体不明或只是推断时不强行更新偏好，不把个人意见升级成群约定；可以保留有来源、明确不确定性的描述。没有新证据时不反复生成相同结论。

**错误修订**：以原文和明确更正修订当前版本，标记旧理解已被取代；检索及后续上下文不得继续把已失效偏好当现行事实。保留可查的修订关系和来源，原始记录仍遵守既有删除语义。恢复后再次验证当前版本实际生效，不能只验证数据库多了一行。

**缺群或多人条件**：个人偏好可独立验收；多人归属、真实群约定及群内效果保留为 BLOCKED_EXTERNAL/NOT_RUN。群偏好受控重放只证明实现行为。Bonus 按子项报告，不拖住已可用交付。

## 7. 每阶段最小回报

沿用 `REPORT_TEMPLATE.md`，列出已可用能力、各子项状态与证据来源、实际失败和修复归属、外部待补条件、恢复办法、当前主要阻塞及唯一下一步。允许继续的阶段必须写明依赖已满足的依据；禁止用整体“通过”掩盖待补验项目。
