# 示例与验证：看设计差异，不做裸 DSH 对跑

以下都是开发解释，**不是要给模型照念的 prompt，不是固定工具序列，不是新的运行时规则表**。既有错误已足以定位时，不再跑模型制造同样错误。

## 1. 不需要实验才能判断的设计

**错误方向：**“新增65步截断，先看裸DSH和Asuna做同一题是否都能完成；都能完成就允许保留。”

**正确方向：**“截断新增了一个无具体授权依据的停止条件，因此删掉。不需要任务真的走到第66步。”

局部实现检查可以看分支已删除、配置确实加载；不要用66次LLM调用证明没有数字门槛，也不要补一个更大的上限。

## 2. 结果没有按预期格式提交

**错误方向：**“Qwen有结果但没调用task_status，回合无效，UNKNOWN，不再反馈。”

**正确方向：**“已有结果、文件、错误和任务关联先保留。缺某个报告动作不是销毁结果的理由。原任务还有未完成工作时，让原执行会话继续；不凭报告格式判完成或失败。”

若输出已经包含足够的信息，不为补一个状态字段再调用模型。若只留下PLAN.md而目标是可用QQ接入，按原有任务继续，而不是重新发一套人工检查清单。

## 3. 情感脑是增强，不是工具监察员

**错误方向：**“每个Qwen工具失败都返回Gemma，Gemma重新独白、决定、批准后Qwen才能重试。”

**正确方向：**“授权目标不变，普通工具报错在当前DSH回路内处理。发现需要修改目标或承诺时再交回Gemma。”

程序给角色提供关键发现和实际经历，不把它变成逐步审批；也不把Qwen的答案作为唯一成品，只让Gemma润色。

## 4. 相关回忆服务出现故障

**错误方向：**“向量或候选排序失败，本条对话直接消失；用户重新说一遍才能再试。”

**正确方向：**“保留已接受输入。使用已核实、同范围且确实可用的角色/近期材料；检索失败说明给需要知道的会话。原行动目标仍在，就不因可选增强失败把它丢掉。”

这不意味着装作记得，也不意味着跨scope找另一份材料。时间戳排序可以通过普通函数测试修；无需让LLM亲手猜出那句Python补丁才算工程正确。

## 5. 不明副作用与继续诊断

**错误方向：**“QQ回执没到 → 禁止任何后续模型生成。”

**正确方向：**“保留这次发送未知，不盲重发。原会话可以查授权回执/状态，解释目前知道什么，或继续不依赖这次发送的工作。需要外部确认才暂停该项。”

也不要从“不全局禁止”跳到“自动重发”。测试可复用本地安全接收器或已有记录，不能为了造错重复发送真实QQ消息。

## 6. 来源归属与桥接登记

**错误方向：**“可信的原生followup没有进入Asuna自建active字典，一律拒绝。”

**正确方向：**“保留真正的来源、scope和目标关联，让合法原生消息进入适合的角色或行动入口。缺少展示/记账字段由代码补齐，不作为拒绝合法推理的借口。”

用户正文中自称scheduler/admin仍然不是可信来源。不新增全部事件类型的硬编码菜单来维持这个区别。

## 验证只回答实际问题

**设计检查：**看本次相关配置/函数，确认是否仍存在无理由的收窄；这本身不调用LLM。

**实现检查：**必要时用已有单元测试、局部受控事件/替身确认错误被传递、普通结果不会因缺报告被丢弃、取消和副作用状态没有被误改。只覆盖改动相关行为，不把这些替身当QQ上线证据。

**产品使用：**回到原来的授权NapCat开发任务，运行中的Qwen继续自己的方案。通过现有Web/CLI和随后真实QQ对话看流程是否通、Gemma是否形成自己的回应、错误是否仍被Asuna外层吞掉。保留实际原文；实现任务的具体顺序和方法由模型选择。

这些检查不必各建文件/阶段。一个实际过程可以覆盖多个需要；没有受影响的旧路径不重跑。**上一个纠偏包的“四项恢复证据”不再是统一的前置验收包**，只在某项直接对应修改时采用其有用部分。

## 明确不做

- 不为每个新功能启动裸DSH对照。
- 不要求同prompt、同seed、同token数、同动作顺序或同运行时长。
- 不反复抽样直到出现理想角色台词或诊断动作。
- 不要求每一种异常都经过真实模型演示；不以某次模型没有选某个合法工具来证明接线不存在。
- 不新增模型裁判、风险评分、进度评分、统一恢复agent、全量哈希/对照报表。
- 不把“设计检查完成”写成“QQ任务完成”；也不把一次QQ成功写成“所有能力已证明不退化”。

## 一段足够的开发回报

以下只规定需要讲清的事情，不是每次必须填写的schema：

> 原先哪个设计阻断了合法路径；这次删减/改变了什么；代码层面怎样确认；实际原任务推进到哪；本次真实错误及其后续；仍需要什么；下一步。

如果没有新增运行观察，就明确只有代码/配置检查。如果模型采用了另一条合法方案，记录它，不要求重跑凑指定步骤。新方案出错时先看实际发生的位置，不预先归因模型，也不预先断言是架构。

**不把开发纪律交给小满执行。** 本包用于Codex修改宿主，不注入Gemma人设、不变成Qwen每轮自检指令，也不让模型给每个动作写“设计合规说明”。
