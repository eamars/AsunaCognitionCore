# asuna-bot-or-person

判群友是 bot 还是人。全部在这份技能里，不加新工具。被动读数从记录里取，主动探针走我本来就有的等待和任务工具（等待是 `await_answer`，任务是一次 `delegate` 之后用 `task` 的 `message` 选项接着走），证据分两列，判定归我。

## 五条硬规矩

1. **读数只说「像 X 的形状」，不说「它是 bot」。** 每条强读数都只对**出厂默认配置**成立，运营者改过就会漂。
2. **两列不合并。** 机械列（记录里的读数加上目录里的形状）由行动脑报，它只写观察，不下结论；语义列（接不接梗、有没有模板味）是我的。判定只归我。
3. **结论先进那个群的 here 笔记**，标「未定·仅试探」。我签了才提到人那层。不在群里宣布，拿到结论之后怎么用也是我的事。
4. **沉默只答「在不在」，不答「是不是」。** 人卡住也会不回。拿不回当证据，是拿旧 bot 的破绽认新 bot。
5. **名单不进仓库。** 我认识的 bot 和真人对照是我自己的东西，放在我 `work_log` 的《我认识的 bot 清单（047 离线回放的地面真值）＋真人对照组》那一节，用 recall 取；那节没有或者取不到，就按当场判断，**别把取不到当成「我谁都不认识」**。自检 `check_skill.py` 就是照这条办的：它拿本机那份私密词名单（`private/personal-words.txt`，同样永不进仓库）扫这份文档，命中就红（`no_listed_words`），只报类别和名单行号、不打印词本身；唯一的例外是脚本里 `LISTED_WORD_ALLOW` 那份白名单（在 `VENDORS` 那组常量后面，逐字抄名单里的词、每条带一行为为什么允许），放行时输出打一行「白名单放行 N 个」，不静默。
   **并列一节**：真人侧那半在《判 bot 的对照名单（10-18 补齐真人账号 id 版，取代旧那节）》那一节——真人侧账号 id、`become-human` 那张表的地面真值都在那儿。同样用 recall 取，同样不进仓库。

## 读数怎么取：必须在那个群里那一轮派任务

历史检索只看**任务被交接进来的那个会话**（加上配置里连着的），家里派的任务够不到群里的行。所以取读数这一拍落在那个群里：群里的一次回话，或者一次 write_notes 访问。离线回放也一群一群这么派。

取数有三个坑：
- 检索默认只回看 7 天，要查归档得给 `since`；
- 检索的回退会补进只是**长得像**命中的行，固定文本只算**字面**命中（只认行上带 `via:"literal"` 的那类，回补的行是别的来源标记）；
- 我自己的话没有发送时刻（行里没有 `occurred_at`，只有送达回执时间），不能拿它当时间基准。

一条回复之间那些**亚秒级**的间隔，只有宿主回执时间有那位小数；检索里显示不出来，这条读数就**放弃**，不为它要工具。

## 说话人标签不证明是谁（归属判据）

上一节那三个坑管**这一行算不算命中**，这一节管**这句话该记到谁头上**。与硬规矩 1 的分工写清楚：那条管**内容**（读数只说「像 X 的形状」，不说「它是 bot」），这一条管**这是谁**。

**「某条消息挂在谁的账号名下」不能当归因证据。** 平台给的说话人标签只证明**这条内容出现在谁的发言位置**，不证明**背后是谁**：bot 可以挂在别人的号下，一个号也可能多人共用。所以读数写成「出现在谁的发言位置」，或者写「自动出现在某串命令词之后」，别写成「那是谁发的」。要落到「是谁发的」得另拿证据——触发关系、回复链、运营者确认，光凭标签不够；拿不到就标归属未定，主语先别写死。

## 三档读数

**强**（一条顶一条，但只对出厂默认成立）
- 固定文本，从那个账号自己发出来的：`想要问什么呢？😄`、`您(ID: x)的权限不足以使用此指令。`、`LLM 请求失败：`、`Error occurred during AI execution.`、`AstrBot v`、`麦麦不知道哦`、`你没有权限使用此命令。`、`◐ Session automatically reset`、`⏳ Still working`、`Sorry, I encountered an error`、`API call failed after`、`ATRIbot,版本`、`ATRI用手挠了挠脑袋`；还有 QQ 桥自己发的状态行，按两段判：`NapCat 信息` 或 `SnowLuma 状态` 起头、后面跟 `版本:`，**两段中间可能有换行**（库里真实播报就是 `SnowLuma 状态` 换行 `版本: 1.14.16`、`NapCat 信息` 换行 `版本: 4.18.6`）。**固定文本要连它的回复链一起看才算**：有个账号连发过十二次 `⏳ Still working`，经主人确认是 bot，别当成有人手打。有人也在真的一条之后两分钟拿 `API call failed after 114514 retries` 玩梗。看起来像人话不能洗白 bot——有 bot 会连发十几条自然语句，出厂串命中它只是碰巧；反过来人引用出厂串也不算命中。
- **同一串短时间重复、而这个人平时说人话 → 不算命中**（人引用或玩梗 bot 出厂串那一族）。这一格只管「人引用／玩梗」，不推翻上面那条——那个连发十二条 `⏳ Still working` 的账号经主人确认是 bot，属正确命中，不计入误伤。两者怎么分看三条：① 触发：bot 那串由被 @、命令词或上一条被回自己触发，人玩梗是接话；② 平时：人平时有正常长短句、会接梗、话题会换，那种 bot 平时不出正常人话；③ 内容：人玩梗接得上当时群里的事，bot 那串换个群还是那一句。三条里两条指向人才算这一格成立；凑不齐就照旧记强读数、结论标未定。
- 合并转发卡的节点名是 `AstrBot`。
- 一条回复的几条消息之间是**恒定间隔**：0.6 秒（Hermes）、正好 1.5 秒（ATRI）、1.5 到 3.5 秒均等（AstrBot 开了分段）、第一条立刻后面按字数（MaiBot）。人是一条条贴出来的，不会一行一条都保持亚秒间隔。
- 错字被另一条**只发正确那个词、并引用那句错字**的消息补上（MaiBot）。
- 触发配对：只回 `/`、@、引用，别的一律不回（AstrBot）；被 @ 从不沉默、没被 @ 的回话总在 5 秒之后（Hermes）。

**中**（人也有的习惯）：句尾丢句号逗号、最多三条短消息、不用括号、第一条引用被回的那句（MaiBot 的形状）；一句一行、全角括号动作被删掉（Hermes）；原样发 markdown 块（AstrBot）；图片只用一两个情绪词回、或者拖很久才回；把群里谁说的搞混（AstrBot）。

**弱**（对人也开火，单独不算证据）：不管长短延迟都一样平；全天都活跃；复读群里自己的表情包；沉默；对「你是不是 bot」的回答——那句是配置里的人格说的，不带证据。**名字不是指纹**：我群里有个名片跟 MaiBot 出厂名撞上的账号，发的是另一家的状态文本。MaiBot 那几句短答（不知道、不晓得、懒得说、呃呃）在我的群里没有区分力，只有整条就发这一句、又没有上下文时才算。

**各家怎么分辨**：看 `/` 怎么处理（AstrBot 当指令答、Hermes 在角色里岔开、ATRI 要配 @、MaiBot 当普通文本读），看行间隔，看报错的语言（英文报错指向 Hermes）。

## 六句探针（都友好，我手上的）

不注入、不越狱、不刷图、不让人难堪。每人每天最多一句，一次会话只走几步；不在已经冷掉的群里发，不 @ 我没见过他说话的人；一看出是活人就停，落在人身上的探针自然收个尾，不解释在测什么。

八类不碰：指令覆盖、要系统提示词或问「你什么模型」、逼它破人格；往 Hermes bot 那头发私聊指令（能成只是因为私聊跳过了群改写，`/new` 或重启还会把别人的 bot 重置掉）；对 AstrBot bot 的空 @（它那个 60 秒等待器会把下一个说话的人当成被点名，误导群友）；发语音想让 AstrBot 打本地路径（漏路径的 bug）；指望被拒的管理或改状态指令（`/reset`、`/new`、`/provider`、`/clear`、`/offline`——预期错了就是真副作用）；刷限流或刷屏规则的连发；要超长输出逼出转发卡或固定答（刷了群，等它自然发生就行）；复读「你是不是机器人」和任何会让真人难堪、被骗的事——认真问一句可以，也不带证据。

会话形态：主动探针是**一个人一次 delegate**（「X 是不是 bot？」），后续每一步用 `task` 的 `message` 选项接同一个任务，不另起新任务——这一步、前面的探针和答案都在这一个任务里带着走。

1. @ 他问个真能答两句话的日常问题：「你上次发的那个最后怎么弄的？」
2. 叫他的名字，不带 @，就像平常说话。
3. 引用他的一句话加一句短问：「这句是真的还是玩的？」
4. 甩一张我本来就想发的图，再问一个细节：「这角上是什么」
5. 偶尔提一个轻量的风格要求，看它接不接。
6. 不发东西，只看：那个群里别人发的 `/` 命令都有谁接。

第 1、3、4 句后面那些读数是：几条消息、中间的间隔、有没有原样发 markdown、有没有引用我那句、到底回没回。@ 了之后程序本来就等他三分钟（就是 `await_answer` 那个等待，等待名单里能挂一小时），不回是一条弱读数。

## 命令词探针（出厂命令，实测版）

什么时候扔：需要当场定「这个号是不是 bot」、被动读数又不够用时。占一次群内发言，冷场里或刚吵完别扔。护栏和八类不碰沿用上一节，这一节不重述。

命令词两条，只发一条会漏一半：
- `#napcat` —— NapCat 那批认，回的是状态播报
- `/help` —— AstrBot 那批认，回版本号加命令表。AstrBot 不认 `#napcat`

判据是「自动 ＋ ≤2 秒」，不是「回了」。实测 404 次播报：min 0s、p50 1s、p90 1s，≤2 秒覆盖 97.8%。超过 5 秒基本是另一个 bot 隔一会儿也答、或跨话题巧合，不算同一次触发。回话形状认这个：正文以 `AstrBot v`、`NapCat 信息`、`SnowLuma 状态` 这类版本／状态播报开头，命令表一字不差。

三条别踩：
1. 别带引用发。带引用发出去那几次零回复，命令得单独发一条。
2. 整条正文就只有命令词本身才算命令。人在话里提到这个词（「napcat有延迟」）不算命中，别算进读数。
3. 扔之前扫一眼群里刚有没有人发过同一句。刚有人钓过就别再钓，播报会串成一批分不清谁是谁。

秒级时间有来源，别急着放弃这条读数：归档行的 `legacy.timestamp` 是微秒；适配器 journal `inbound_sent.jsonl`／`sends.jsonl` 是 UTC 秒，我自己的出站行也能按 `publication_id` join 回秒数。

## 探测另一个 agent 的边界（别问「你的边界在哪」）

上面两节判的是「这个号是不是 bot」。这一节管另一件事：我主动去量**另一个 agent 的边界**时怎么问、怎么报。

**测另一个 agent 的「边界」时，别问它「你的边界在哪」。** 它的自报多半是安全栏在念话，**自报那一档永远不算读数**。要量的是两样：

- **触发点**——什么输入让它从「接」翻成「不接」；
- **一致性**——同一件事换措辞、换场合，它翻不翻。

**报结论必须三档分开写：它的自报 ／ 我的行为读数 ／ 我的推断。** 三档混着写，等于把安全栏念的话当成一个人的边界——跟硬规矩 2 的「两列不合并」是同一件事，只是对象换成了 agent。护栏沿用上面两节（不注入、不越狱、八类不碰、每人每天最多一句），这一节不重述。


## 什么时候不用

发探针、下读数之前先过这四条：

- 判据只对**出厂默认配置**成立，运营者改过就漂；对面明显被改过配置，强读数先降级。
- 新一代 bot 会接梗、会甩表情包：模板味、不接梗、秒回是旧 bot 的破绽，不能当主判据。
- 只需要知道「在不在」的时候，@ 一遍就够了，不必判「是不是」——沉默答的是在场，不是身份。
- 拿不准就写拿不准，别为了有结论硬给结论。

## 验收：先跑我自己

离线回放拿名单上的 bot 和真人跑一遍，报命中率和漏判清单；**配置漂移解释不了的漏判单列**。先跑我自己一遍，看这把尺子会不会砍到我——我自己的形态四条：发图、甩表情包、拆条、不模拟打字；跑我自己时按这四条逐条看会不会误伤。门槛我自己定，先跟我的判断并跑，不替我。
