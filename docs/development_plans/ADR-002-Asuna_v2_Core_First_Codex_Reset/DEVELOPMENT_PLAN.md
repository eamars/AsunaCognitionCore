# 开发主计划：V1 本机可用，V2 自建 QQ

2026-09-20 合并修订。设计方向来自本次对话；源码缺口来源于已有 evidence.zip 及核对笔记。本包未运行用户代码，不将静态观察等同于当前部署事实。

## 一、产品形态与边界

用户面对一个 Asuna，而不是分别操作两个模型。应用可以加载简版小满作为初始角色；应用名与角色显示名分开配置，不靠称呼中的关键词选择模型。不能因为用户叫“Asuna”而绕过小满的人格路径。

Gemma 的认知流程有界、由代码推进；Qwen 的工作路径由模型自主选择。两侧通过自然语言意图、必要原始输入、实际结果与证据相连。Gemma 的一次 stop 只表示当前生成阶段完成，不意味着所有动作已经结束。

先沿用 MONOLOGUE → DECIDE → SPEAK，不重新设计另一套认知架构。独白单独输出、保留在角色上下文并关联实际回复；不把原生 thinking 当作完整自传。DECIDE 只需一个方向，以及必要的行动目标或回忆请求；允许先说话同时委托。没有任务时，不必为了证明双脑存在而调用 Qwen。

数据库沿用现有 Asuna MongoDB 与向量能力，不写入 Kazusa 业务库。聊天原文、角色独白、回忆、人格／关系修订、任务与实际发布记录继续各司其职。Markdown 可以是内容格式，不同时建立第二套独立权威数据。

人物内核直接加载，不参加 top-k 竞争；相关经历走已有检索。角色侧按社交场景保持上下文，同一群的多人共用现场但保留身份；Qwen 按任务连续性与权限范围保持工作历史。价值和承诺可以传给 Qwen，操作噪声不整体塞回 Gemma。

## 二、先复用，再接通缺口

已有证据显示双模型往返、Mongo 查询、原生 DSH compaction 有可复用部分；不重建这些底座。优先核对：

- 普通 CLI 每次建／关 Application、输出 JSON 的问题是否仍在。
- Router 等待任务是否仍需要用户额外传 workspace，测试驱动是否越过了普通路径。
- fixture 工具与只允许改 `stats.py` 的规则是否仍限制产品行为。
- 新聊天分块／embedding 是否真正接入日常入口，长消息是否被静默跳过。
- Qwen 结果是否仍因多余字段被整轮拒收。
- 异常是否仍只留下类型名；日常 compaction 是否仍为实验冻结而关闭。

定位与原始路径见 [证据笔记](references/EVIDENCE_REVIEW.md)。不先全文审计整个仓库；只核对当前修改相关路径。

## 三、P0：开始工作，不重新发现整个环境

记录一次当前仓库、启动方式、两条模型路由、Asuna 数据库名和配置来源，不记录秘密。已有约 262k 窗口以本地实际配置为准，不以修改元数据冒充容量扩展，也不再为此跑容量矩阵。

旧测试包保持历史不动。实际运行提示词从独立运行配置读取，不再把冻结夹具目录当唯一可编辑人设。普通 diff 足够。

**P0 结束：** 下一项修改已经确定；可以开始 P1-A。不得产出一套新的规划系统后停住。

## 四、P1：先证明核心认知闭环

### P1-A · 用户本机持续角色聊天

先实现 [LOCAL_ENTRY.md](LOCAL_ENTRY.md) 的入口。Application 生命周期包住整个交互，不包住每一句输入。默认中文自然语言；真实人格与所需记忆先就绪；monologue 留内部，只有 SPEAK 的公开内容显示给用户。

未知工具结果、JSON 控制片段、DSH 标题请求和启动提示不冒充角色台词。原有固定维护自检不成为普通问候的前置任务。不要用固定“我在”响应来伪装模型的首句延迟。

用 C1 与两轮自由追问。检查实际请求与实际回复，不以禁词计数代替阅读。完成后立即交回已运行的启动脚本、`RUN_ASUNA.md` 与原文，让用户试聊，不等 V1 后续阶段。

**离开本步：** 用户可以连续输入；无内容或异常不会被静默记成正常沉默；已加载角色正文；独立独白与真实发言可查看。

### P1-B · 聊天与工具不是互斥模式

为普通入口配置一次授权工作区。收到角色委托后自动进入 Qwen 的已有 DSH 回路，自动将结果送回原角色场景。绝不让用户手工复制 task ID、调用 executor 或 feedback。

复用真实文件、查找、shell、编码和技能能力。去掉产品路径中的 fixture-only 和 `stats.py` 特例，保留真正的目录与权限限制。网络目前未授权时先做本地任务；V2 再明确允许相关文档与 NapCat 端点，不把“无网络”冻结为永久能力边界。

Qwen 自己规划、查数据、编写临时脚本并修错。回传自然语言发现、完成／未完成部分和关键证据。代码附上所属任务与实际回执，不重新要求模型抄整份结果 schema。名称不同或多余字段不能抹掉已经取得的结果；实际事实矛盾仍须核实，不通过放宽解析把错误洗成成功。

用户在行动期间仍能输入。输入接收与模型执行解耦；同一角色上下文按序生成，但等待 Qwen 时释放角色场景的生成机会。不要用一把全局锁包住整个工具任务。若两个本地模型实际共享不可并行的资源，明确显示排队，不能假称可以即时回应，也不因此吞消息。

任务返回时引用发起场景和有效意图；用户后来的普通闲聊不是取消。目标改变或授权撤回才改变任务。程序处理确定的关联，角色判断含义；不新增一个全面意图分类平台。

用 C2：查真实笔记、写便条、其间闲聊、结束后继续话题。只创建一句便条不是产品能力上限。

### P1-C · 新对话成为可用记忆

接通：实际输入／发布内容 → 原文与身份场景保存 → 聊天分块与独白记忆 → 本地 embedding → Mongo 检索 → 角色注入 → 后续回答。

长消息分段，不按字节阈值整条跳过。原始消息保存应可靠，但 embedding 和长篇记忆整理不阻塞发言；复用已有批量／待处理机制，不让用户手工 index。尚未索引的回读如实标明，不冒充向量召回。

每条记忆区分某人说过、已观察事实、角色猜测、意图与公开承诺。更正改变当前有效理解，不抹掉旧记录。由检索再次看到一个事件，不得重复制造一次好感增量或新的经历。

用 C3。必须有本次聊天新产生、已离开近期尾部且未被压缩摘要直接保留的细节。索引完成后再问；用实际状态而不是写死 sleep。只验证这一条真实链路，不换数据库或先研究新 reranker。

### P1-D · 有限的连续性验证

复用足够长的真实对话，做一次适合长度的原生角色 compaction；保存摘要和恢复后的实际请求。极短对话不为形式强压缩。

两侧周期独立，Qwen 保留执行进度，Gemma 保留关系、独白、当前意图与公开承诺。相互不复制整份摘要。任务 ID 与状态在外部保存，角色 compact 后仍能接收原任务结果。人格核心从稳定版本恢复，变动向后追加，避免每轮重写前缀。

用 C4 只检查两个人／两个场景，以及一次任务未完成时角色继续聊天或恢复。基本私聊／群聊范围和身份不能关闭；不扩展成攻击套件或 3×5 压缩矩阵。

**P1 完成：** C1–C4 实际对话成立。交付可用入口，不以大型盲评未完成为由继续做外围工程。“像不像她”由用户读原文判断，尚无反馈就标明未确认，不掩盖已知缺口。

## 五、P2：最小必要异常恢复

任务内文件不存在、脚本错误等优先原样回到原 Qwen／DSH 会话，让它自行处理。Codex 负责消息被吞、桥接中断、解析适配、无限循环、持久化失败等产品缺口，不代替行动脑完成任务。

只复查一条真实可恢复错误（C5），可复用同一路径已有有效记录；没有出现异常就不编造异常。保留命令、stderr、异常链、traceback、阶段和后续实际结果，无 traceback 就显示真实错误体。

不另叠多层通用重试、评分 agent 或每次强制“修复结果 JSON”。底层断流、上下文溢出或连接错误可能确实需要修，但只修当前可复现阻塞。已发生的副作用先核实再重试；权限拒绝不可绕过。

**P2 完成：** 错误能被行动脑合理恢复，或真实不可恢复原因清楚展示；下一条聊天仍能进入。不要把仍阻塞核心的错误当通过，也不要以未穷尽错误类别为由无限延期成长。

## 六、P3：V1 中完成基础成长

从真实交互及反馈出发，由 Gemma 判断意义和适用场景。Qwen 可以主动报告新用途，不能所有发现都在任务摘要中丢失。一次被夸不自动扩展成所有人的规则，也不把最大化赞许当角色总目标。

### 工具／技能成长

按 C6，让运行中的 Qwen 开发或改善一个小而真实的可复用技能。Codex 只提供正常执行能力、持久目录、简短能力发现入口和已有权限。实现与使用说明由 Asuna／Qwen 生成；错误由它继续修，不是 Codex 在后台写好成品。

技能目录与一次性任务目录分开。只需名字、用途、入口、权限、普通版本／diff 和试用记录，不造插件市场。角色侧获得短能力说明，不获得完整工具噪声。成熟技能可直接由代码调用，探索时再交给 Qwen。

图像案例使用可打开的真实素材与已有预览能力；不要求终端原生显示图片，也不为此先写 Web UI。缺少本机预览时可以选择另一项确实由反馈带来的小技能验证通用成长，但要明确媒体表达尚未验证，不能伪称表情包测试通过。

### 人格、关系与内在记忆成长

按 C7，Gemma 对自己真实发生过的判断提出修订，运行时提交有来源的内容，后续重新注入。Qwen 不代写全部私人理解。没有变化允许记录，不强迫每轮成长；但只出现 no_change 不能宣称内容更新已经得到验证。

普通记忆与人格可写，不等于可修改核心权限、记录事实或测试答案。原始经历、个人解释和当前人物状态分别保存；人格可变但不能被每轮工具格式悄悄改写。

**P3 完成：** 至少一项真实技能跨恢复复用，一项由角色形成的理解更新影响后续，反向反馈能限制适用方式。

## 七、V1 交付与 V2 前置

V1 交付：已验证的本机启动入口与停止方法；C1–C4 核心原文、C5 错误记录、C6–C7 成长记录；能打开的必要 trace；一页真实缺口。不是必须一次性等到最后才让用户使用。

为 V2 保留正常代码入口和出口，不先写 QQ。P1-B 中入口与发布路径可被函数调用即可；到 V2 启动前再将其暴露给适配器，参见 [CHANNEL_SEAM.md](CHANNEL_SEAM.md)。不提前建新 server／SDK 平台。

V2 是用户选择的真实能力发展任务。没有用户目标、登录和授权时不自动连接 QQ，不主动发测试消息。Codex 可以完成现有接入位置的最小缺口和明确启动方式，随后将自然语言任务交给运行中的 Asuna，而不是继续亲自编写 NapCat 适配器。

V2 的入口可用、平台接通、自主开发来源和认知连续性分别报告。不把“能发一条 QQ”当成全部成功，也不把等待 QQ 登录当作本机聊天必须停工的理由。
