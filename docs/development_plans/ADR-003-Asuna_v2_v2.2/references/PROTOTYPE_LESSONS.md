# 独立裸 DSH 小满原型：只借鉴经验，不迁入实现

来源：先前提供的 `qq(1).zip`。该原型与Asuna行动脑使用同类本地Qwen3.8 Flash，但不是Asuna v2代码。它参考过Kazusa／Asuna设计；观察到安全行为不等于所有路径都受程序约束。以下是源码行为参考，不是本轮重新运行QQ后的实测。

| 原型事实／风险 | 原型源码位置 | 新任务中的最小对应要求 |
|---|---|---|
| 全库向量比较，同群只加0.03分 | `qq/prewarm.py:86–109` | 先限可读scope再检索；已有Asuna过滤保留，不能为QQ另开无约束入口 |
| 私聊group_id为None，另一个私聊也会满足场景条件 | `qq/prewarm.py:123–129` | 私聊scene用连接账号＋对方身份明确构造；None不是共享场景 |
| 同场景独白不足时，用其他场景独白补数量 | `qq/mono.py:94–102` | 不足就少给，不能拿隐私补top-k |
| 在同群／另个None私聊发过消息，就可能销掉未处理输入 | `qq/inbox.py:85–108` | 用输入事件及实际处理关联，不根据“后来开过口”推断完成 |
| 原文正文截为400字 | `qq/inbox.py:392–410` | 原始允许记录内容完整保存，模型上下文可切分／引用，不把展示上限当原文上限 |
| 预热最长等待90秒，结束后台任务后才通知模型 | `qq/inbox.py:749–802` | 收件先存和返回；宿主唤醒，不靠退出码／重挂等待脚本 |
| auto-rearm主要留下待续挂状态 | `qq/inbox.py:899–911` | adapter由宿主管理生命周期，正常静默不需要LLM循环 |
| 全部插入异常被吞，成功数量是尝试数量 | `qq/qq.py:661–681` | 真实持久化确认后推进游标，失败原始原因可见 |
| 填写自审理由可以解开hold，另有普通send与通用OneBot调用 | `qq/qq.py:291–318、482–521`；`qq/probe.py:20–40` | 反思≠授权；群任务拿不到通用NapCat token／旁路发言入口 |
| 保存“看过图”的标记不等于实际看了那张图 | `qq/meme.py:176–232`（先前源码审阅） | 媒体后续开发时绑定实际候选/选择/发送对象，不在文本接通阶段强迫实现全部媒体能力 |

值得继承的模式：平台身份与昵称分开；提供公共现场加当前参与者前文；保留原始monologue且不当事实；经历和反馈能改变工具；普通任务错误继续回原Qwen。

不继承：原私聊库、旧QQ号的授权、旧牌照系统、默认token作为新系统有效授权、模型每轮恢复整套门铃、模型自报字符数审核、Qwen可直接取代角色发表台词。

之前对话曾针对None场景和独白补齐进行过合成检查；V2.2对新系统重新检查对应自然场景即可。这里不把旧的合成测试说成Asuna已经发生了真实泄漏。
