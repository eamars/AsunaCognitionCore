# 致架构师：本地开发能力应如何成为默认能力

> **现行状态（2026-09-25）**：本文保留架构师裁定前的咨询记录。后续裁定已实施并在本机 Web 宿主启用：可信 `local-dm/local-user` 输入默认可用已配置的集成与自我开发能力，由角色决定是否委托；两个逐条授权框及聊天区“停止集成”按钮已删除。旧草稿“撤回”和下文“仍靠逐条勾选”只描述裁定前状态，**不代表当前权限**。QQ 接入与权限隔离未改变；集成停止工具保留。现行操作说明见 [RUNTIME_API.md](../../../RUNTIME_API.md)。

2026-09-25。用户要求 Codex 暂停自行决定本项实现，先在本交互文档陈述问题并征求架构师意见。本文不是实施方案或授权变更。架构师无需访问代码即可判断下述设计问题。

## 用户的目标与对 Codex 的纠正

用户希望本机聊天像基线 DSH 一样：小满若愿意，可以直接委托行动脑做开发、集成、调试和发布，不需要用户在每条消息前额外授予“开发许可”。本机界面不再显示“本条授权集成开发”“本条授权自我开发”“停止集成”三个控件。**QQ 的现有权限隔离保持不变；用户没有要求修改 QQ 消息来源或通道路由。**

Codex 先前回答“不能只把两个框默认勾上”，用户追问这究竟是技术限制还是过度开发残留。准确的代码事实是：当前 Asuna Web 把两种勾选设置为互斥，发送后都清空；本机聊天入口也显式拒绝两种授权同时为真。这是 Asuna 自己加的产品规则，不是 DSH 无法在同一行动中提供两组工具。行动任务的能力集合已经可以组合两组工具。Codex 不应以现有互斥实现反过来证明逐条许可有必要。

ADR-003.1 的有效原则是：双脑增强角色，不以额外宿主门槛削弱授权目标内 DSH 原有的工具、编码、长流程和自主排错能力；真实资源身份与授权范围仍保留。这里需要区分“本机 owner 长期授权的工作域”和“QQ 普通消息不得取得宿主能力”，不能把两者折叠成逐条 UI 勾选。

## 当前运行机制，供设计判断

1. 当前有效配置中的本机聊天身份是 `local-dm` / `local-user`，本机集成和自我开发功能均已启用。现有六条 QQ 路由使用其他场景和身份，没有与本机身份重叠。
2. 本机 Web 的两个勾选框分别把 `integration_profile=owner`、`development_profile=owner` 加到当条输入。角色决定委托后，宿主才把相应工具列入该行动任务；工具调用时仍核对任务能力。集成工具使用持久开发目录、受限端点和受管理服务；自我开发工具使用可发布的当前项目候选、检查命令与现有真实数据库。授予能力不等于要求角色开发，也不自动启动服务或发布。
3. 一条已获授权的行动任务在结果反馈时继续携带相应能力；本机计划可继承集成授权。内部自我开发机会已有自我开发能力，普通本机聊天则仍靠逐条勾选。
4. “停止集成”并非权限开关：它停止已启用的集成进程并关闭自动恢复，但不取消行动任务，也不撤销未来再启动的能力。隐藏这个 UI 按钮与保留行动脑的集成停止工具是两件事。
5. QQ 接入的外部消息字段清单不接收上述授权标记；本机 Web 对群聊代发也拒绝携带开发授权。现有工具仍按任务授权执行。用户要求保持这些 QQ 边界和现有 QQ 行为，不借本议题改写 QQ 来源。

## 请架构师裁定

1. 是否将本机 owner 聊天的集成与自我开发能力设为持续可用的工作域，由角色脑决定是否委托、行动脑决定是否使用，而不是逐条 Web 勾选？如是，授权应附着在什么现有的可信本机入口与任务续接语义上，才能符合 ADR-003.1 且不改变 QQ？
2. 对本机计划和内部自我开发机会，是否沿用各自现有的能力继承规则，还是也纳入同一“本机默认能力”？请明确边界；不要让 Codex 因界面删除而擅自改变定时任务或 QQ 的授权。
3. 删除三个 UI 控件后，“停止集成”的服务控制应仅由小满通过已有集成工具自主执行，还是需要保留一个不在聊天输入区的本机维护入口？该按钮目前不是撤销授权的机制。

请给出最小的授权来源、能力继承和 UI 处理决定即可。无需设计新审批层、权限总开关或 DSH 对照实验。

## Codex 当前处置

Codex 在用户要求先咨询架构师之前，写过两处**未完成、未重载、未验证**的本机默认授权草稿：本机聊天入口自动给两种能力，以及 Web 提交忽略旧勾选字段；尚未修改 QQ 接口或路由，也尚未删除 UI 控件。这两处草稿现已撤回，持久开发候选也已核对为与当前宿主源码一致，且没有这两处未发布编辑。ADR-007 已部署的自我开发基座和此前运行记录不属于这次草稿，不在清理范围内。架构师裁定前，现行逐条授权行为保持不变。

另有一个忽略在 `.runtime` 下的旧机械探针临时目录。Codex 已核实其路径位于本仓库运行目录内，但自动审批以 `blocked by policy` 拒绝了递归删除；未换用其他方式绕过。它不属于运行中的候选、发布快照或数据库，仍待允许的清理方式处理。
