# ADR-012：心跳——家是她的主循环，她从家里出门去群里

| 项 | 内容 |
|---|---|
| 状态 | **已实施**（M-A、可见性与 `/heartbeat`、M-B；记录见 §12）。owner 2026-10-05 批准，§11 全部按推荐裁定 |
| 日期 | 2026-10-05 |
| 继承 | ADR-009 §10（节律、心跳、夜间沉淀）、ADR-009 §2.1（会话类由目标场景决定）、ADR-011（工具化回合）、P5 主动插话 |
| 参考 | 她在 DSH 时期的旧居（私有备份，仅作参考）；Kazusa 项目的自我反思槽 |
| 作者 | 实施者（Claude），应 owner 2026-10-05 的要求起草；调研由一个独立的研究代理完成 |

## 一句话决定

**心跳只在家里跳。** 家（本机私聊）是她的主循环，自我改进和别的定期事件也都在家里发生。每一拍是她在家里的一次自己的时机。她可以什么都不做，也可以决定「去某个群看看」：这时由程序在那个群里另开一个公开回合，她在那里读这个群最近的情况，再决定开口、写笔记，或者不说话。**这条心跳归程序所有，一定存在；节奏归她调，但调不没。**

## 0. owner 的要求（2026-10-05）

1. 她的核心思考循环在本地。本地会话不只是和她的对话，而是她的主循环；心跳、自我改进和其他定期事件都应该在那里发生。心跳决定去群里发消息，那就去。
2. 节奏让她自己决定，但要有护栏保证心跳一直存在。（旧居里她有时会忘了排下一次心跳。）
3. 把她当成一个真人：鼓励她自己开启对话，这是她要学的第一步，主动参与。
4. 她自己做的图可以发到她在的任何群，由她挑，一律全年龄向。
5. 鼓励她把每个群的偏好、话题、节奏和她认识的人记下来，作为她自己知识的起点。
6. 心跳是设计出来的功能，和她的长期目标一致，不是一次性任务。
7. 两个过去的设计都要纳入考虑：DSH 时期的旧居，以及 Kazusa 的自我反思槽。

## 1. 现状（已在源码中核对）

- **ADR-009 §10.2 的心跳（presence）已经实现，但现网没有开**：
  - 她的人格模型没有 `heartbeat` 段，本地配置也没有 `heartbeat_target`。
  - 实现：一条原生 `every_seconds` 计划 `plan-asuna-presence`，目标必须是 `owner_private` 场景。
  - 投递前有三道确定性闸门：`BUSY`、`MIN_GAP`、`REST_WINDOW`。
  - 改节奏走 `/schedule/update`，不删建。
- **她改不了节奏**：
  - `heartbeat.*` 不是核心可写键，她的模型也没声明；
  - 所以 `set_policy` 会拒绝，报 `POLICY_KEY_UNDECLARED`。
- **她能取消自己的心跳**：
  - `plans_from_program` 只排除了 `self_development`，心跳和夜间沉淀的计划都会出现在她的计划列表里；
  - `tool_plan` 的取消会照做。
- **原生记录丢了没人补**：
  - `ensure_presence` 只在宿主启动和她改心跳政策后运行；
  - `reconcile()` 不会重建一条消失的 `native_recurring` 原生记录。
- **家以外的地方**：
  - P5 只在有人说话时评估，是「插话」；安静的群里，没有任何东西能让她先开口。
  - 现网 5 个群路由中，有 2 个开了 P5 主动模式。
- **已有的群里资产，可以直接复用**：
  - 群笔记（`write_document` 的 `group_notes`）；
  - 人物理解（`understand_person`）；
  - 她自己做的图在群回合里可见、可发（`produced_only`）；
  - 群回合的 `catch_up`：最近 12 行，加上她上次说话以来的所有行，最多 40 行、60 分钟。

## 2. 两个过去的设计

### 2.1 旧居（DSH 时期）

- **机制**：
  - 心跳是她自己用 schedule 工具建的会话级循环提醒，提醒的 id 由她手抄进配置。
  - 每次醒来，序言里有一条自检，比对配置和调度器存储。
  - 暂停是一个配置开关，只有主人发话才恢复。
  - QQ 门铃是一个响一次就退出的后台任务，醒来后要她自己重新挂上。
  - 另有一个带过期时间的「忙」标记：她忙的时候心跳让路，但过期后不会永远挡住。
- **为什么会「忘了下一次心跳」**：
  - 钟归模型和某一个会话所有：换会话或压缩之后，钟就丢了；
  - 重新挂上要靠她醒来后自己动手；
  - 发现丢失要靠她读到自检，有一次是主人问起她才知道；
  - 还发生过一次时区混用，挂到了错的一天。
- **做对了的**：
  - 心跳是「她自己的时间」，做什么由她选；
  - 有抖动；
  - 「忙就让路，但让路有期限」；
  - 失败必须大声。
- **本设计取什么**：
  - 让路闸门（`BUSY`）；
  - 期限思想（暂停自动恢复）；
  - 把钟搬到宿主（§4.3）。
- **不取什么**：每一拍的内容义务（例如每拍必须发一张图）。那是设计上的刷屏。

### 2.2 Kazusa 的自我反思槽

- **机制**：
  - 反思工作器每 900 秒运行一次。每个周期至多 3 个相位槽，每槽挑一个合格的频道；合格指她 24 小时内在那里说过话。
  - 对群：先构建以 15 分钟对齐的活动窗，丢掉已审过的窗，只审最新一个，更早的合并跳过。同频道前台正在跑时让路。
  - 窗里有确定性标签：
    - 活跃度：安静 / 活跃 / 热闹 / 很忙；
    - 说话人多样性；
    - 她说没说过话；
    - 是直接点名还是旁听；
    - 新近程度、噪声、回应风险。
  - 窗里还有至多 6 行可见消息、参与者行、一个可选的 LLM 场景摘要，以及第二人称歧义警告。
  - 认知返回 `stay_silent` 或 `propose_visible_reply`，附参与依据、回应目标和理由。
  - 提议还要依次通过几道确定性闸门：来源、新近、参与依据、目标绑定、原子去重预留。通过后才渲染和发送。
- **它做得比单纯的「家里一拍」好的地方**：
  - 判断来自现场本身：一个新鲜、有界、带标签的快照；
  - 开口要有参与依据；
  - 一个窗只产生一次尝试（原子预留）；
  - 语义、政策、执行三类结果分开记。
  - 家里只看计数和标题，只能判断「去哪儿看」，判断不了「现在说什么合适」。
- **为什么不能直接移植**：
  - Kazusa 是先组包、再路由一个类型化决策的流水线；Asuna 的回合是原生 DSH 带工具的回合，现场由模型读，不由程序预先分类。
  - 地点轮换是程序在替她选地方，owner 要的是「家是主循环，去哪儿由她选」。
  - Kazusa 没有 `owner_private` / `public` 之分，Asuna 的交接不能把家里的内容带进群（§4.2）。
- **本设计取什么**：
  - 确定性标签（写成文字）；
  - 只看最新的窗；
  - 每群一份「看过了」的账；
  - 参与依据（作为提示，不作为闸门）；
  - 前台让路；
  - 「沉默是常态」的框架。
- **不取什么**：
  - LLM 场景摘要：每次去群都要多一次模型调用，而 `catch_up` 本身已经足够短；
  - 程序选地方。

## 3. 方案比较

| | A. ADR-009 原设计 | B. 每群一条开口计时（实施者先写的 initiative） | C. 一条心跳，程序轮流挑地方（上一版草稿） | **D. 本提议：家里跳，她决定出门** |
|---|---|---|---|---|
| 主循环 | 家 | 没有，各群各敲各的钟 | 没有，注意力被程序推着走 | **家** |
| 去哪儿由谁定 | 只能待在家 | 程序（每群一条） | 程序（离开最久的） | **她** |
| 群里能做什么 | 不能 | 开口或不开口 | 开口、写笔记或不开口 | 开口、发她的图、写笔记或不开口 |
| 心跳保证 | 无，她能取消，丢了不补 | 无 | 无 | **程序拥有，多点看门** |
| 成本上限 | 每拍一个回合 | 群数 × 频率 | 每拍一个回合 | 每拍一个家回合，外加每天有上限的出门 |

- B 复制了 A 的整套机制，还把她的节律拆成几条互不相干的钟；它的代码只留在实施者的草稿区，不进仓库。
- C 把「去哪儿」从她手里拿走，又把主循环搬出了家。
- D 是 A 的延伸：ADR-009 的原则一条不变，只加一个工具和一道交接。

## 4. 设计

### 4.1 家里的一拍

- **计划**：一条原生计划 `plan-asuna-presence`，每 `heartbeat.every_min` 分钟一拍，目标是 `heartbeat_target`（必须是 `owner_private`，ADR-009 规则不变）。
- **闸门**（确定性；跳过时不调模型，只记一条计数审计）：
  - `BUSY`：家的队列里有东西，或者她的角色回合正在跑。行动脑的后台任务不算忙：任务可能跑几个小时，期间她照样能说话，心跳不该因此停掉。
  - `MIN_GAP`：距上次**进入模型**的心跳不足 `heartbeat.min_gap_min`，并且此后没有「找她的新事」。新事指：家里有新的入站、她的任务有了结果、群里有人点名或回复她，或者她上次出门的群里有人回应。群里与她无关的闲聊不算新事，那交给 P5。
  - `PAUSED`：她自己设的暂停还没到期。到期后自动恢复，不需要任何人动手。
  - `REST_WINDOW`：她选了 `skip_in_sleep`，并且正处于她的睡眠窗。
  - `DAILY_BUDGET`：当天进入模型的心跳已达核心上限（§5）。
- **心跳通知**：沿用现有的内部回合通知，并且只在家里出现。它包括：
  - 她此刻的节律和心情，以及活账；
  - 跨场景的「最近经历」；
  - 一个新的「地方」视图（§4.4）；
  - 上一次出门的结果（§4.2）。
  - 通知已经按差量投递：与会话最近约 32k token 内容相同的块不重发，所以「没什么新鲜事」的一拍很轻。
- **她能做什么**：和 ADR-009 一样，可以：
  - 沉默；
  - 对主人说一句；
  - 委托行动脑；
  - 写文档；
  - 记想法；
  - 调自己的节奏。
  - 新增一项：**出门**（`visit`）。

### 4.2 出门：`visit`

```
visit { place, intent, topic?, artifact_id? }
  place        地方视图里的一个群（程序给的编号，不是群号）
  intent       start_topic | share_picture | check_in | write_notes
  topic        可选，≤ 80 字；是否允许见 §11 Q1
  artifact_id  可选，intent=share_picture 时她自己做的一张图
```

- **两步走**：
  1. 家里的回合只记下这次出门，然后照常结束。
  2. 程序用现有的内部入站（`offer_internal`），在那个群里排一个 `visit` 回合，再经路由和协调器进入正常流程。这一步复用的是方案 B 已写好的「群场景内部入站」和「路由放行」。
- **为什么不从家里直接发**：
  - 家里的回合是带着 `owner_private` 内容组织语言的，直接发进群等于造一条新的发布路径，违反 ADR-009 §2.1。
  - 群会话里也会什么都看不到，主人没法在那个地方检查她做了什么。
- **群里的回合是 `public`，因为场景是群**。它看得到：
  - 这个群的 `catch_up`；
  - 她写的这个群的笔记；
  - 她对这里的人的理解；
  - 她自己做的图；
  - 她此刻的心情（心情是全局的）。
  - 外加一个 **Kazusa 式的现场窗** `visit_from_program`。窗里的标签都是确定性的，由版本化的表转成文字，内容包括：活跃度、多少人在说、上一句是多久前、她在不在这段里说过话、有没有人点名她，以及参与依据（「没人叫你」「有人提到你」）。
  - 它**看不到**家里的任何东西：
    - `rhythm_from_program`；
    - `recent_experience_from_program`；
    - 主人私有的档案和活账；
    - 家里的计划列表。
- **在群里她能做什么**：起话头、发一张她的图、写群笔记、理解某个人、记想法，或者 `stay_silent`。沉默照样是正常结果。
  - 群里的 `visit` 回合本身没有 `visit` 工具，也没有任何开发授权，不会再出门、不会连锁。
- **交接的文字**：
  - `intent` 是分类，放心过界。
  - `topic` 是她自己写的一句话，会被带进群回合。允不允许见 §11 Q1。
  - 她在家里的推理全部留在家里的回合中，可审计、可在家里的界面看到。
- **每次出门只算一次**：
  - 入站 id 是 `visit:<群场景>:<心跳那一拍>`，重放会被去重。
  - 同一个群在 `heartbeat.after_own_min` 内不接受第二次出门。
  - 每个群的 `last_visit_at` / `last_visit_outcome` 就是「看过了」的账。
- **结果带回家**：下一次家里的心跳通知里有 `last_visits_from_program`，写明去了哪儿、多久前，以及结果：开了口、没说话，或者写了笔记。
  - 如果她开口后没人接话，下一次在这个群的间隔加倍。这和 P5 的「话头没人接」是同一个思路。

### 4.3 心跳一定在

- **归程序所有**：
  - `presence`、`settlement`、`self_development` 三类计划从 `plans_from_program` 中排除；
  - 她的 `plan` 工具只认 `plans_from_program` 里列出的计划，所以她看不到它们的计划 id，也取消、改期不了。
- **她能调什么**：成为核心可写键，与人格无关，人格包不需要声明。M-A 只开前四个，出门相关的四个随 M-B 加入。

  | 键 | 范围 | 含义 |
  |---|---|---|
  | `heartbeat.every_min` | 15–240，越界夹住 | 多久一拍 |
  | `heartbeat.min_gap_min` | 0–720 | 没新事时，两次进入模型之间至少隔多久 |
  | `heartbeat.skip_in_sleep` | 布尔 | 睡眠窗里要不要跳过 |
  | `heartbeat.pause_min` | 0–720 | 暂停一会儿：程序记下 `paused_until`，计划照常跳，到期自动恢复 |
  | `heartbeat.visits` | 布尔 | 要不要出门 |
  | `heartbeat.quiet_min` | 0–240 | 群安静多久，才算可以起话头 |
  | `heartbeat.after_own_min` | 30–1440 | 她在一个群说过话后，多久内不再去 |
  | `heartbeat.visits_per_day` | 0–核心上限 | 每天最多出门几次 |

- **她不能做的**：关掉心跳、删除计划。`heartbeat.enabled` 是 owner 键：人格包可以给缺省值，但不能把它声明成她的政策键。
- **只有 owner 能关**：
  - 本地配置的 `persona_runtime.<persona>.heartbeat_target`（缺省就是没开，现状如此）；
  - 人格包的 `heartbeat.enabled`；
  - 设置卡里已有的「心跳目标」项（复用，不新增界面）。
- **看门**：只检查，不排期；时钟仍只有 DSH 一个。检查的内容：距上次心跳投递（包括被闸门跳过的那些）超过 `2 × every + 5 分钟`，就审计一条 `rhythm.heartbeat_missed`，删掉旧的原生记录、重建一条（看起来还活着却不响的记录也换掉），并记下 `reconnected_at`。同一段沉默只重建一次；两拍之后还没响，再试一次。
  1. **宿主启动**：`reconcile()` 之后紧接着 `ensure_presence`（已有），消失的原生记录在这里重建。
  2. **每次回合结束**（`Chat.on_turn_finished`，原来用于检查重启）：家、群、私聊和行动脑任务的回合都算。
  3. **夜间沉淀和自我改进投递时**。
  4. **宿主已有的看护线程**（检查发布后重启的那一条）每 5 分钟检查一次：没人说话的安静日子里也不会漏。
  5. **心跳中途崩溃**：入站在回合开始前就已落盘，`recover_inputs` 会重新排队。重放的投递得到同一个事件 id，在 `persist_input` 去重（已有）。
- **失败要大声**：
  - `rhythm.heartbeat_missed`、重建、夹住，每一项都记审计；
  - 下一次家里的心跳通知会用一句话告诉她：「你的心跳刚刚断过一次，已经接上了。」

### 4.4 家里的「地方」视图

- `places_from_program`：她在的每个有路由、没被屏蔽的群各一行。每行用文字写明：
  - 群名（按她读到的样子）；
  - 活跃度档位，以及上一句是多久前；
  - 她上次在这里说话或来看是多久前，结果如何；
  - 有没有没回的点名；
  - 她这个群笔记的各节标题；
  - 能不能去：「可以去」「刚来过」「正热闹，P5 会叫你」「那边是夜里」。
- 不放任何消息原文：新鲜的内容在出门时才读（§4.2）。
- 档位和时长都来自版本化的表，转成文字，符合 AGENTS 的「状态以文字到达模型」规则。
- 每个群约 60 token。
- 「那边是夜里」的规则：
  - 开了 P5 的群用路由自己的 `quiet_hours`；
  - 没开的群用核心默认（23:00–08:00 本地）。
  - 这是对群里其他人作息的尊重，是硬闸门。

### 4.5 和其他节律的关系

- 三条原生计划保持分开，因为它们的节奏和授权都不同：
  - 心跳（在场）；
  - 夜间沉淀（消化当天）；
  - 每日自我改进。
- 自我改进带开发授权，心跳不能带，所以不能并进心跳。
- **账合并**：`last_presence_at` 改为 `last_home_event_at`。家里任何内部回合都会更新它，所以刚做完沉淀或自我改进，心跳的 `MIN_GAP` 就会算上。
- **P5 不变**：有人说话时的插话仍由 P5 负责；出门负责安静的群。
- **出门的发言计入 P5 同一套上限**：每群 `max_per_hour`、`min_interval`，避免两条路叠加刷屏。

### 4.6 图

- `share_picture` 的出门回合里会列出她做出来的图。她用 `attach_image` 选一张，`accept_artifact(produced_only=True)` 保证只能发她自己做的。
- 全年龄向是她的判断，加上群聊提示 `GROUP_NOTE`。要不要再加一个确定性的标记，见 §11 Q4。

### 4.7 和她的长期目标对齐

- **学习回路**：
  - 每次出门都先读她自己的群笔记和现场窗。
  - 不开口，也可以把看到的东西写下来：这个群聊什么、什么节奏、谁是谁、什么话题和图合适。
  - 笔记越厚，「地方」视图里的标题越有用，下一次去哪儿、说什么就越准。owner 的第 5 条要求落在这里。
- **主动参与**：去哪儿、什么时候去、说不说，每一步都是她的选择。程序只负责让机会一定会来，并挡住刷屏。owner 的第 3 条要求落在这里。
- **自我改进**：出门时冒出的改进想法用 `note_idea` 记下，在家里的自我改进回合里决定，路线和 ADR-011 相同。
- **一族节律**：以后新的定期事件按同一族加，都满足以下几条：
  - 原生调度；
  - 程序拥有；
  - 有看门；
  - 参数是她的政策键，只能调不能关；
  - 都在家里。

## 6. 成本估算

- 估算方法：按 4 字符 ≈ 1 token；中文实际约为估算的 2 倍，下面已经计入（ADR-011 §8）。
- **家里**：
  - `every_min=60`、`min_gap_min=120` 时，每天约 6–10 次进入模型。
  - 每次约 0.8–1.5k 输入、约 150 输出，家会话一天增长约 10–25k。
  - 只算心跳，家会话大约 1–2 周触发一次 75% 压缩。
- **出门**：每次在群会话里约 3–6k；每天 ≤ 4 次时不碰家的窗口。
- **改成 30 分钟一拍**：总量约 ×1.3，因为多出来的拍子大多被闸门跳过。

## 7. 风险与护栏

| 风险 | 应对 |
|---|---|
| 刷屏 | 安静、发言后间隔、每天出门上限、P5 共用上限、没人接话加倍间隔、群里的夜间硬闸门；沉默是正常结果 |
| 隐私 | 出门回合是 `public`，只看这个群自己的东西；交接只过分类（以及 §11 Q1 决定的 topic）；加一条泄漏测试 |
| 连锁 | `visit` 只在家里的心跳回合可用；群里的出门回合没有 `visit`，也没有开发授权 |
| 成本失控 | 核心每日上限，加上每次跳过都记计数审计 |
| 心跳丢失 | 程序拥有，加上五个看门点（§4.3），每一项都记审计并告诉她 |
| 重启 | 计划持久在调度会话；任务照旧暂停；心跳重放幂等 |
| owner 想停 | 删掉 `heartbeat_target`，或在人格包里关掉 `heartbeat.enabled`；单个群可以用 `blocked_groups` |

- **顺手修好的缺陷**：心跳改节奏时发给 DSH 的变更写成了 `kind: every_seconds`，DSH 只认 `kind: every`，一旦她改节奏就会被拒；之前从没开过心跳，所以没暴露。测试替身现在按 DSH 的规则校验变更。
- **现网第一次 `/heartbeat`（03:41Z）**：命令回复「Heartbeat given … Next scheduled beat」，她的心跳回合出现「Tool added: visit」，地方视图列出 15 个群。她想去一个正在聊的群「只看不说、回来写第一份群笔记」，被安静闸门拒了；转去一个安静了 18 小时的群。由此改了两处：
  - **安静闸门只管开口**：`quiet_min` 只拦 `start_topic` 和 `share_picture`；有人在聊时去看看、写笔记照样可以（地方视图写「正有人在聊：可以去看看、写笔记；起话头或发图等安静下来」）。这正是 owner 第 5 条要的学习。
  - **出门不是平台输入**：第一版给出门回合带了通道信封，工作线程按平台输入复核发送者，`visit` 不是群成员，于是 `INPUT_ROUTE_STALE`，那次出门没到。更要紧的是，带信封的输入会被投影成群会话里某个成员说的话。现在出门回合不带信封，按 scene tick 唤醒；发言由发布服务按这个群自己的路由发出（只认 `direction=internal` 且 `episode_kind=visit` 的来源）。没到的那次出门回家报「没去成」，不占她当天的次数，也不让那个群等。
